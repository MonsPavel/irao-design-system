## 1. Что сделано

Пилотный клон карьерного портала «Интер РАО» собран **из компонентов irao-ui**
без копирования CSS оригинала: вся разметка пересобрана на `ui-button`,
`ui-card`, `ui-field`,`ui-form`, `ui-modal`, `ui-tabs`, `ui-accordion`,
`ui-select`, `ui-dropdown`, `ui-tag`, `ui-breadcrumbs`, `ui-pagination`,
`ui-error`, `ui-vi`, `ui-file`, `ui-checkbox`, `ui-radio-group` + роли
типографики и layout-примитивы `base/`. Блоки, у которых в ДС нет аналога
(hero, карусель, направления, …), собраны как **зона сайта** (`pilot.css`,
префикс `cp-`) — ровно так, как предписывает 02-architecture §7.

Собрано 12 страниц (главная + 11 типовых внутренних; генеративные повторы
оригинала — карточки 12 вакансий и variant-2 главной — не пересобирались).

**Пересборка 21.10 (T14.12, после EPIC-14).** Разметка переведена на API,
заведённое эпиком: заголовки внутренних страниц — `ui-page-title` (T14.2);
CTA строк/деталок — `ui-button--pill` (T14.4); чипы — `ui-chip`
(`cp-chip` и его JS удалены; состояние — `aria-current`/`aria-pressed`,
T14.8); табы стажировок — `ui-tabs--pill` с начальным выбором из
`aria-current="page"` (T14.9, порядок табов фиксирован как в оригинале);
тинты hero — токены `--ui-color-primary-a94/a26` (T14.7); крошки — со
связкой ритма из канона list-page (T14.5, `.cp-breadcrumbs` = значения
`.lpp-breadcrumbs`). По итогам ревью пересверки крошки добавлены на
vacancies/internships/practices — они есть в оригинале, но пропадали при
переносе 20.10 (полнота пересборки, не калибровка ДС): промежуточный пункт
«Школьникам и студентам» — plain span без `aria-current` (как в оригинале),
`aria-current="page"` — ровно один на цепочку (уточнён и стиль промежуточных
пунктов education/events/career-track, где он дублировался).

## 2. Методика сравнения

`compare.mjs`: обе версии открываются в Chromium 1440×900, страницы
прокручиваются для догрузки `loading="lazy"`-изображений, затем:

- полностраничные скриншоты обеих версий → `compare-output/{original,pilot}/`,
  просмотр парами — `compare-output/viewer.html`;
- DOM-метрики: высота документа, высоты одноимённых блоков главной,
  computed-стили пар «класс оригинала → ui-компонент» (шрифт, цвет, геометрия).

Ограничения: (а) сайт-зона `pilot.css` — приближение вёрстки оригинала, а не
пиксель-в-пиксель пересъём, поэтому высоты блоков расходятся в том числе из-за
калибровки пилота; (б) пробы берут первый совпадающий элемент — на страницах с
модалками часть проб оригинала попала в скрытые элементы (высота 0), часть
проб пилота — в содержимое закрытых модалок (`height: auto`); на страницах,
где одноимённый класс встречается в разных ролях, пара сравнивает разные
сущности — проба `tabs-pill` с T16.16 сравнивает ту же сущность по обе
стороны на всех страницах с ней (поднавигация на career-track/education/
events, табы «практика/стажировка» на internships/practices); разноимённые
пары остались на `section-title` (оригинал несёт
inline `fs-h3` на заголовках сегментов), на education/media — `card`/`tag-blue`
(первое вхождение — тег/карточка на фото с оверлейным вариантом оригинала);
на vacancy/vacancy-apply пары `page-title` нет вовсе — в оригинале h1 несёт
другие классы (см. §3.1);
(в) education/career-track в пилоте упрощены (меньше повторов данных), их высоты
не сравниваются напрямую; (г) **Pages-деплой актуален** (live CSS идентичен
main 8469ea6 — проверено сверкой 20.10): «48px против 52px» у поля — не
отставание, а компактный вариант форм в модалках оригинала
(`.apply-form .field__input { height: 48px }`, pages.css:1208) без аналога
в ДС на момент раунда — передано в T14.6 (аналог доставлен T14.6 —
`ui-field--compact`, принят пилотом: §3.3 и §10.5). С 21.10 probe-пары
обновлены под новое API пилота:
`chip` → `.ui-chip__pill` (было `.cp-chip`), `page-title` → `.ui-page-title`
(было `.ui-h1`).

## 3. Систематические различия компонентов — статус после EPIC-14

Различия, которые воспроизводятся на каждой странице — это свойства самих
ui-компонентов, а не пилотной обвязки. Ниже — итог пересверки 21.10
(`compare-output/compare.json`): по каждой probe-паре — статус
**«закрыто T14.x»** (computed-стили совпали), **«принято ДС»** (осознанное
значение системы, mapping-строка) или **«остаток»** (кандидат следующего
эпика/бэклога, в этой задаче не правится).

Роли `ui-h1…ui-h6`/`ui-page-title` несут `--ui-color-heading` (alias

`section-title` — проба сравнивает заголовок с inline
`fs-h3`-переопределением оригинала (42px) с ui-h2 пилота (60px), артефакт
выборки пробы (разные блоки под одним селектором), не свойство ролей;
заголовок страницы-формы vacancy-apply (строка таблицы выше) —
P3-остаток (оригинал fs-h3 42px против 60px пилота).

### 3.2 Размер заголовка внутренней страницы — закрыто (T14.2)

Роль `ui-page-title`: h1 со шкалой h2 (60px desktop) — как `.page-title`
оригинала. Probe `page-title` MATCH по всем стилям (fs/fw/lh/color/padding/
height) на 8 из 10 страниц с h1 — vacancies, internships, practices,
education, events, media, career-track, companies (vacancy/vacancy-apply —
см. §3.1).

### 10.3 axe-AC и новые систематики (фикс-раунд 24.10 по ревью приёмки)

Ревью приёмки не подтвердило AC «axe-пробы новых страниц: только известные
исключения (KNOWN_AXE_EXCEPTIONS)» в буквальной формулировке: проба 23.10
дала вне реестра (а) `heading-order` на events-search/education-catalog и
(б) 9 color-contrast-узлов offer-карточек, чьи цели с атрибутными
суффиксами не матчились регэкспу реестра. Оба пункта закрыты в
фикс-раунде 24.10:

1. **`heading-order` на новых страницах — исправлено разметкой пилота**
   (TDD: tests/unit/pilot-axe-heading-order.test.js): карточки списков
   несли h3 сразу после h1-страницы — пропуск уровня (WCAG 1.3.1;
   канон base/typography.css: «семантику страницы даёт реальный тег,
   h1→h2→h3 без пропусков — гейты irao/heading-order; класс — вид»).
   Тег заголовка карточки стал параметром `eventCard`/`offerCard` через
   map-безопасный санитайзер `cardHeading` (h1–h6, иначе h3; регрессия
   сборки 24.10 — идиома `.map(eventCard)` передавала индекс тегом,
   `<0 class="ui-h4">` в dist — поймана перегоном сборки, пиннута):
   events-search и education-catalog собираются с 'h2' (карточка — сразу
   за h1, промежуточной секции в оригинале нет); events/education/event
   остаются на h3 (там перед карточками секции h2) — старые страницы
   байт-в-байт не изменились. docHeight обеих страниц после фикса не
   изменился (§10.1). Систематика на СТАРЫХ страницах (media —
   article-карточки, career-track — карточки преимуществ) остаётся —
   вне AC новых страниц T15.9, зона своих задач (BACKLOG, medium,
   предложенный приоритет P2).
2. **9 color-contrast-узлов offer-карточек — узнаны существующей записью
   реестра**: это та же одобренная пара `.ui-button--accent` (белое на
   акценте 3.12:1 — design-decision владельца, ADR-0010), но axe
   составляет цели с продолжениями селектора того же элемента
   (`.ui-button--accent[href…][target…]` — «сайт „Работа России"»;
   `.ui-button--accent.ui-button[type…]` — «Найти» find-бара), которые
   прежний lookahead `(?=$|\s|:)` не маттил. Нового исключения нет:
   match записи расширен до `(?![\w-])` — любое продолжение селектора
   того же класса, кроме более длинного имени класса (пин негативного
   контроля — `.ui-button--accent-hover` остаётся вне реестра).
   Документировано по правилу реестра: запись + строка в таблице
   tests/README.md; stands-sweep ДС 45/45 после правки.
3. **Остальные находки пробы 23.10 — без изменений, в BACKLOG**:
   подписи полей страниц-форм (оригинал тёмный rgb(31,31,31) против
   muted gray-700 ДС после T16.9 — vacancy-apply/internship-apply/
   event-apply, probe `field-label`) — предложенный приоритет P3;

   52px/r8 — сайт-зона findBar, решение T15.5) — low, по потребности.
