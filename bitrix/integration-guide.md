# Integration guide (черновик) — подключение irao-ui к сайту на Bitrix

> Статус: **черновик** (кейс T2.4). Living-doc раздела 6 архитектуры
> (02-architecture §6) собирается в T10.3/T11.1; этот файл — рабочее зерно:
> порядок каскада и два кейса переопределения токенов. Копия `dist/` на сайте
> = read-only (`/local/ui/{version}/`), правки системы — только через
> обновление версии.

## Порядок каскада (не нарушать)

```text
/local/ui/{version}/ui-core.min.css     # дефолты слоя 2 в :root
/local/ui/{version}/themes/theme-*.css  # тема (необязательна; в MVP — нет брендовых)
template_styles.css                     # стили сайта — последними
```

Система подключается раньше CSS сайта: односелекторная специфичность `ui-*`
устойчива к legacy, а сайт получает документированную точку расширения —
переопределение токенов последним каскадом.

## Кейс: сайту нужен свой оттенок/отступ — переопределение токенов локально

Компоненты читают только слой 2 (`tokens/semantic.css`, ADR-0009), поэтому
точечная правка сайта = переопределение семантического токена в
`template_styles.css` (он подключён **после** core). Классы и HTML не трогаем.

```css
/* template_styles.css сайта */
:root {
  /* свой акцент бренда вместо дефолтного --ui-orange-500 */
  --ui-color-accent: #b34a10;         /* hex на сайте допустим: это слой САЙТА, не системы */
  /* крупнее радиус карточек */
  --ui-radius-md: 1.25rem;
}
```

Правила кейса:

1. Переопределяйте **только семантические токены** (`--ui-color-*`,
   `--ui-fs-*`, `--ui-space-*`, `--ui-radius-*`…) — как темы системы. Примитивы
   (`--ui-blue-800`…) и имена `ui-*` не трогать: производные значения и
   будущие обновления системы рассчитаны на слой 2.
2. Селектор `:root` — для сайта целиком; для раздела сайта можно сузить
   (`.landing-2026 { --ui-color-accent: … }`) — механика var-каскада та же,
   её же используют темы (`[data-ui-theme]`) и media-правила career-portal.
3. Проверяйте контраст своих значений на ключевых парах (текст на фоне —
   ≥ 4.5:1): система гарантирует AA для дефолтной палитры, свои значения —
   ответственность сайта.
4. Обновление системы: переопределения живут в `template_styles.css` сайта,
   копия `/local/ui/{version}/` read-only — minor-обновление core не задевает
   кейс; если система переименовала токен (major) — правится одна строка здесь.

Этот же приём — основа тем системы: `themes/theme-*.css` переопределяет
семантику под `[data-ui-theme="…"]` (см. `themes/README.md`); механизм и
правило совместимости («новый токен — только с дефолтом в `:root`») проверены
в T2.4.
