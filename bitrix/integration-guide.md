## Подключение (header.php)

Копипаст-готовый сниппет —
[`snippets/header-php.snippet.php`](snippets/header-php.snippet.php):
константа `UI_VERSION` (пин версии — констрейнт 8), CSS через
`Asset::addCss` в порядке core → (тема, опционально) → vi, `addJs(…, true)`
в конец (readyState-guard модулей T1.1 закрывает позднюю загрузку), preload
шрифтов 400/500 cyr до `ShowHead()`, skip-link первым элементом `<body>`
(T3.5). Объединение/минификация Bitrix совместимы: файлы уже минифицированы
(02-architecture §6.4). PHP-блок сниппета как есть:

```php snippet=bitrix/snippets/header-php.snippet.php
// Версия UI-системы, закреплённая за сайтом. Обновление = правка этой строки.
const UI_VERSION = '0.1.0';

$asset = \Bitrix\Main\Page\Asset::getInstance();
$asset->addCss('/local/ui/' . UI_VERSION . '/ui-core.min.css');
// Тема бренда — опциональна (в MVP все сайты в дефолтном бренде). Если тема
// есть, она идёт СТРОГО после core (порядок каскада core → theme → сайт):
// $asset->addCss('/local/ui/' . UI_VERSION . '/themes/theme-corp.css');
$asset->addCss('/local/ui/' . UI_VERSION . '/ui-vi.min.css');
$asset->addJs('/local/ui/' . UI_VERSION . '/ui.min.js', true); // true => в конец, defer-семантика Bitrix
```

## Что вы подключаете: CSS, JS, шрифты

Файлы поставки (структура dist, 02-architecture §6.1) и роль каждого:

| Файл | Что это | Как подключается |
|---|---|---|
| `ui-core.min.css` | токены → base → все компоненты, баннер версии+sha | первым (порядок каскада ниже) |
| `ui-vi.min.css` | модуль версии для слабовидящих (ГОСТ Р 52872), отдельным файлом | после core, всегда — кнопка входа в VI на любой странице |
| `ui.min.js` | все JS-модули (классические IIFE), публичное API `window.IraoUI` | `addJs(…, true)` — в конец страницы |
| `fonts/` | Golos Text woff2 (400/500/600, cyr/lat) + OFL-лицензия | не подключаются вручную: `@font-face` внутри core, `url()` относительно |
| `themes/` | темы бренда — только переопределение семантических токенов | опционально (секция ниже); в MVP не используются |

Шрифты лежат рядом с CSS в той же папке версии — относительные `url()` из
`@font-face` работают без правок. Preload — только приоритетные грани
400/500 cyr (90% русской страницы, паттерн career-portal, T3.1), до
`ShowHead()`, с обязательным `crossorigin` (шрифты грузятся в CORS-режиме —
без атрибута preload не матчится с загрузкой, шрифт запросится дважды).
Подключение вручную других граней не требуется.

## Порядок каскада (не нарушать)

```text
/local/ui/{version}/ui-core.min.css     # дефолты слоя 2 в :root
/local/ui/{version}/themes/theme-*.css  # тема (необязательна; в MVP — нет брендовых)
template_styles.css                     # стили сайта — последними
```

Система подключается раньше CSS сайта: односелекторная специфичность `ui-*`
устойчива к legacy, а сайт получает документированную точку расширения —
переопределение токенов последним каскадом (констрейнт 1).

## Опциональная тема бренда

Тема — файл `dist/themes/theme-<имя>.css` (только переопределение
семантических токенов в одном блоке `[data-ui-theme="…"]`, гейт stylelint;
механика — ADR-0009, themes/README.md). Копипаст-сниппет —
[`snippets/theme-connect.php`](snippets/theme-connect.php): файл строго после
core, атрибут `data-ui-theme` на `<html>` (значение = имя файла без
`theme-`/`.css`), сценарии «весь сайт / по разделам / без перезагрузки».
В MVP (все сайты в дефолтном бренде) тема не подключается.

## Кейс: сайту нужен свой оттенок/отступ — переопределение токенов локально

Компоненты читают только слой 2 (`tokens/semantic.css`, ADR-0009), поэтому
точечная правка сайта = переопределение семантического токена в
`template_styles.css` (он подключён **после** core). Классы и HTML не трогаем.

```css
/* template_styles.css сайта */
:root {
  /* свой акцент бренда вместо дефолтного --ui-orange-500 */
  --ui-color-accent: #b34a10;         /* hex на сайте допустим: это слой САЙТА, не системы */
  /* крупнее радиус карточек */
  --ui-radius-md: 1.25rem;
}
```

Правила кейса:

1. Переопределяйте **только семантические токены** (`--ui-color-*`,
   `--ui-fs-*`, `--ui-space-*`, `--ui-radius-*`…) — как темы системы. Примитивы
   (`--ui-blue-800`…) и имена `ui-*` не трогать: производные значения и
   будущие обновления системы рассчитаны на слой 2.
2. Селектор `:root` — для сайта целиком; для раздела сайта можно сузить
   (`.landing-2026 { --ui-color-accent: … }`) — механика var-каскада та же,
   её же используют темы (`[data-ui-theme]`) и media-правила career-portal.
3. Проверяйте контраст своих значений на ключевых парах (текст на фоне —
   ≥ 4.5:1): система гарантирует AA для дефолтной палитры, свои значения —
   ответственность сайта.
4. Обновление системы: переопределения живут в `template_styles.css` сайта,
   копия `/local/ui/{version}/` read-only — minor-обновление core не задевает
   кейс; если система переименовала токен (major) — правится одна строка здесь.

Этот же приём — основа тем системы: `themes/theme-*.css` переопределяет
семантику под `[data-ui-theme="…"]` (см. `themes/README.md`); механизм и
правило совместимости («новый токен — только с дефолтом в `:root`») проверены
в T2.4.

## JSON-данные для JS

Данные для JS-компонентов — в разметке страницы, заполняются из PHP
(`json_encode` из инфоблоков; ADR-0008 п.2, 02-architecture §6.3). Сниппет
[`snippets/json-data.php`](snippets/json-data.php):
`irao_ui_json_script($data, 'tabs')` → `<script type="application/json"
data-ui-tabs-data>` с флагами `JSON_HEX_TAG` (нельзя убрать — защита от
вылезания из `<script>`, XSS) и `JSON_UNESCAPED_UNICODE`. Разметку из данных
рендерит сайт; модули системы инициализируют готовую каноническую разметку
(прецедент — ui-tabs). Вызов в шаблоне компонента:

```php snippet=bitrix/snippets/json-data.php
<?= irao_ui_json_script($tabsFromIblock, 'tabs') ?>
```

## Крошки и пагинация (серверные сниппеты)

Разметку компонентов рендерит сервер — клиентские модули системы
инициализируют готовую каноническую разметку (модель ADR-0008). Для двух
серверных генераторов разметка выведена в копипаст-сниппеты; живые
интеграционные стенды — patterns/list-page и patterns/form-page полигона.

Хлебные крошки (T4.7) —
[`snippets/breadcrumbs.php`](snippets/breadcrumbs.php): `nav[aria-label]` →
`ol[role="list"]` с микроразметкой BreadcrumbList, `aria-current="page"` на
текущей, весь вывод экранирован. Источник цепочки — `$arResult` компонента
`bitrix:breadcrumb` или собственный массив; правила построения —
components/ui-breadcrumbs/README.md. Вызов в шаблоне страницы:

```php snippet=bitrix/snippets/breadcrumbs.php
renderUiBreadcrumbs([
    ['NAME' => 'Главная', 'LINK' => SITE_DIR],
    ['NAME' => 'Вакансии', 'LINK' => SITE_DIR . 'vacancies/'],
    ['NAME' => 'Стажировка в ИРАО', 'LINK' => null], // текущая — span aria-current="page"
]);
```

Пагинация (T6.3) —
[`snippets/pagination.php`](snippets/pagination.php): окно показа с «…»
(края всегда, окно ±`$side` у текущей), `aria-current="page"` на текущей,
недоступные стрелки — `button[disabled]`; для `bitrix:news.list` числа — в
`$arResult`. Правила и решения — components/ui-pagination/README.md:

```php snippet=bitrix/snippets/pagination.php
if ((int)$arResult['NAV_PAGE_COUNT'] > 1) {
    renderUiPagination(
        (int)$arResult['NAV_PAGE_COUNT'],
        (int)$arResult['NAV_PAGE_NOMER'],
        $arResult['sUrlPath'] . '?PAGEN_1=#PAGE#'
    );
}
```

## Серверные ошибки форм (контракт T5.6)

Формы системы валидируются **на сервере всегда** — JS (`IraoUI.form`,
компонент ui-form, T5.5) только предваряет проверку на клиенте. После
перезагрузки страницы с ошибками PHP обязан рендерить **те же классы и
aria**, что клиентская валидация, — иначе пользователь увидит два разных
интерфейса ошибок. Таблица контракта «состояние → классы → aria → фокус» —
components/ui-form/README.md (секция «Серверный контракт ошибок»).

Копипаст-готовый шаблон вывода для `bitrix:form.result.new` (и произвольной
формы) — сниппет
[`snippets/form-error-render.php`](snippets/form-error-render.php):
сводная `ui-form__summary[role=alert]` из `$arResult["FORM_ERRORS"]`,
у поля `ui-field--error` + `aria-invalid="true"` + `aria-describedby` +
`<p class="ui-field__error" id="…-error" role="alert">`, inline-сниппет
фокуса на summary (фокус-менеджмент серверных состояний работает без
модулей; success-страница — тот же сниппет с id заголовка). Экранирование
вывода обязательно — сообщения могут нести пользовательские данные (XSS).

AJAX-отправка (появится на сайтах): контракт тот же — разметку ошибок
рендерит клиентский модуль, сервер возвращает данные. Интеграционный стенд
полного цикла — стенд `integration/form-full-cycle` в showcase (стендовая
репетиция пилота).

## Legacy-констрейнты (раздел 6 плана 06)

Технические ограничения, чтобы legacy не ломал систему, — 9 пунктов
[docs/06-implementation-plan.md §6](../06-implementation-plan.md). Исполнимая
форма — чек-лист
[`first-connect-checklist.md`](first-connect-checklist.md) (проходится при
первом подключении); здесь — правила одним списком:

1. **Порядок каскада:** ui-core первым, `template_styles.css` сайта — после
   (точка законных переопределений).
2. **Специфичность:** компоненты — одним классом (0-1-0) против legacy
   tag-стилей (0-0-1); фокус-политика — элемент+псевдокласс (ADR-0001).
3. **box-sizing:** каждый ui-компонент объявляет свой (ADR-0002) — переживает
   `* { box-sizing: content-box }`.
4. **Запрет эскалации:** система не отвечает на legacy `!important` своим
   (кроме vi); конфликт = страница остаётся на legacy или изолируется.
5. **Запретные обёртки:** ui-компоненты не вкладываются в legacy-контейнеры
   с фиксированной высотой и `overflow: hidden` (кроме осознанных скролл-зон).
6. **Смешение на странице** — только целыми компонентами/секциями, не
   «половина компонента».
7. **Глобалы base минимальны** (`[hidden]`, img max-width, scrollbar-gutter,
   ресет отступов, reduced-motion — base/README.md): сайт знает, что получит
   глобально.
8. **Пин версии:** точная версия константой `UI_VERSION`; обновление —
   осознанный акт по upgrade-гайду (T11.4).
9. **Журнал конфликтов** обязателен на каждом сайте (формат T11.2) — кормит
   «известные ограничения» документации.

### Стойкость под legacy-атакой (e2e, каталог исключений)

Расширенная атака T11.1 (`tests/e2e/legacy-attack.spec.js`): после ui-core
инжектится пакет токсичных правил — `a { outline: none }`,
`* { box-sizing: content-box }`, tag-стили форм (`input { height: 30px;
border: dashed… }`), `h1 { font-size: 18px }`, `ul { list-style: none }`.
Ключевые компоненты (button/field/card/link) сохраняют геометрию, фокус и
читаемость; набор инжектов параметризован (`tests/helpers/legacy-attack.js`)
и переиспользуется в регрессии.

Каталог стойких исключений (граница защиты системы):

| # | Исключение | Почему это норма |
|---|---|---|
| 1 | Обводка фокуса карточки-ссылки живёт на `::after` по всей карточке, а не на самой ссылке | Замена обводки допустима при сохранении индикатора (focus-policy.md, ADR-0001); замена неуязвима к `a { outline: none }` |
| 2 | «Сырые» теги без класса роли (заголовок без `ui-h1`, список без `ui-list`) legacy tag-правило перебивает: reset 0-0-1 против legacy 0-0-1, подключённого позже | Защита системы — классы ролей (T3.3 «классы, а не теги»): разметка с классом держит вид (0-1-0); правило для сайта — носить роли классами |
| 3 | Свойства, которые система не декларирует на элементе, legacy задать может | Точка расширения каскада (см. «Порядок каскада»); гарантия — на декларированных свойствах: у контролов это вся коробка (box-sizing/min-height/padding/border/radius/фон/шрифт) |

## Миграция legacy → UI System (стадии)

Стадийная модель — docs/06-implementation-plan.md §6: аудит legacy →
alongside install (`/local/ui/` подключён ДО `template_styles.css`,
legacy-страницы не тронуты) → новые страницы/секции сразу на `ui-` →
постраничная замена по компонентам (с чек-листом страницы) → удаление
legacy-стилей, когда ссылок на классы нет. Пилоты — T11.2/T11.3; каждый сайт
ведёт журнал конфликтов (констрейнт 9).

## Обновление версии

Единственное место правки на сайте — константа `UI_VERSION` в `header.php`
(сниппет [`snippets/header-php.snippet.php`](snippets/header-php.snippet.php));
копия `/local/ui/{version}/` read-only, новая версия = новая папка рядом.
Semver и правила поддержки — ADR-0007; репетиция обновления — T11.4
(upgrade-чек-лист). Major-обновление правит переопределённые токены в
`template_styles.css` (см. кейс выше, п. 4).

Версионирование сниппетов (T10.3): если сниппет изменился между
minor-релизами, в [snippets/README.md](snippets/README.md) и в гайдах стоит
пометка «с версии X» — при обновлении сверяйте свои копии сниппетов с
файлами по этим пометкам. Гайды хранят embed-блоки сниппетов, сверяемые с
файлами на билде: копипаст из гайдов всегда актуален текущей версии.
