# Чек-лист первого подключения сайта к irao-ui

Исполнимая форма legacy-констрейнтов (T11.1): 9 технических ограничений
раздела 6 плана 06 ([docs/06-implementation-plan.md §6](../06-implementation-plan.md),
миграция legacy → UI System) в порядке внедрения. Пройдите пункты при первом
подключении системы к сайту, отмечайте галочки — чек-лист копируется в PR/задачу
подключения. Подробности каждого правила —
[integration-guide.md](integration-guide.md); стойкость компонентов под
типовыми legacy-атаками доказана e2e
(`tests/e2e/legacy-attack.spec.js`, каталог исключений — integration-guide.md).

Прежде чем считать подключение законченным:

- [ ] **1. Порядок каскада.** `ui-core.min.css` подключён первым;
  `template_styles.css` сайта — после (точка законных переопределений).
  Проверка: в `<head>` страницы link core стоит раньше link'ов сайта
  (DevTools → Elements). Сниппет: [`snippets/header-php.snippet.php`](snippets/header-php.snippet.php);
  каскад — integration-guide.md «Порядок каскада».

- [ ] **2. Специфичность и фокус.** Компоненты стилизуются одним классом
  (0-1-0) и побеждают legacy tag-стили (0-0-1); глобальная политика фокуса —
  «элемент + :focus-visible» (ADR-0001, 0-1-1). Проверка: Tab-обход страницы —
  фокус виден на каждом интерактивном элементе, в том числе на legacy-странице
  с `a { outline: none }`. Сайт фокус НЕ переопределяет и не глушит;
  заголовки/текстовые роли — классами (`ui-h1`…), не «сырыми» тегами
  (T3.3 «классы, а не теги»).

- [ ] **3. box-sizing.** Каждый ui-компонент объявляет свой
  `box-sizing: border-box` (ADR-0002) — геометрия переживает legacy-ресет
  `* { box-sizing: content-box }`. Проверка: кнопка/поле/карточка на странице
  с legacy-ресетом держат высоты 52px и радиусы (авто-гейт —
  `npm test` → e2e legacy-атаки). Сайт вправе не заботиться о box-sizing
  ui-разметки.

- [ ] **4. Запрет эскалации.** Система никогда не отвечает на legacy
  `!important` своим `!important` (единственное место — a11y/vi.css). При
  конфликте: страница остаётся на legacy или изолируется — повышение
  специфичности в системе ЗАПРЕЩЕНО. Проверка: в подключённой копии
  `/local/ui/{version}/` нет правок (`git diff` пуст — копия read-only,
  ADR-0006).

- [ ] **5. Запретные обёртки.** ui-компоненты не вкладываются в
  legacy-контейнеры с фиксированной высотой и `overflow: hidden` (кроме
  осознанных скролл-зон). Проверка: у каждой обёртки над ui-компонентом либо
  auto-высота, либо это документированная скролл-зона; «прыгающие» подсказки
  модалок/дропдаунов не обрезаются.

- [ ] **6. Смешение — целыми компонентами.** На странице допускается
  сосуществование legacy и ui- только на уровне целых компонентов/секций, не
  «половина компонента» (кнопка на ui-, поле на legacy — запрещено).
  Проверка: визуальный осмотр + grep шаблонов на смешение классов внутри
  одного компонента.

- [ ] **7. Глобалы base минимальны.** Сайт знает, что получит глобально:
  `[hidden]`, `img { max-width: 100% }`, `scrollbar-gutter: stable`, ресет
  отступов body/h1–h4/p/ul/ol, kill-switch `prefers-reduced-motion`
  (base/README.md). Проверка: на legacy-страницах без ui-компонентов
  картинка не «поплыла» и списки выглядят ожидаемо (маркеры — только с
  классом `ui-list`).

- [ ] **8. Пин версии.** Сайт закрепил точную версию константой `UI_VERSION`
  (обновление = новая папка `/local/ui/{version}/` + правка одной строки,
  ADR-0006/0007; осознанный акт по upgrade-гайду — T11.4). Проверка:
  в `header.php` есть `const UI_VERSION = '…'`; папка версии read-only.
  Сниппет: [`snippets/header-php.snippet.php`](snippets/header-php.snippet.php).

- [ ] **9. Журнал конфликтов.** На сайте заведён журнал конфликтов legacy
  (формат — T11.2): каждый конфликт — запись «страница → правило → решение
  (обход/изоляция/задача в систему)». Журнал кормит «известные ограничения»
  документации системы. Проверка: файл журнала существует (пустой — тоже
  результат), ссылка на него добавлена в задачу подключения.
