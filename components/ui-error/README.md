# ui-error

Паттерн ошибочного состояния: inline (в секции — ошибка загрузки) и
полностраничный (`--page` — 404/500). Задача T4.8. Источник одобренного
дизайна — `.page-404` career-portal (pages.css:666–685): центрированная
колонка (gap 20 → `--ui-space-5`), `min-height: 50vh`, заголовок роли `ui-h3`,
текст muted, CTA `ui-button--primary`. CSS минимален — остальное дают
примитивы (типографика ролями, CTA из `ui-button`/`ui-link`).

## API

| Что | Значение |
|---|---|
| Блок `.ui-error` | корень паттерна — центрированная колонка слотов; база = inline-вариант (в секции, без растягивания) |
| Модификатор `.ui-error--page` | полностраничный вариант (404/500): `min-height: 50vh` + центрирование по высоте (перенос `.page-404`) |
| Элемент `.ui-error__media` | на `<svg aria-hidden="true">` или `<img alt="">` — декоративная иллюстрация; **необязателен** |
| Элемент `.ui-error__title` | на `<h1>` (полностраничный) или `<h2>` (inline) — заголовок состояния; вид даёт роль `ui-h3` |
| Элемент `.ui-error__text` | на `<p>` — пояснение; роль `ui-body` + `ui-text--muted` |
| Элемент `.ui-error__actions` | лента CTA; **обязательна** — хотя бы одно действие (назад/на главную/повторить) |
| CTA | «Повторить» — `ui-button`; «На главную» — `ui-button--primary`; «назад» — `ui-link` |
| JS | не требуется; JS-логика retry — контекст сайта (Out of scope T4.8) |
| Токены | `--ui-space-5` (шаг колонки), `--ui-space-3` (шаг CTA), `--ui-color-text-muted` (тон слота) |

```html
<div class="ui-error ui-error--page">
  <svg class="ui-error__media" aria-hidden="true" focusable="false" width="48" height="48" viewBox="0 0 24 24">
    <path d="M12 21.5S5.5 15.9 5.5 10.75a6.5 6.5 0 0 1 13 0C18.5 15.9 12 21.5 12 21.5Z" fill="none" stroke="currentColor" stroke-width="1.5" stroke-linejoin="round"></path>
    <circle cx="12" cy="10.5" r="2.25" fill="none" stroke="currentColor" stroke-width="1.5"></circle>
  </svg>
  <h1 class="ui-error__title ui-h3">Страница не найдена</h1>
  <p class="ui-error__text ui-body ui-text--muted">
    Такой страницы нет или она была перемещена. Начните с главной — там всё на месте.
  </p>
  <div class="ui-error__actions">
    <a class="ui-button ui-button--primary" href="/">На главную</a>
  </div>
</div>
```

Inline-вариант — тот же корень **без** `--page`, заголовок — `h2`
(пример в каноническом паттерне `ui-error.html` и на стенде ui-error).

## Правило заголовков (спека T4.8 п.2)

- **Полностраничный 404/500 — `h1`**: состояние занимает страницу, у которой
  нет собственного заголовка; h1 страницы — заголовок состояния.
- **Inline — `h2`**: страница уже имеет `h1`; состояние — часть секции.
- Проверка сквозная: `html-validate` (`irao/one-h1` — один h1 на страницу,
  `irao/heading-order` — без пропусков уровней) по каноническим паттернам и
  стендам в `npm run lint`. Стенд error-404 собирается каркасом **без**
  служебного h1 — заголовок страницы несёт сам паттерн (`showcase/build.mjs`).

## Правила текстов

Спека T4.8 сжимает правила в две строки: **нет вины пользователя** и **есть
следующее действие**. Тон — референс `career-portal/404.html` (страница
одобренного дизайна): «Такой страницы нет или она была перемещена. Начните с
главной — там всё на месте.»

1. **Нет вины пользователя.** «Страница не найдена», а не «неверный адрес»;
   «не удалось загрузить», а не «вы сломали интернет». Формулировки — от
   состояния мира, без «вы».
2. **Есть следующее действие.** Пояснение подсказывает выход, действия стоят
   в `.ui-error__actions` — состояние без действий запрещено (Implementation
   requirements T4.8 п.3).
3. **Причина — без техники.** «Пропало соединение», а не «HTTP 504 gateway
   timeout»; коды (404/500) — не тексты, а контекст для поддержки.

### Когда retry-кнопка, когда просто ссылка

| Ситуация | Действие | Почему |
|---|---|---|
| Сбой сети, таймаут, разовый сбой запроса | `ui-button` «Повторить» | повтор имеет смысл: состояние мира могло измениться |
| Раздел/данные недоступны надолго, ошибка известна | `ui-link` на рабочий раздел | повтор бессмыслен — ведите туда, где работа есть |
| 404 | `ui-button--primary` «На главную» (+ опционально ссылка «назад») | страницы нет; выход — в навигацию |
| 500 | `ui-button--primary` «На главную» + текст «мы уже исправляем» | повтор почти никогда не помогает мгновенно |

«Назад» — `history.back()` сайта по ссылке (JS-контекст сайта, Out of scope
T4.8); текст «Вернуться назад» без работающего JS на демо-стенде ведёт в
якорь — на сайте ссылка обязана работать (href + JS-усиление).

## Nav-минимум полностраничного состояния

Крошки в полностраничном 404/500 **не заводятся** (Technical considerations
T4.8): пользователь дезориентирован — цепочка «где я» здесь бессмысленна и
только добавляет шум. Только nav-минимум: действия «На главную»/«назад».
Разметка паттерна не содержит `<nav>` — проверка закреплена юнит-пином и
e2e-сценарием error-404.

## Граница с ui-alert

| | `ui-alert` | `ui-error` |
|---|---|---|
| Что это | статусное сообщение **рядом с контентом**: операция прошла/не прошла, фон | состояние **вместо контента**: загрузить не удалось / страницы нет |
| Объём | одна фраза, иконка, опционально закрытие | заголовок + пояснение + действия |
| Роль | `role="status"`/`role="alert"` (живой регион) | без live-роли: статичная разметка в потоке |
| Типичный кейс | «резюме отправлено», «не удалось отправить форму» | «не удалось загрузить список», 404 |

Правило: если контент на месте и сообщается результат операции — `ui-alert`;
если контента нет и есть чем его заменить — `ui-error`.

## A11y

- Состояние объясняется **текстом**, не только иллюстрацией (Accessibility
  requirements): `__media` декоративен (`aria-hidden`), заголовок и пояснение
  — обычный поток.
- Появляется в потоке, фокус программно не ловится (Technical considerations
  T4.8); при динамической замене контента объявление — задача контейнера
  (`aria-live`/`aria-busy` области результатов, T8.1/T5.5).
- CTA доступны с клавиатуры нативно; фокус-обводка — ADR-0001. Кнопка
  «Повторить» на стенде без JS просто фокусируется и получает клик —
  обработчик retry за пределами системы.
- axe на обоих стендах чист, известных исключений нет.

## Bitrix

- **404/500**: отдельные шаблоны сайта (`/404.php`, `/500.php` + настройки
  `ERROR_404`) рендерят `.ui-error--page` с `h1`. Каркас страницы без
  хлебных крошек.
- **Inline**: в шаблоне компонента — ветка «запрос данных не удался»
  рендерит `.ui-error` вместо пустого контейнера; текст ошибки — из
  языковых файлов, экранируйте `htmlspecialchars`.
- Логика повтора — JS сайта по кнопке (data-хук по конвенции `data-ui-*`,
  §2 «Namespace»: JS не вешается на стилевые классы).

## Do / Don't

- **Do**: 404/500 — `h1`, inline — `h2`; хотя бы одно действие всегда.
- **Do**: для 404 — «На главную» основной кнопкой; «Повторить» — только
  когда повтор реально имеет смысл (таблица выше).
- **Don't**: крошки/полная навигация в полностраничном состоянии —
  nav-минимум (см. выше).
- **Don't**: `role="alert"`/`aria-live` на статичном состоянии — оно читается
  в потоке; живые регионы — для динамических замен (T8.1).
- **Don't**: вина пользователя, технический жаргон, пустые действия («ОК» без
  следствия) — правила текстов выше.
- **Don't**: `ui-error` для результатов операций рядом с контентом — это
  `ui-alert` (граница выше).

## Известные границы

- Шаг колонки `--ui-space-5` (24px) — маппинг gap 20px одобренного
  `.page-404` на шкалу §3.2; точные 20px — design-decision владельца дизайна.
- Крупная цифра «404» карьерного портала (pages.css:676–681, 120px) — контент
  иллюстрации, не структура: сайт рисует её в `__media` (система размер слота
  не навязывает).
- JS-логика retry, локализация кодов ошибок, серверные тексты — вне системы
  (Out of scope T4.8).
