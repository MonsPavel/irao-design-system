# ui-stat

Плашка «крупное значение + подпись + опциональная сноска» — повторяющаяся
сущность корпоративных лендингов группы («50% молодых специалистов»,
«60+ тысяч», «Топ-20»). Три поверхности одобренного дизайна career-portal:
`--glass` (стекло на фото-секции), `--filled` (primary), `--deep`
(blue-deep). Задача T17.4; до компонента пилот собирал три вариации руками
(T15.2: «унификация дороже двух вариаций» — варианты снимают вопрос).
Ключевой принцип: **размер значения — не компонентом** — значение несёт
типографическую роль в разметке (`ui-h2` у статов, `ui-h4` у преимуществ),
компонент задаёт только поверхность и ритм.

## API

| Что | Значение |
|---|---|
| Блок | `.ui-stat` на `<li>` (канон — `<ul>` из пунктов) — flex-колонка: значение → подпись → сноска; радиус `--ui-radius-md` |
| Поверхность | токен-хук `--ui-stat-surface`, дефолт `--ui-color-primary`: второй потребитель перекрашивает базу без fork'а (годовые отчёты, «о компании» других сайтов группы) |
| Элемент `.ui-stat__value` | крупное число/текст; типографику задаёт разметка ролями base (`ui-h2`/`ui-h4`) — компонент шрифты не переобъявляет, только перекрашивает роль в `--ui-color-text-on-dark` (заголовочные роли красят в `--ui-color-heading` — на тёмной плашке нечитаемо) |
| Элемент `.ui-stat__label` | подпись значения; на тёмном — `--ui-color-text-on-dark-muted` (AA-пара T2.3); у `--glass`/`--deep` — `text-on-dark` (значения оригинала: holding desc и adv text — белый) |
| Элемент `.ui-stat__note` | опциональная сноска «* по данным …»: `--ui-fs-micro` + on-dark-muted (прозрачность 0.72 плашек пилота maps на токен-пару) |
| Модификатор `.ui-stat--glass` | стекло на фото-секции: фон `--ui-color-glass-dark`, рамка `--ui-color-text-on-dark-muted`, паддинг 16, шаг 8 — живёт внутри фото-секции (T17.3) |
| Модификатор `.ui-stat--filled` | primary (поверхность базы): геометрия оригинала pages.css:806 — 20/24, шаг значений 0 |
| Модификатор `.ui-stat--deep` | `--ui-color-surface-blue-deep` (маппинг `--color-blue-700`): 24/20, шаг 12 |
| JS | не требуется (CSS-компонент) |
| Токены | `--ui-stat-surface`, `--ui-color-primary`, `--ui-color-glass-dark`, `--ui-color-surface-blue-deep`, `--ui-color-text-on-dark(-muted)`, `--ui-space-2/3/4/5`, `--ui-radius-md`, `--ui-border-width`, `--ui-fs-micro` |

```html
<ul class="ui-grid ui-grid--3">
  <li class="ui-stat ui-stat--glass">
    <span class="ui-stat__value ui-h2">50%</span>
    <span class="ui-stat__label">молодых специалистов получают карьерное продвижение</span>
    <span class="ui-stat__note">* по данным мониторинга</span>
  </li>
  …
</ul>
```

## Геометрия и значения

- Паддинги перенесены «как есть» из одобренного дизайна: база 16/24
  (`--ui-space-4`/`--ui-space-5`, holding), `--filled` 20/24 (20px вне
  шкалы §3.2 — прецедент `--ui-field-pad-inline`), `--deep` 24/20
  (pages.css:815); радиус — `--ui-radius-md` (= `--radius-card`
  оригинала).
- Шаг элементов (gap): 8 база (`--ui-space-2`, holding), 0 у `--filled`
  (оригинал pages.css:806 шага не задаёт), 12 у `--deep` (`--ui-space-3`).
- Никаких фиксированных высот: плашка — flex-колонка, растёт по контенту;
  выравнивание в ряду — сетка (`ui-grid`), она же держит раскладку 3/4
  колонок (Out of scope T17.4).
- Сноска у holding оригинала прижата к низу фиксированной высотой плашки
  (280px); в ДС плашка растёт по контенту — сноска идёт за подписью в
  потоке (высота блока пилота — сайт-зона, REPORT §3.3).

## Клавиатура и a11y

- Статы — статичный контент: в Tab-порядок не попадают, интерактива нет
  (анимации счётчиков — Out of scope, в оригинале их нет).
- Семантика фактов — список: `<ul>` из `<li class="ui-stat">`
  (прецедент holding-списка, Implementation requirements п.1); скринридер
  читает «50%, молодых специалистов…» одним пунктом.
- Значение — `span`/`h3` с ролью типографики: заголовок преимущества
  (`h3.ui-h4`) остаётся в структуре заголовков страницы, числа-статы —
  `span` (пункт списка, не заголовок).
- Контраст on-dark-пар — гейт T2.3: `on-dark-on-surface-dark` (значение на
  primary), `on-dark-muted-on-surface-dark` (подпись), `on-dark-on-surface-blue-deep`
  (`--deep`). Стекло `--glass` — альфа-поверхность поверх фото: как и
  тинты T14.7, парой с конкретным фоном не гейтится (исключение
  `--ui-color-glass-dark` в pairs.config.mjs); читаемость на фото-секции
  обеспечивает тёмный оверлей секции (T17.3), e2e проверяет пару на
  подложке стенда.
- VI-режим (T9.1): перекраска накроет плашку как все элементы — цветов вне
  токенов в файле нет (инвариант §5).

## Do / Don't

- **Do**: статы холдинга на фото — `ui-grid--3` из `ui-stat--glass` внутри
  фото-секции; значение — `ui-stat__value ui-h2`.
- **Do**: преимущества компании — `ui-stat--deep` со значением-заголовком
  `ui-h4` (роль в разметке, не в компоненте).
- **Do**: другой бренд группы — `--ui-stat-surface: var(--ui-color-primary-deep)`
  на сетке: база перекрасится без fork'а (пару к поверхности несёт
  text-on-dark).
- **Don't**: `<div class="ui-stat" style="font-size: 42px">` — размер
  значения задаёт роль в разметке (ui-h2/ui-h4), не inline и не site-CSS.
- **Don't**: менять фон `--glass`/`--deep` через `--ui-stat-surface` — хук
  красит только базу/filled (поверхности одобренного дизайна фиксированы).
- **Don't**: сетку стат (3/4 колонки, адаптив) собирать классами
  компонента — раскладка страницы: `ui-grid` уже есть (Out of scope).

## Bitrix (шаблоны)

Статы собираются в шаблоне компонента списка/раздела «о компании»: пункты
`<li>` получают `ui-stat` + вариант поверхности, значения — роль из
настроек инфоблока. Цвета и геометрия едут из токенов: смена темы
перекрашивает варианты без правки разметки; `--ui-stat-surface` на
странице сайта — штатная кастомизация брендового блока.

## Известные границы

- Сетки стат (3/4 колонки) — раскладка страницы: `ui-grid` (Out of scope
  T17.4); адаптив — сайт-зона или сетка.
- Анимации счётчиков (count-up) — нет в оригинале, не переносится (Out of
  scope).
- Фото-фон секции — фото-секция `ui-section--photo` (T17.3): `--glass`
  живёт внутри неё, компонент фон не несёт.
- Прижатие сноски к низу (margin-top: auto как у `ui-card__footer`) не
  перенесено: плашка растёт по контенту; нужна фикс-высота —site-CSS
  потребителя.
