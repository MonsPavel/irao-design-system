# ui-pagination

Пагинация списковых страниц: лендмарка `nav` с лентой страниц-ссылок и
стрелок, `aria-current="page"` на текущей, окно показа с «…» на длинных
списках. Задача T6.3. Перенос `.pagination` career-portal
(components.css:229–269, класс A): touch-цели 44×44, hover-фон blue-100,
текущая — заливка primary + белая подпись, disabled-стрелки — opacity 0.3.
JS не требуется — пагинация работает без JS по построению (обычные ссылки,
переходы серверные).

## API

| Что | Значение |
|---|---|
| Блок `.ui-pagination` | на `<nav aria-label="Пагинация">` — лендмарка навигации; имя — конвенция (Technical considerations), при нескольких пагинациях на странице различайте: «Пагинация каталога», «Пагинация комментариев» (axe требует уникальности пар «роль + имя») |
| Элемент `.ui-pagination__page` | на `<a href>` — страница-ссылка с `aria-label="Страница N"` (голая цифра — слабое имя, WCAG 2.4.4); на `<span aria-current="page">` — текущая страница |
| Элемент `.ui-pagination__arrow` | на `<a href>` — доступная стрелка с `aria-label="Предыдущая страница"`/`"Следующая страница"`; на `<button type="button" disabled>` — недоступная (первая/последняя страница) с тем же aria-label |
| Элемент `.ui-pagination__ellipsis` | на `<span aria-hidden="true">…</span>` — декоративный указатель пропуска страниц (не интерактив, скринридеру не читается: информация — в самих ссылках) |
| Модификатор `.ui-pagination--bare` | на `<nav>` блока — форма без стрелок (T16.6): разметка вовсе не включает стрелки; для готовой разметки модификатор прячет `__arrow` через `display: none` — скрытое не фокусируется, не кликается и не читается скринридером. Стили `__page` не меняет. Когда уместен — секция «Без стрелок» ниже |
| Глиф стрелки | `<svg aria-hidden="true" width="16" height="16">` внутри стрелки — цвет `currentColor`, имя несёт aria-label стрелки |
| Токен `--ui-pagination-size` | 2.75rem (44px) — touch-цель страниц и стрелок (career-portal components.css:240/261, перенос «как есть»; min-геометрия — растёт с 32px-базой T3.6) |
| Токены | `--ui-space-2/3` (gap 8px, паддинг 12px), `--ui-radius-sm` (career-portal `--radius-small`), `--ui-fs-small`/`--ui-fw-small` (career-portal `--fs-small-regular` × `--fw-small`), `--ui-color-text`, `--ui-color-surface-hover` (hover blue-100, ADR-0010), `--ui-color-primary` + `--ui-color-text-on-dark` (текущая), `--ui-opacity-disabled` (0.3, career-portal components.css:269), `--ui-transition` |
| JS | не требуется (CSS-компонент); `data-ui-*` хуков нет |

```html
<nav class="ui-pagination" aria-label="Пагинация">
  <button class="ui-pagination__arrow" type="button" disabled aria-label="Предыдущая страница">
    <svg aria-hidden="true" width="16" height="16" viewBox="0 0 16 16" fill="none"><path d="M14 8H3M8 3L3 8l5 5" stroke="currentColor" stroke-width="2" stroke-linecap="round" stroke-linejoin="round"/></svg>
  </button>
  <span class="ui-pagination__page" aria-current="page">1</span>
  <a class="ui-pagination__page" href="?page=2" aria-label="Страница 2">2</a>
  <span class="ui-pagination__ellipsis" aria-hidden="true">…</span>
  <a class="ui-pagination__page" href="?page=12" aria-label="Страница 12">12</a>
  <a class="ui-pagination__arrow" href="?page=2" aria-label="Следующая страница">
    <svg aria-hidden="true" width="16" height="16" viewBox="0 0 16 16" fill="none"><path d="M2 8h11M9 3l5 5-5 5" stroke="currentColor" stroke-width="2" stroke-linecap="round" stroke-linejoin="round"/></svg>
  </a>
</nav>
```

```html
<!-- Форма без стрелок (--bare): только страницы, как .pagination
     оригинала career-portal на списковых страницах. -->
<nav class="ui-pagination ui-pagination--bare" aria-label="Пагинация">
  <span class="ui-pagination__page" aria-current="page">1</span>
  <a class="ui-pagination__page" href="?page=2" aria-label="Страница 2">2</a>
  <a class="ui-pagination__page" href="?page=3" aria-label="Страница 3">3</a>
</nav>
```

## Без стрелок (`--bare`)

Модификатор даёт форму компонента без стрелок: в DOM остаются только
номера страниц. Так рендерит пагинацию оригинал career-portal на списковых
страницах (vacancies и остальные списки: `.pagination` содержит лишь
`pagination__page`, стрелок нет — REPORT §8.2 №7), и для таких списков
клона bare — каноническая форма.

**Когда bare уместен**: компактные списки с малым числом страниц (3—5), где
шаг на соседнюю страницу — клик по самому номеру, а стрелки дублируют
соседние номера и съедают ширину строки (как в career-portal). Для длинных
списков с окном и «…» (12, 20 страниц) держите default со стрелками:
стрелки — структурный элемент доступной навигации по страницам (T6.3),
шаг «вперёд/назад» вне окна показа.

**Две формы применения** (Implementation requirements п.1):

1. Основная — bare-разметка вовсе не включает стрелки (как в примере выше
   и в оригинале career-portal).
2. Страховка для готовой разметки — модификатор на блоке прячет существующие
   `.ui-pagination__arrow` через `display: none`. Скрытый элемент
   не фокусируется, не кликается и исключается из дерева доступности —
   bare не добавляет ни одной лишней остановки Tab.

Граница с правилом «не прячьте недоступную стрелку» (Do / Don't ниже):
там речь о выборочном скрытии ОДНОЙ стрелки в default-форме — лента
«прыгает», а состояние «дальше нет» перестаёт читаться. `--bare` снимает
ОБЕ стрелки формой компонента целиком — лента без стрелок и есть одобренный
вид такой пагинации.

A11y не сужается: лендмарка `nav[aria-label]` остаётся смысловым контейнером
(WCAG 2.4.4), ссылки страниц — по-прежнему единственные и достаточные цели
навигации (имена «Страница N», `aria-current="page"` на текущей); Tab-порядок
сжимается до самих страниц.

## Решения a11y (Open Questions задачи — закрыты при реализации)

APG отдельного паттерна «pagination» не содержит; правила сведены из
смежных практик WAI (aria-current, нативная семантика disabled) и
зафиксированы здесь:

1. **Текущая страница — `<span class="ui-pagination__page"
   aria-current="page">`, не ссылка.** Ссылка «на себя» — мусорная
   остановка Tab и ложное обещание перехода; `aria-current="page"`
   объявляет текущую скринридеру ровно один раз на навигацию. Стиль
   текущей читает CSS из семантики: `.ui-pagination__page:where([aria-current='page'])`
   — атрибут-источник правды без класса-дубля (`is-active` career-portal
   не переносится; прецедент — `aria-selected` ui-tabs, `aria-current`
   ui-dropdown). Спека допускала и `<a>` без href — выбран span: у якоря
   без href роль generic, атрибуты-поговорки не нужны, а html-валидность
   очевиднее.
2. **Недоступная стрелка — `<button type="button" disabled>`, а не
   `<span aria-disabled>` и не `<a disabled>`.** `<a disabled>` career-portal
   невалиден (атрибут действует только на button/input/…). Нативный
   disabled — принцип «сначала нативная семантика» (02-architecture §5):
   гарантированно не фокусируется, не кликается, скринридер объявляет
   «неактивно» без единого ARIA-атрибута. Альтернатива «span + aria-hidden
   глиф + aria-disabled на обёртке» отвергнута: aria-label на generic-
   элементе запрещён (axe aria-allowed-attr), имя пришлось бы собирать
   визуально-скрытым текстом, а не-кликабельность обеспечивать
   pointer-events вместо семантики. Доступная стрелка — ссылка (переход
   без JS); disabled-кнопка появляется только там, где цели перехода нет.
3. **Страницы называются «Страница N»** (aria-label): список из голых цифр
   скринридер читает отрывочно; имя продолжает видимый текст (WCAG 2.5.3).
   На текущей span aria-label не ставится (запрещён на generic) — её
   объявляет aria-current.
4. **«…» — `aria-hidden`**: указатель пропуска декоративен; набор
   доступных ссылок сам сообщает, какие страницы достижимы.

## Клавиатура и скринридер

- **Tab** идёт по порядку DOM = визуальному: «Назад» → страницы по
  возрастанию → «Вперёд»; текущая страница (span) и «…» — не остановки.
- **Фокус** — глобальная политика ADR-0001 (`a:focus-visible`,
  `button:focus-visible`), компонент outline не гасит.
- **Enter** на странице/стрелке — штатный переход по ссылке.
- Скринридер: вход в лендмарку «Пагинация», страницы объявляются
  «Страница N, ссылка», текущая — «текущая страница», недоступная стрелка
  — «неактивно».

## Окно страниц с «…»

Первое/последнее приглашение всегда видно; вокруг текущей — окно ±1
(параметр `$side` сниппета); разрыв длиннее одной страницы сжимается в
«…», разрыв ровно в одну страницу показывается самим номером («…» ради
одной страницы не рисуют). Пример (20 страниц, текущая 7):
`1 … 6 7 8 … 20`. Расчёт — копипаст-готовый PHP-сниппет
`bitrix/snippets/pagination.php`; JS-версия не заведена (рендер —
серверная зона, Out of scope AJAX-пагинация).

## Bitrix

- Генератор — `bitrix/snippets/pagination.php` (`renderUiPagination($total,
  $current, $urlTemplate, $label, $side)`): принимает общее число страниц,
  текущую и шаблон URL с плейсхолдером `#PAGE#`; текущая/стрелки/«…»
  собираются по правилам выше, вывод экранируется. Для
  `bitrix:news.list` — `$arResult['NAV_PAGE_COUNT']`/`['NAV_PAGE_NOMER']`
  (пример в шапке сниппета).
- Вертикальные отступы вокруг пагинации — ответственность шаблона
  страницы (layout-примитивы), не компонента.
- Каскад legacy-CSS: цвет и `text-decoration` страниц заданы явно —
  глобальные стили ссылок сайта пагинацию не перекрашивают.

## Do / Don't

- **Do**: одна лендмарка на список; на странице с несколькими
  пагинациями — различайте aria-label.
- **Do**: давайте URL каждой достижимой странице (в т.ч. выпавшим за
  окно — они возвращаются изменением текущей).
- **Do**: компактным спискам с малым числом страниц (как списки
  career-portal) — форма `--bare`: только страницы, стрелки там дублируют
  соседние номера; длинным спискам с окном и «…» — default со стрелками
  (секция «Без стрелок» выше).
- **Don't**: не делайте текущую страницу ссылкой и не вешайте
  `aria-current` на несколько элементов.
- **Don't**: не прячьте недоступную стрелку из DOM — её место занято
  (лента не «прыгает»), а состояние «дальше нет» communicated
  button[disabled]; удаляйте стрелку целиком, только если список
  помещается на одну страницу (пагинация не выводится вовсе). Это правило
  про ВЫБОРОЧНОЕ скрытие одной стрелки в default-форме; снять обе стрелки
  формой компонента — легитимный `--bare` (секция «Без стрелок» выше).
- **Don't**: не оборачивайте страницы в кнопки «для единообразия» —
  без JS кнопка не перейдёт на страницу; ссылки — единственный
  работающий без JS путь.
- **Don't**: не меняйте 44×44 touch-цель под «компактные» списки —
  требование задачи и WCAG 2.5.8; уменьшение — design-decision
  владельца дизайна.

## Известные границы

- **AJAX-пагинация / load-more — Out of scope (T6.3)**: перехват кликов и
  подмена контента — зона сайта; при AJAX сохраняйте ту же разметку
  состояний (aria-current, disabled) и переносите фокус на начало
  нового списка сами (паттерн — задача списка T8.1). Load-more —
  тривиальный паттерн на ui-button (кнопка-действие, не навигация).
- Расчёт окна живёт в PHP-сниппете; клиентского JS-рендера у компонента
  нет — клиентский сценарий (SPA) соберёт разметку по правилам этой
  доки.
- «…» не интерактивна (раскрытие пропущенных страниц — расширение по
  потребности, отдельная задача с фокус-менеджментом).
