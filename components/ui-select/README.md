# ui-select

Кастомный listbox поверх нативного `<select>` по паттерну
[APG «Listbox and associated button»](https://www.w3.org/WAI/ARIA/apg/patterns/listbox/):
нативный select остаётся в DOM и работает (формы, скринридер), кастомный
триггер+список строятся поверх, выбор синхронизируется в обе стороны и
диспатчит `change` (bubbles) — фильтры и формы сайтов работают как с
нативным контролом. Задача T7.3. Источник поведения — `dropdowns.js`
career-portal (класс B аудита); критический рефакторинг: знание о классе
проекта (`vacancy-search__select-wrap`) заменено модификатором
`data-ui-select="wrap"` — сайт-специфика не попадает в системные модули
(правило CONTRIBUTING).

## API

| Что | Значение |
|---|---|
| Хук | `data-ui-select` на `<select>` — только на нём (иначе `console.warn`) |
| Модификатор `data-ui-select="wrap"` | select живёт в обёртке сайта («пилюля» фильтра): обёртка даёт позиционный контекст и геометрию, триггер растягивается на неё (замена хака `vacancy-search__select-wrap`) |
| Построенный корень | `.ui-select` (или `.ui-select--wrap`) — создаёт модуль |
| Построенный `.ui-select__trigger` | `<button type="button">` — абсолютный слой `inset: 0` поверх select; `aria-haspopup="listbox"`, `aria-expanded`, `aria-controls` (id генерируется от id select) |
| Построенный `.ui-select__label` | текст выбранного — **имя триггера отражает выбор** |
| Построенный `.ui-select__icon` | декоративный шеврон (aria-hidden), разворот в `.is-open` |
| Построенный `.ui-select__list` | `role="listbox"`; видимость — атрибут `hidden`; `aria-label` = текст label поля |
| Построенный `.ui-select__option` | `<button role="option">` + `aria-selected`; выбранному — `is-selected` + «✓»; `value=""` — `--reset` (muted) и не получает `is-selected` |
| Построенный `.ui-select__group` | для `<optgroup>`: `role="group"` + `aria-label` группы |
| Состояние `.is-open` | на построенном корне, только в цепочке |
| Состояние `.is-placeholder` | на триггере, когда выбрано пустое значение |
| Нативный select после init | класс `.ui-select__native` (opacity 0 + pointer-events none — custom-select-hidden career-portal) + `tabindex="-1"` (триггер заменяет его в Tab-порядке); форму не покидает, значение уходит |
| JS | `IraoUI.select`: `init()`, `selector`, `closeAll()`, `destroy(selectOrRootOrId)`; чистые функции `viewOf(select)`, `typeaheadIndex(texts, from, char[, disabled])` |
| Событие | нативный `change` (bubbles) на select — единственная точка расширения; собственных событий модуль не диспатчит |
| Токены | `--ui-z-dropdown` (лестница T2.2), `--ui-color-{text, text-muted, surface, surface-muted, surface-hover, primary}`, `--ui-radius-{sm, pill}`, `--ui-border-width`, `--ui-space-{1,2,3,4}`, `--ui-shadow-lg`, `--ui-fs-{small,micro}`, `--ui-fw-{body,small}`, `--ui-lh-{small,micro}`, `--ui-transition`, focus-тройка ADR-0001 |

```html
<!-- Авторская разметка: обычный select; всё остальное строит модуль -->
<div class="ui-field">
  <label class="ui-field__label" for="ui-select-city">Город</label>
  <select class="ui-field__select" id="ui-select-city" name="city" data-ui-select>
    <option value="">Любой город</option>
    <optgroup label="Россия">
      <option value="msk">Москва</option>
      <option value="spb">Санкт-Петербург</option>
    </optgroup>
  </select>
</div>
```

## Деградация без JS

В разметке select **не скрыт и не тронут** — это обычный нативный select:
значение уходит с формой, скринридер и клавиатура работают с ним. Класс
скрытия, `tabindex="-1"`, триггер, список и aria — всё ставит модуль при
инициализации (тот же приём, что `novalidate` в ui-form): разметка остаётся
правдивой без JS, а «подмена» появляется только вместе с умением её обслуживать
(принцип T5.2: «нативный select не прячется никогда» — до инициализации).

## Синхронизация

- **UI → select**: выбор опции устанавливает `select.selectedIndex`, и модуль
  диспатчит `new Event('change', { bubbles: true })` — обработчики формы
  срабатывают как от нативного контрола (перенос career-portal).
- **select → UI**: нативный `change` от любого стороннего кода (фильтры,
  сброс формы, Bitrix AJAX) обновляет текст триггера и отметки `is-selected`/
  `aria-selected`.
- **Чистые функции** (юнит-поверхность, `tests/unit/select.test.js`):
  `IraoUI.select.viewOf(select)` — модель опций/групп из состояния select
  (без мутаций DOM); `IraoUI.select.typeaheadIndex(texts, from, char,
  disabled?)` — индекс следующего совпадения typahead. DOM-синхронизация —
  метод инстанса `sync()`.
- Отметка выбора: `aria-selected` — всегда правда состояния select;
  `is-selected` («✓») — только у непустых значений: пустое значение — это
  placeholder триггера (пара career-portal `dropdowns.js`).

## Клавиатура — чек-лист APG listbox (проверено e2e)

| Действие | Поведение |
|---|---|
| Клик по триггеру | toggle; фокус остаётся на триггере (pointer-сценарий) |
| `Enter` / `Space` на триггере | открыть, фокус на **выбранной** опции (open() career-portal) |
| `ArrowDown` / `ArrowUp` на закрытом триггере | открыть, фокус на выбранной опции |
| `ArrowDown` / `ArrowUp` в списке | соседняя опция **без зацикливания** (APG listbox), disabled пропускается |
| `Home` / `End` в списке | первая / последняя доступная опция |
| Печатный символ в списке | typahead по первой букве: следующее совпадение с циклом; disabled не матчится (APG type-ahead — принят по Scope; чистая функция `typeaheadIndex`) |
| `Enter` / `Space` на опции | выбрать: value синхронизован, `change` (bubbles), список закрыт, фокус на триггере |
| `Escape` | закрыть, фокус на триггер (слушатель **документа** — работает и при фокусе вне инстанса, перенос career-portal) |
| `Tab` | закрыть список, фокус уходит по естественному порядку (select вне Tab-порядка — пропускается) |
| Открытие одного select | закрывает другие (closeAll career-portal; реестр свой — dropdown'ы T6.1 не трогаются) |
| Клик вне | закрыть (переиспользование логики T6.1) |

## A11y

- `aria-haspopup="listbox"` + `aria-expanded` + `aria-controls` на триггере —
  ставит и синхронизирует модуль. Имя поля переносится с нативного select по
  схеме, зависящей от связи label:
  **`label[for=id]`** → `aria-labelledby` триггера = label + собственный текст
  (имя «Город» не теряется, выбранное значение входит в имя — пара APG);
  **label-обёртка** (label содержит select) → `aria-label` триггера и списка
  чистым текстом label **без поддерева select**: наивный `textContent` дал бы
  весь инвентарь опций (нативная ассоциация label-обёртки контрол исключает),
  а живая обёртка после init содержит и построенный UI — `aria-labelledby` на
  неё не ссылается (ревью T7.3 high; юнит-пины обоих случаев). Нюанс: при
  label-обёртке выбранное значение видно текстом триггера, но в доступное имя
  не входит — если оно должно быть в имени, дайте полю `label[for]`.
  id генерируются только там, куда есть ссылка.
- Список получает `aria-label` поля (в обеих схемах, когда имя удалось
  определить).
- Опции — настоящие `<button role="option">` с `aria-selected`: фокус
  настоящий (без roving tabindex/activedescendant — упрощение переносится из
  career-portal, все опции Tab-табелируемы при открытом списке).
- `<optgroup>` → `role="group"` + `aria-label` (ARIA 1.1: группы внутри
  listbox), заголовок группы виден.
- Нативный select остаётся форм-контролом и элементом a11y-дерева
  (opacity 0, не display:none): скринридер в режиме обзора доходит до него,
  форма отправляет значение. Из Tab-порядка его убирает модуль
  (`tabindex="-1"`), иначе после триггера фокус попадал на невидимый select —
  двойная таб-остановка.
- Disabled select → `disabled` триггер; disabled-опции → `disabled` кнопки
  (не фокусируются, пропускаются стрелками и typahead).
- Видимый фокус рисует глобальная политика `base/focus.css` (ADR-0001);
  пунктам и триггеру поверх добавляется поверхность hover/фокуса (пара
  ui-dropdown). Контраст поверхностей — гейт T2.3; e2e axe чист закрытым и
  открытым во всех секциях стенда.

## Мобильная стратегия — [ADR-0012](../../docs/adr/0012-select-pointer-coarse.md)

На устройствах с coarse-указателем (`matchMedia('(pointer: coarse)')`) модуль
**не активируется**: select остаётся нативным — системный пикер ОС на таче
доступнее самодельного списка (колесо, крупные цели, нативный скролл). Запрос
живой, на момент инициализации инстанса; переинициализация после смены режима
без перезагрузки страницы не отслеживается. Проверка: юнит-пин (jsdom-
заглушка matchMedia) + e2e-контекст `hasTouch`.

## Do / Don't

- **Do**: хук — только на `<select>`; name обязателен (иначе форма не
  отправит значение и без JS).
- **Do**: select в ui-field — просто оставьте `ui-field__select` на select;
  триггер накроет его той же поверхностью (surface-muted + radius-sm — визуал
  поля сохраняется).
- **Do**: для «пилюли» фильтра (замена vacancy-search-хака) — обёртка сайта с
  геометрией + `data-ui-select="wrap"`; обёртку удобно сделать `<label>` —
  тогда имя поля получают и select, и триггер.
- **Don't**: не оборачивайте улучшаемый select в `ui-field__select-wrap` —
  обёртка рисует стрелку псевдоэлементом, которая будет торчать над
  кастомным шевроном; обёртка стрелки нужна только чисто нативному select
  (T5.2).
- **Don't**: не кладите класс `ui-select__native` и `tabindex="-1"` в
  разметку — их ставит/снимает модуль; статичное скрытие убивает деградацию.
- **Don't**: multi-select и поиск-фильтрация внутри списка — не этот
  компонент (Out of scope T7.3).

## Bitrix (шаблоны)

Разметка копируется в шаблон компонента фильтра; `data-ui-select` — хук
модуля (он уже в `ui.min.js`). Значение опций — из инфоблока (JSON-паттерн
02-architecture §6.3). Динамически вставленный select (AJAX-фильтр) —
вызовите `IraoUI.select.init()` повторно: инициализированные инстансы
пропускаются по флагу. Для удаления инстанса — `IraoUI.select.destroy(select)`
(разметка возвращается к no-JS состоянию, повторная инициализация возможна).
Интеграция с формами — по нативному `change` на select; `closeAll()` —
закрыть все открытые списки (например, перед сабмитом извне).

## Известные границы

- Двойное представление для скринридера: в режиме обзора доступны и
  нативный select, и кастомный триггер (цена PE-паттерна career-portal;
  порядок обхода — нативный select последним ребёнком корня).
- Позиционирование списка — только «вниз от корня» (`top: 100%`), без
  флипа вверх и коллизий с краем вьюпорта (решается обёрткой сайта;
  потребность — по факту, как в ui-dropdown).
- Высота списка ограничена `max-height: 300px` (18.75rem, career-portal) со
  скроллом; пункты вне видимой области при стрелках скроллит браузер.
- Смена pointer-режима на живой странице (отстёгнутая клавиатура планшета)
  не переоценивается — см. ADR-0012.
- Escape/вне-клик слушаются на документе: закрытие работает из любой точки
  страницы, но список не закрывается автоматически при сабмите формы
  (стандартное поведение — перезагрузка/переход).
