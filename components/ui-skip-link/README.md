# ui-skip-link

Клавиатурный переход к основному контенту («Перейти к основному содержимому»).
Задача T3.5; a11y-паттерн WCAG 2.4.1 «Bypass Blocks» — закрытие пробела аудита
career-portal (§6: skip-link отсутствовал, первый Tab попадал в меню).

## API

| Что | Значение |
|---|---|
| Блок | `.ui-skip-link` на `<a>`; модификаторов и элементов нет |
| Цель | `href="#main"` — `<main id="main" tabindex="-1">` на странице |
| JS | не требуется (CSS-компонент) |
| Где ставить | **первым элементом `<body>`** — до шапки, чтобы первый Tab попадал в него |
| Текст | «Перейти к основному содержимому» (текст каркаса showcase; сайты могут формулировать иначе) |

```html
<body>
  <a class="ui-skip-link" href="#main">Перейти к основному содержимому</a>
  <header>…</header>
  <main id="main" tabindex="-1">…</main>
```

## Состояния

- **До фокуса** — 1px-клип (`clip-path: inset(50%)` + легаси-дублёр
  `clip: rect(0, 0, 0, 0)`, бокс 1×1, `margin: -1px`): визуально недоступна,
  но в дереве доступности — скринридер видит ссылку первым элементом страницы.
  Никаких `display: none` / `visibility: hidden` — они выкинули бы ссылку из
  дерева доступности.
- **В фокусе** (Tab) — фиксированная плашка top-left: `position: fixed`,
  `top/left: 0`, `z-index: var(--ui-z-overlay)` (лестница T2.2 — уровень
  оверлеев), фон `--ui-color-primary`, текст `--ui-color-text-on-dark`
  (контрастная пара одобренного дизайна). Outline клавиатурного фокуса
  рисует глобальная политика `base/focus.css` (ADR-0001).
- Появление мгновенное, без анимации (уважение к `prefers-reduced-motion`
  и меньше движения).

## Клавиатура и a11y

- **Tab** (первый на странице) — фокус на skip-link; **Enter** — переход к
  `#main`. e2e: `tests/e2e/skip-link.spec.js` (Tab→Enter→`activeElement`
  внутри `main`, скрытость до фокуса, плашка, axe).
- **`tabindex="-1"` на цели обязателен в каркасе.** Спека допускала цель без
  него, но зонд chromium 2026-10-06 (фиксирован в e2e-пинах) показал: без
  `tabindex="-1"` Enter меняет хэш, а `activeElement` уходит на `<body>` —
  фокус «виртуально» в контенте, но скринридер/клавиатура продолжают со
  ссылки. `tabindex="-1"` делает `<main>` фокусируемым программно (в Tab-порядок
  он не попадает — минус не участвует в последовательной навигации) — это же
  стандартное решение Safari-кейса переноса фокуса. Сайтам — то же правило.
- **Safari/WebKit**: по умолчанию Tab не встаёт на ссылки (нужен Option+Tab —
  системная настройка полного клавиатурного доступа). Это поведение браузера,
  не дефект разметки: e2e-сценарии Tab-обхода на webkit помечены skip
  с этим основанием.
- **Дополнительные skip-цели** (к поиску, меню) — по потребности сайтов,
  паттерн расширяется тривиально: ещё один якорь с другой целью и текстом;
  каждая — со своим `id`-целью. В систему не входит (Out of scope T3.5).
- NVDA/VoiceOver-чек-лист — T9.2 (поведение в скринридерах).

## VI-режим (EPIC-9)

Перекраска `a11y/vi.css` (`!important` по ГОСТ) накрывает плашку как обычный
элемент: компонент не содержит цветов вне токенов `--ui-*` (инвариант §5
02-architecture), поэтому VI-версия остаётся контрастной без правок этого
файла.

## Do / Don't

- **Do**: первым элементом `<body>`; цель `<main id="main" tabindex="-1">`
  существует на странице; текст «Перейти к основному содержимому».
- **Don't**: не прятать цель `display: none`/`visibility: hidden` — ссылка
  уйдёт из дерева доступности; не ставить на видимое место в разметке среди
  контента (плашка появится в левом верхнем углу — так задумано); не
  дублировать `id="main"` на странице.

## Bitrix (header.php)

Ставить **сразу после открывающего `<body …>` в `header.php`** шаблона сайта —
он вставляется до `$APPLICATION->ShowPanel()`-контента и шапки, поэтому первый
Tab страницы попадает в ссылку (сниппет: `bitrix/snippets/header-php.snippet.php`).
Цель — `<main id="main" tabindex="-1">` в шаблоне страницы/`footer.php`; сборка
showcase валидирует пару «ссылка + цель» на каждой странице полигона
(selfChecks `showcase/build.mjs`) — то же правило для сайтов: **цель
существует**, иначе ссылка ведёт в никуда (дефект 2.4.1).
