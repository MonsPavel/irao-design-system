# ui-figure

Фигура с подписью: нативные `<figure>`/`<figcaption>` — подпись структурно
принадлежит изображению, а не «текст рядом с картинкой» (Accessibility
requirements T4.6: «подпись связана семантически»). Задача T4.6. В
career-portal подписи собирались контентной вёрсткой без figure-семантики
(article-page__gallery, pages.css:455).

## API

| Что | Значение |
|---|---|
| Блок | `.ui-figure` на `<figure>` — сброс UA-отступа (`margin: 0`; глобальный сброс базы figure не трогает, legacy-сброс сайта тоже не обязан) |
| Элемент `.ui-figure__caption` | на `<figcaption>` — шаг от изображения `--ui-space-2` (8px); типографика — роли base в разметке (`ui-small`, `ui-text--muted`), компонент шрифты не переобъявляет (паттерн ui-card/ui-alert) |
| Внутри | `<img class="ui-image">` со всеми атрибутами паттерна (alt, width/height, loading, aria-describedby — README ui-image) |
| JS | не требуется (CSS-компонент) |
| Токены | `--ui-space-2` |

```html
<figure class="ui-figure">
  <!-- prettier-ignore -->
  <img class="ui-image" src="/upload/reports/internship-2025.svg"
       alt="Динамика заявок на стажировку за 2025 год" width="640" height="360">
  <figcaption class="ui-figure__caption ui-small ui-text--muted">
    Рис. 1. Число заявок по месяцам: пики — март и сентябрь.
  </figcaption>
</figure>
```

## Семантика подписи

- `<figcaption>` объявляется скринридером вместе с содержимым `figure`:
  связь подписи с изображением структурная — при переносе контента и в
  a11y-дереве подпись не теряется. Соседний `<p>` этой гарантии не даёт.
- **Alt и подпись — разные задачи**: alt описывает, что изображено; подпись —
  что это значит в контексте страницы («Рис. 1. …»). Подпись НЕ заменяет alt.
- `figure` без `figcaption` легален (изображение без подписи); обратная
  задача — подпись без изображения — тоже покрывается figure-семантикой,
  но такие кейсы в системе не типизируются.

## Клавиатура и a11y

- Не интерактивен: фигура не фокусируется и в Tab-порядок не попадает;
  остановки — интерактивы внутри (например, ссылка на изображении).
- Скринридер: `figcaption` объявляется вместе с содержимым `figure`
  (связь структурная); изображения в фигуре — по паттерну
  [ui-image](doc:ui-image) (alt обязателен и осмысленный — подпись его
  не заменяет).
- Подписывать декоративное изображение (`alt=""`) запрещено: скринридер
  пропускает и картинку, и подпись к ней (do/don't ниже).

## Do / Don't

- **Do**: подписи диаграмм/фото в статьях — `ui-figure` + `figcaption` +
  роли base для типографики.
- **Do**: для complex-изображений сочетайте с `aria-describedby` (README
  ui-image): alt — кратко, описание — полностью, подпись — вывод.
- **Don't**: подписывать декоративное изображение (`alt=""`): скринридер
  пропускает и картинку, и подпись к ней — «подпись в никуда»; у
  подписанного изображения alt обязателен и осмысленный.
- **Don't**: текст подписи как обычный `<p>` после `<img>` — связь
  теряется и для скринридера, и при переносе контента.
- **Don't**: стилизовать подпись inline или компонентными шрифтами —
  роли base в разметке (инвариант §5, паттерн слотов ui-card).

## Bitrix (шаблоны)

Подпись — из свойства инфоблока (например, `SIGNATURE`): `<figcaption>`
выводится только когда свойство заполнено; пустой figcaption не рендерить.
Изображение внутри — `ui-image` со всеми атрибутами паттерна; типографика
подписи — роли base.

## Известные границы

- Компонент сознательно минимален: без вариантов оформления подписи
  (утверждённого дизайна подписей в career-portal нет) — стилизуйте ролями
  base; появление дизайн-пары подписи — отдельная задача с токеном.
- Галереи/слайдеры из фигур — контентные паттерны EPIC-8 (T8.1+), не здесь.
