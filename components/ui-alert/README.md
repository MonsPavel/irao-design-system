# ui-alert

Статусные сообщения: 4 варианта из семантических пар статусов (`--info`,
`--success`, `--warning`, `--error` — bg + иконка + цвет), закрываемый вариант
`__close`. Задача T4.5. В career-portal отдельного компонента сообщений не
было — только пары токенов статусов и текст ошибок полей; потребители паттерна —
формы (сводная ошибка — T5.4) и списки (пустое/ошибочное состояние — T4.8).

## API

| Что | Значение |
|---|---|
| Блок | `.ui-alert` на `<div>` — корень сообщения (флекс: иконка + тело + опциональная кнопка закрытия) |
| Модификатор `.ui-alert--info` | пара `--ui-color-info-bg` / `--ui-color-info` |
| Модификатор `.ui-alert--success` | пара `--ui-color-success-bg` / `--ui-color-success` |
| Модификатор `.ui-alert--warning` | пара `--ui-color-warning-bg` / `--ui-color-warning` (токены заведены T4.5: оранжевые ступени одобренной шкалы) |
| Модификатор `.ui-alert--error` | пара `--ui-color-error-bg` / `--ui-color-error` |
| Без модификатора | нейтральное сообщение: `--ui-color-surface-muted` / `--ui-color-text` (прецедент «тихой» базы ui-button/ui-tag) |
| Элемент `.ui-alert__icon` | svg-иконка варианта 24px (`--ui-space-5`); **обязателен `aria-hidden="true"`** — красится `currentColor` |
| Элемент `.ui-alert__body` | тело: колонка сообщений (роль типографики + текст), шаг `--ui-space-2` |
| Элемент `.ui-alert__close` | кнопка закрытия 32px (`--ui-space-6`); `type="button"`, **`aria-label="Закрыть"`**, data-хук `data-ui-alert-close` |
| Элемент `.ui-alert__close-icon` | svg-глиф × 16px (`--ui-space-4`), `aria-hidden="true"` |
| JS | модуля нет (статичный компонент, Out of scope T4.5): удаление делает JS сайта по хуку `data-ui-alert-close` |
| Токены | радиус `--ui-radius-md`, отступы `--ui-space-3`/`--ui-space-4`/`--ui-space-2`, размеры `--ui-space-5`/`--ui-space-6`/`--ui-space-4`; цвета — пары «Цветов-смыслов: статусы» |

```html
<div class="ui-alert ui-alert--info" role="status">
  <svg class="ui-alert__icon" aria-hidden="true" focusable="false" width="24" height="24"
       viewBox="0 0 24 24"><!-- круг + i, stroke="currentColor" --></svg>
  <div class="ui-alert__body">
    <p class="ui-body">Приём заявок открыт до 30 ноября.</p>
  </div>
</div>

<div class="ui-alert ui-alert--error" role="alert">
  <svg class="ui-alert__icon" aria-hidden="true" focusable="false" width="24" height="24"
       viewBox="0 0 24 24"><!-- круг + ×, stroke="currentColor" --></svg>
  <div class="ui-alert__body">
    <p class="ui-body">Не удалось отправить форму: проверьте подключение к сети.</p>
  </div>
  <button class="ui-alert__close" type="button" data-ui-alert-close aria-label="Закрыть">
    <svg class="ui-alert__close-icon" aria-hidden="true" focusable="false" width="16" height="16"
         viewBox="0 0 16 16"><!-- ×, stroke="currentColor" --></svg>
  </button>
</div>
```

## Роль по критичности: status vs alert

Роль выставляется **в HTML-паттерне** — интегратор копирует её вместе с
разметкой, JS ничего не выставляет (Technical considerations T4.5). Роль живёт
в DOM вместе с алертом, поэтому динамически вставленный алерт объявляется
скринридером немедленно; алерт, отрендеренный сервером при загрузке страницы,
скринридеры целиком не объявляют (стандартное поведение live-регионов) —
роль при этом обязательна: она объявит алерт при клиентской вставке и при
повторном обновлении содержимого.

| Критичность | Роль | Когда |
|---|---|---|
| Низкая — результат операции, к которому не нужно немедленно реагировать | `role="status"` (вежливое объявление, aria-live polite) | «Черновик сохранён», «Заявка принята в работу», информационные заметки форм |
| Высокая — требуется реакция сейчас | `role="alert"` (немедленное объявление, aria-live assertive) | сводная ошибка формы (T5.4), «сессия истекает», серверная ошибка отправки |

Примеры:

- `info` + `role="status"` — «Приём заявок открыт до 30 ноября»;
- `success` + `role="status"` — «Резюме отправлено»;
- `warning` + `role="alert"` — «Сессия истекает через 5 минут»;
- `error` + `role="alert"` — «Не удалось отправить форму».

Не переключайте роль/`aria-live` динамически на уже показанном алерте —
меняйте разметку целиком (вставьте новый узел, удалите старый).

## Закрываемый вариант: правило живого региона

aria-live-регион не должен «терять» контент неожиданно (Implementation
requirements T4.5 п.2). Правило компонента:

- **закрытие допустимо только по явному действию пользователя** — клик или
  Enter/Space на `ui-alert__close`: регион пустеет синхронно с действием,
  пользователь сам инициировал исчезновение (WCAG-безопасно);
- **скрытие таймаутом запрещено** — алерт исчезает «сам», скринридер и
  пользователь с клавиатурой теряют контент без действия (toasts со стеком и
  таймаутами — P2, Out of scope T4.5);
- **скрытие — удаление узла из DOM** (демо-скрипт стенда:
  `node.closest('.ui-alert').remove()`); эквивалент — атрибут `hidden`
  (глобальная гарантия `base/reset.css` убирает узел и из a11y-дерева);
  переключать `aria-live`/роль при этом не нужно;
- JS вешается только на data-хук `data-ui-alert-close` — не на стилевой класс
  (§2 «Namespace»); без JS кнопка просто не закрывает — компонент остаётся
  статичным, сайты без скриптов удаляют алерт серверно или не показывают
  кнопку.

## Варианты и геометрия

- Отступы — spacing-токены: паддинг `--ui-space-4`, gap иконка↔тело
  `--ui-space-3`, шаг сообщений в теле `--ui-space-2` (Technical
  considerations T4.5); радиус — `--ui-radius-md`.
- Высот нет: алерт растёт по контенту вместе с 32px-базой T3.6 (прецедент
  ui-card).
- Иконка — svg 24×24 с атрибутами `width`/`height` (нет CLS), `fill="none"`
  и `stroke="currentColor"` в разметке: CSS-цвет сознательно не задаётся —
  варианты, темы и VI-перекраска работают сами (паттерн ui-button__icon).
- Типографика текста — роли base (`ui-body` и др.): компонент текстовые
  стили не переобъявляет. Составное сообщение (заголовок + текст) собирается
  в `ui-alert__body` ролями типографики (`ui-h4` + `ui-body`) — отдельного
  слота `__title` у компонента нет.

## Клавиатура и a11y

- Смысл сообщения — **текстом, не только цветом/иконкой** (WCAG 1.4.1):
  иконка `aria-hidden`, алерт без текста не имеет смысла (do/don't ниже).
- Кнопка закрытия — нативный `<button>` с `aria-label="Закрыть"`: доступна с
  клавиатуры (Tab→Enter проверено e2e), имя не зависит от декоративного глифа.
- Фокус кнопки — глобальная политика ADR-0001 (`button:focus-visible` в
  `base/focus.css`): компонент outline не запрещает и не заменяет.
- Контраст всех пар — гейт T2.3 (`npm run test:contrast`): warning-пара —
  4.78:1 на своём bg, 5.84:1 на белом; error 4.80:1, info/success — пары
  `*-on-*-bg`; e2e стенда пинит computed-пары и контраст ≥ 4.5:1.
- VI-режим (T9.1): перекраска `!important` накроет алерты как все элементы —
  цветов вне токенов в файле нет (инвариант §5); функциональная проверка
  читаемости — за T9.1.

## Do / Don't

- **Do**: `<div class="ui-alert ui-alert--error" role="alert">` поверх формы —
  сводная ошибка отправки (потребитель — T5.4).
- **Do**: вставлять алерт в DOM в ответ на действие — live-роль объявит его.
- **Do**: закрывать только по действию пользователя на `__close`.
- **Don't**: `<div class="ui-alert ui-alert--error" role="alert">` без текста
  — «иконка-сообщение»: смысл не дублируется текстом (WCAG 1.4.1), скринридер
  не объявит ничего.
- **Don't**: `setTimeout(() => alert.remove(), 5000)` — таймаут-скрытие
  живого региона: контент теряется без действия пользователя (правило выше);
  тосты — P2.
- **Don't**: `<span class="ui-alert ui-alert--info">` как декоративную
  подложку-подпись без статуса — для нейтральных заметок есть база без
  модификатора, а для тегов-аннотаций — `ui-tag`.
- **Don't**: стилизовать алерт inline-стилями или hex-цветом — ломает темы и
  VI-режим (инвариант §5); цвет — выбор модификатора + токены.

## Bitrix (шаблоны)

Паттерн копируется в `template.php`: роль — атрибутом в разметке, вариант —
модификатором, статус — значением из `$arResult`. Серверные ошибки рендерите
теми же классами, что и клиентские (`ui-field--error` + алерт `--error`):
форма и фронт выглядят одинаково (паттерн career-portal). Цвета едут из
токенов: смена темы перекрашивает все варианты без правки разметки.

## Известные границы

- JS-модуля у компонента нет (Out of scope T4.5): закрытие — 3 строки JS сайта
  по data-хуку; тосты/стеки уведомлений и таймаут-скрытие — P2 (Out of scope).
- Warning-пара — ступени одобренной оранжевой шкалы (`--ui-orange-50` =
  `--tag-orange-bg` career-portal, `--ui-orange-800` = AA-замена T2.3):
  значениеbg заметно насыщеннее error-bg/success-bg; пересмотр —
  design-decision владельца дизайна (новая запись таблицы диффов).
- VI-перекраска алертов не проверялась в этой задаче — функциональная
  проверка читаемости в VI-темах за T9.1 (Scope T4.5).
- Новые цветовые варианты без пары контраст-гейт T2.3 не пропустит (новый
  цвет — сначала пара/исключение, прецедент ui-tag).
