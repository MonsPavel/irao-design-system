# CONTRIBUTING

> Статус: финал (T10.4). Обязательные гейты каждого PR: линтеры (`npm run
> lint` + негативные фикстуры `npm run test:lint`), сборка (`npm run build`),
> unit-слой Vitest (`npm run test:unit`, T1.6), e2e+axe-харнесс (`npm test`,
> `npm run test:docker` — tests/README.md), контраст-гейт (`npm run
> test:contrast`). Путь нового участника «задача → PR» — § «Процесс: от задачи
> до PR»; процессные разделы (токены, semver, ADR) — контракт ревью.

## Куда положить файл X

| Тип файла | Куда | Примечание |
|---|---|---|
| Примитив-токен (палитра, шкалы) | `tokens/primitives.css` | hex допустим **только** здесь |
| Смысловой токен `--ui-*` | `tokens/semantic.css` | только ссылки на примитивы (ADR-0009) |
| Базовый стиль (reset, шрифты, фокус, типографика, сетка) | `base/<файл>.css` | глобальная политика фокуса — ADR-0001 |
| Новый компонент | `components/ui-<name>/` | см. «Как добавить компонент» ниже |
| CSS компонента | `components/ui-<name>/ui-<name>.css` | БЭМ `ui-`, токены `--ui-*`, box-sizing на корне (ADR-0002) |
| Канонический HTML компонента | `components/ui-<name>/ui-<name>.html` | источник доки и тестов |
| JS компонента | `components/ui-<name>/ui-<name>.js` | копия `docs/templates/module-template.js` |
| Дока компонента (API, состояния, a11y) | `components/ui-<name>/README.md` | |
| Метаданные док-страницы (шаблон T10.1) | `showcase/docs/<name>.mjs` | карта «секция шаблона → ## заголовок README» + клавиатура/ARIA/чек-лист скринридера/schema/версия; страница генерируется в `showcase/dist/docs/` (showcase/README.md) |
| A11y-модуль (ГОСТ vi) | `a11y/` | `!important` допустим **только** в `a11y/vi.css`; skip-link — не здесь, а компонент `components/ui-skip-link/` (T3.5) |
| Паттерн страницы (header, list-page…) | `patterns/<name>/` | HTML из готовых компонентов, без кода в dist |
| Тема бренда | `themes/theme-<company>.css` | только переопределение токенов `--ui-*` |
| Стенд компонента | `showcase/pages/<name>/` | расширенный стенд; базовый генерируется автоматически из паттерна (showcase/README.md) |
| Сниппет подключения Bitrix | `bitrix/snippets/` | см. `bitrix/integration-guide.md` |
| e2e/axe-тесты | `tests/e2e/`, `tests/a11y/` | привязка к стендам `showcase/pages/` |
| Unit-тесты JS (Vitest, T1.6) | `tests/unit/<имя>.test.js` | юнит-пины решения; эталон контракта шаблона — `tests/unit/module-template.test.js` |
| Скриншот-эталоны | `tests/visual/` | создаются только в контейнере (ADR-0004) |
| Архитектурные доки и ADR | `docs/`, `docs/adr/` | ADR — по процессу из § «ADR-процесс» ниже |
| Шаблон JS-модуля | `docs/templates/` | не production-код |
| Негативная lint-фикстура | `tests/lint-cases/` | намеренно «кривой» файл; строка-ожидание в `tools/run-lint-cases.mjs`; из `npm run lint` исключён |

Правила каскада, действующие везде: hex только в `tokens/primitives.css`;
`!important` только в `a11y/vi.css` (единственные осознанные исключения —
`[hidden]` и reduced-motion kill-switch в `base/reset.css`: байты
career-portal, перенос T3.1, каждое помечено inline-disable с обоснованием);
правило ADR-0002: компонент объявляет свой `box-sizing: border-box` на корне
и не полагается на глобальный сброс `base/reset.css` — legacy-сброс сайта
подключён позже и побеждает равные универсальные селекторы; mobile-first,
`min-width` только из шкалы брейкпоинтов
(шкала и исключения — дока [«Адаптивный подход»](docs/ui-system/architecture/responsive-approach.md));
производные состояния без одобренного дизайна — `color-mix` над токеном слоя 2
(88% базовый + black, под `@media (hover: hover)`), hover-пары одобренного
дизайна — явные токены `--ui-color-primary-hover` / `--ui-color-accent-hover`
(ADR-0010); значения утверждённого дизайна career-portal не меняются
(отклонение — design-decision владельца дизайна). Слои токенов и гейты
заведения новых — § «Правила токенов» ниже; версии изменений —
§ «Semver-триггеры».

## Процесс: от задачи до PR

Путь любого изменения системы (шаги раскрыты в разделах ниже; эталон прохождения
— компонентные задачи EPIC-4–7):

1. **Задача.** Работа идёт по файлу задачи в `docs/ui-system/epics/…` (или по
   заведённой вами заявке, оформленной так же): `## Scope` — граница изменений,
   `## Acceptance Criteria` — приёмка, `## Testing` / `## Accessibility
   requirements` — тесты и a11y. Чужие задачи не трогаются; новая потребность —
   новая задача, а не расширение текущей.
2. **Решения — до кода.** SPIKE, смена принятого подхода, исключение из
   действующего правила — сначала ADR (§ «ADR-процесс»), потом реализация.
3. **Шаблон.** Компонент стартует с канонического HTML-паттерна
   `components/ui-<name>/ui-<name>.html`; JS — копия
   [`docs/templates/module-template.js`](docs/templates/module-template.js)
   (контракт — § «Контракт JS-модуля»); дока — по шаблону страницы T10.1
   (`showcase/docs/<name>.mjs`, § «Чек-лист „страница = шаблон“»).
4. **Тесты first.** Падающие юнит-пины (`tests/unit/<имя>.test.js`) и
   e2e-сценарии (`tests/e2e/<имя>.spec.js`) пишутся ДО реализации; красный шаг
   фиксируется коммитом.
5. **Реализация.** Минимальный код, делающий тесты зелёными; `npm run lint` и
   `npm run test:unit` зелёные в каждом осмысленном коммите.
6. **Дока.** README компонента (API, состояния, a11y, do/don't) + док-страница
   из генератора; changelog-строка компонента и версия введения (semver —
   § «Semver-триггеры»).
7. **Чек-лист ревью и PR.** Компонентная задача проходит «Чек-лист ревью
   компонента» (заведён в T4.2, эталон `components/ui-button/`), ветка
   `task/<ID>` уходит PR'ом в main; CI гоняет обязательные гейты (lint, unit,
   build, e2e+axe — `.github/workflows/ci.yml`, T1.5), visual-чек — advisory
   до v1.0 (ADR-0004). Правки по ревью — отдельными коммитами с пинами
   (красный шаг → фикс), как в эталонных задачах.

## Гейты линтеров (с T1.2)

Команды: `npm run lint` — всё сразу (css → js → format → html);
`npm run test:lint` — прогон негативных фикстур `tests/lint-cases/`.
Оба должны быть зелёными в каждом PR. Что ловит машина:

| Гейт | Правило | Что запрещает |
|---|---|---|
| `stylelint.config.mjs` | `plugin/selector-bem-pattern` | классы вне БЭМ `ui-{block}__{elem}--{mod}`; `is-*`/`has-*` — только в цепочке с блоком (§2 «Namespace») |
| | `scale-unlimited/declaration-strict-value` | сырые цвета (hex/rgb/hsl) вне `var()`/`inherit`/`currentColor`/`transparent`/`color-mix()` — включая цветоносные шорткаты `background`/`border`/`outline` (expandShorthand) и `box-shadow`/`text-shadow` (значение — целостный `var()`-токен); hex разрешён только в `tokens/primitives.css` (§3.1) |
| | `declaration-property-value-allowed-list` | цветной кастом-проп (`--ui-color-*`) — ровно один токен: `var()`/`color-mix()`/`inherit`/`currentColor`/`transparent` (declaration-strict-value кастом-свойства не видит) |
| | `declaration-no-important` | `!important` вне `a11y/vi.css` (§1, принцип 4) |
| | `declaration-property-value-disallowed-list` | `outline: none`/`0` без замены — warning до EPIC-4, затем error (ADR-0001) |
| | `media-feature-name-disallowed-list` + `media-feature-name-value-allowed-list` + `irao/no-negated-min-width` (плагин `tools/stylelint/no-negated-min-width.mjs`) | media-запросы вне mobile-first шкалы (T2.5): viewport-фичи ширины/высоты запрещены, кроме `min-width` (в т.ч. `max-width` и range-синтаксис `width >= …`); значения `min-width` — только шкала `BREAKPOINTS` из конфига (§3.2); «not» перед `min-width` (`not (min-width: …)`, `not all and (…)`) запрещён — семантика «width < Npx», встроенная пара её не видит; неширинные фичи (`prefers-reduced-motion`…) не регулируются; исключение — только через ADR + override (дока «Адаптивный подход») |
| | `irao/no-primitive-token-references` (локальный плагин `tools/stylelint/no-primitive-token-references.mjs`) | ссылки на примитивы слоя 1 (`var(--ui-blue-800)`…) вне `tokens/` — компоненты читают только слой 2 (ADR-0009, T2.2); список семейств синхронизирован с primitives.css юнит-тестом |
| | `order/properties-order` | произвольный порядок свойств; `box-sizing` — сразу после токенов (ADR-0002) |
| `eslint.config.mjs` | `eqeqeq`, `no-implicit-globals`, recommended | `==`, глобальный scope (только `window.IraoUI.*`), ошибки; код компонентов — классический скрипт, tools — Node ESM, tests — jsdom |
| `prettier.config.mjs` + `.editorconfig` | — | разнобой стиля кода (проза `*.md` не форматируется) |
| `.htmlvalidate.js` | recommended + `wcag/h37`, `input-missing-label`, `irao/one-h1`, `irao/no-positive-tabindex` | невалидный HTML, img без alt, input без label, второй h1, `tabindex > 0` (§0, §5) |

Обязательства, которые линтер не увидит (исполняет ревью):

- **`/** @define <block> */` в начале CSS компонента** — без него файл
  выпадает из БЭМ-проверки сознательно (tokens/base/a11y/themes — не
  компоненты); забыли `@define` в компоненте — БЭМ-гейт молчит.
- Остаточные ограничения hex-гейта (исполняет ревью):
  - `color-mix()` и значения с `var()` внутри гейтятся «снаружи»: сырой цвет
    внутри `linear-gradient(var(--x), #fff)` или `color-mix(in srgb, var(--p), #fff)`
    regex не увидит — внутри функций цвета только из `var(--ui-*)`;
  - `box-shadow`/`text-shadow` проверяются по частям значения: тень — только
    целостный `var()`-токен (`box-shadow: var(--ui-shadow-md)`) либо `none`
    (легитимный сброс при active/hover); составные
    тени из сырых длин не проходят гейт сознательно — тени токенизированы
    (§3.2);
  - цветной кастом-проп — ровно один токен (значение сопоставляется целиком):
    составное значение оформляйте нецветным именем (`--ui-ring`, не
    `--ui-color-ring`) или переносите в слой токенов.
- HTML-паттерны — в стиле HTML5: void-элементы без слэша (`<meta>`, не
  `<meta />`) — `void-style` из recommended это и ловит.

### Как добавить негативную lint-фикстуру

1. Положите файл в `tests/lint-cases/` (для CSS-гейтов путь повторяет
   структуру репозитория: `css/components/...`, `css/tokens/primitives.css` —
   path-based исключения проверяются на тех же путях).
2. Добавьте строку-ожидание в `EXPECTATIONS` в `tools/run-lint-cases.mjs`:
   `{ file, tool, expect: 'fail', rules: [...] }` — с ожидаемым id правила
   (и severity, если оно warning), либо `expect: 'pass'` для позитивного
   контроля исключения.
3. `npm run test:lint` должен быть зелёным — это и есть тест конфигов.

## Граница «система / сайт» для контентных секций (итог EPIC-8)

Лендинг-секции (hero/holding/why-us и любые контентные блоки главной) —
**контентные, принадлежат сайтам**. Правило границы (спека T8.3, дока
[`patterns/landing-section/`](patterns/landing-section/README.md)):

> **Контент и уникальный дизайн секции — сайт; каркас (секция / сетка /
> типографика / карточки / кнопки) — система.**

- **Система даёт** готовый каркас без нового CSS: `ui-section`/`ui-container`/
  `ui-grid` (T3.4), роли типографики (T3.3), `ui-card`/`ui-tag`/`ui-button`/
  `ui-image` (EPIC-4), on-dark- и surface-пары токенов (контраст-гейт T2.3).
- **Сайт даёт** контент секции и уникальные декоративные приёмы (герой-блоки,
  коллажи, слайдеры, marquee) — связки в `template_styles.css`, значения —
  только токены `--ui-*`.
- **Не переносите** уникальный дизайн конкретных лендингов в `components/` —
  это зона сайтов (Out of scope EPIC-8). Если приём нужен нескольким сайтам —
  заявка на компонент/примитив (minor по бэклогу), а не правка паттерна.
- **Сайт-специфика не попадает в системные модули** (урок T7.3): компонент не
  знает классов, id и разметки конкретного сайта — связка только через
  `data-ui-*`-хуки (ADR-0005) и собственные модификаторы. Прецедент: ui-select
  не ссылается на обёртку `vacancy-search__select-wrap` фильтра career-portal —
  позиционный контекст и геометрия обёртки остались сайту, системная часть
  выразилась модификатором `data-ui-select="wrap"`. Нужна связка нескольким
  сайтам — заявка на компонент/модификатор (minor по бэклогу), а не зашивание
  класса сайта в `components/`.
- Сборка страниц — копипаста из паттернов `patterns/` («собери без нового
  CSS»): новые связки паттерна не попадают в dist (`<style>` стенда —
  showcase, не поставка; 02-architecture §7).

## Правила токенов (ADR-0009)

Три слоя; полный разбор с примерами — дока
[«Как пользоваться токенами»](docs/ui-system/architecture/tokens-usage.md):

| Слой | Файл | Кто читает |
|---|---|---|
| 1 — примитивы | `tokens/primitives.css` | только слой 2; единственное место системы с hex |
| 2 — семантика | `tokens/semantic.css` | компоненты, base, темы |
| 3 — компонентные (`--ui-<компонент>-*`) | объявляются в CSS компонента | сам компонент |

- Компонент читает **только слой 2** — ссылка на примитив из компонента
  ловится гейтом `irao/no-primitive-token-references`; иначе тема, меняющая
  семантику, компонент не перекрасит.
- **Новый семантический токен заводится только вместе с потребителем** —
  компонентом/base, читающим его в том же PR; токены «на вырост» не заводятся
  (анти-overengineering ADR-0009). Оформление: minor-версия, дефолт в `:root`
  `tokens/semantic.css`, комментарий происхождения, строка в таблице диффов
  [`tokens-career-portal-mapping.md`](docs/ui-system/architecture/tokens-career-portal-mapping.md).
  Новый **цветовой** токен — плюс пара или осознанное исключение в
  `tests/contrast/pairs.config.mjs` (иначе красный `npm run test:contrast`).
- **Слой 3 — по доказанной потребности**: компонентный токен заводится, только
  когда два сайта реально нуждаются в разных значениях (ADR-0009); по умолчанию
  значения берутся из слоя 2.
- Темы переопределяют **только слой 2** (гейт `irao/theme-semantic-overrides`),
  примитивы не трогают; значения одобренного дизайна career-portal не меняются
  (отклонение — design-decision владельца дизайна). Производные состояния без
  одобренного дизайна — `color-mix` над токеном слоя 2 (ADR-0010), не новые
  токены.

## Semver-триггеры (ADR-0007, 02-architecture §11)

API системы для интегратора — копируемые HTML-паттерны, классы `ui-*`, токены
`--ui-*`, data-атрибуты `data-ui-*`, JS-контракт `window.IraoUI.*`. Версия
определяется тем, что может сломаться у потребителя:

| Триггер | Версия | Примеры |
|---|---|---|
| Невидимое снаружи исправление | PATCH | фикс вычисления имени поля ui-select при label-обёртке (ревью T7.3) без изменения разметки, классов и data-атрибутов; правка доки, тестов, сборки |
| Новое без поломки существующего | MINOR | новый компонент (ui-badge); новый модификатор или `data-ui-*`-хук (`data-ui-select="wrap"`, T7.3); новый семантический токен с дефолтом в `:root` (`--ui-color-primary-hover`, T2.6); новый метод JS-модуля; deprecation-пометка с классом-алиасом и warning в dev-сборке |
| Ломает существующего потребителя | MAJOR | переименование/удаление класса (`ui-btn--primary` → …), токена, data-атрибута; **изменение канонического HTML компонента**; смена имени модуля в `window.IraoUI` |

Правило ревью: **любое изменение канонического HTML компонента — только через
major либо добавлением нового модификатора** (02-architecture §11): интеграторы
копируют разметку по докам, переименование класса = сломанный прод. Цикл
deprecation: пометка в minor → алиас с warning в dev-сборке → удаление в major
с migration guide. Каждое изменение — запись в CHANGELOG (Keep a Changelog,
T12.2) и в changelog-секцию доки компонента (шаблон T10.1, пункт 8).

## ADR-процесс

Журнал — [`docs/adr/`](docs/adr/) (прецеденты 0001–0012, реестр —
[`docs/ui-system/architecture/README.md`](docs/ui-system/architecture/README.md)).
ADR фиксирует решение в момент принятия и не переписывается задним числом:
изменение подхода — новый ADR, старый остаётся историей.

**Когда ADR обязателен:**

- итог **SPIKE** — проверенная гипотеза превращается в решение (ADR-0011 из
  SPIKE T7.1);
- **смена/отмена принятого подхода** (ADR-0003 → ADR-0004);
- **исключение из действующего правила** — своего инварианта каскада, гейта
  или конвенции (ADR-0001 — исключение из «стилизуем только классы»);
  исключение, уже требующее ADR по тексту правила (например, нешкальный
  `min-width`), оформляется так же.

**Формат** (по факту существующих файлов журнала): файл
`docs/adr/NNNN-kebab-name.md`, шапка `# ADR-NNNN: <название решения>` и три
буллета метаданных — **Дата**, **Статус** (`принято (источник: 02-architecture
§N / задача TX.Y / SPIKE)` или `заменено ADR-XXXX`), **Влияет на** (разделы
архитектуры, задачи, компоненты). Секции:

| Секция | Что содержит | По факту в журнале |
|---|---|---|
| Контекст / Context | проблема и ограничения, почему решение нужно сейчас | все ADR |
| Решение / Decision | что решили, вплоть до ключевых селекторов/правил | все ADR |
| Альтернативы / Alternatives considered | что отвергли и почему | 0003, 0005–0011 |
| Why | суть выгоды одной мыслью | 0005–0011 |
| Последствия / Consequences | плюсы, цена/минусы | все ADR |
| Проверка | чем решение закреплено: юнит-пин, e2e, гейт линтера | 0001–0004 (отдельная секция), 0012 (внутри Последствий) |

Первые ADR (0001–0004) писались с русскими заголовками секций, далее — с
английскими; содержательный состав одинаков, новый ADR допустим в любом из
двух стилей, но внутри одного файла — последовательно. Обязательный состав —
контекст, решение, последствия; **Проверка** обязательна для решений,
закрепляемых кодом или тестами (юнит-пин/e2e/гейт); альтернативы и Why —
когда были рассмотренные варианты.

**Нумерация:** сквозная четырёхзначная, следующий номер = последний в журнале
+ 1 (сейчас 0012 → 0013), без дыр и повторов; имя файла — `NNNN-kebab-case.md`.

**Supersede** (прецедент 0003 → 0004): текст старого ADR не переписывается;
в его шапке статус меняется на «заменено ADR-XXXX» с датой, причиной и ссылкой
на файл нового ADR, а новый получает статус «принято (заменяет ADR-YYYY)» со
ссылкой на старый — ссылки в обе стороны; статус в реестре
`architecture/README.md` обновляется.

**Индексация:** строка в реестре
[`docs/ui-system/architecture/README.md`](docs/ui-system/architecture/README.md)
— в том же PR, что и файл ADR.

## Как добавить компонент

1. Создайте папку `components/ui-<name>/` — одна папка = один компонент
   (нейминг: существительное в единственном числе, kebab-case).
2. `ui-<name>.html` — канонический HTML-паттерн. Это источник правды: из него
   живёт документация, стенд и тесты. JS-хуки — только `data-ui-*` (ADR-0005).
3. `ui-<name>.css` — первой строкой `/** @define <name> */` (без префикса
   `ui-`: его добавит гейт; без этой строки файл выпадает из БЭМ-проверки),
   дальше БЭМ с namespace `ui-`, специфичность одного класса, состояния
   `is-*`; только токены `--ui-*`; `box-sizing: border-box` на корневом
   селекторе (ADR-0002); mobile-first.
4. Если нужна логика — `ui-<name>.js` по шаблону
   [`docs/templates/module-template.js`](docs/templates/module-template.js):
   замените три места «НАСТРОЙКА», контракт — ниже.
5. Добавьте имя компонента одной строкой в `COMPONENTS` в
   [`showcase/build.mjs`](showcase/build.mjs) — без него CSS не попадёт в
   `dist/ui-core.min.css` (сборка предупредит; JS `ui-<name>.js` подключается
   автоматически).
6. `README.md` компонента: API (классы, модификаторы, токены, data-атрибуты),
   состояния, a11y (клавиатура, ARIA), do/don't.
7. Базовый стенд генерируется автоматически из `ui-<name>.html`. Расширенный
   стенд — живые примеры всех состояний на 375/768/1440 — положите в
   `showcase/pages/<name>/index.html`: он заменит базовый (showcase/README.md).
8. Тесты: e2e-сценарий поведения и axe-проверка, привязанные к стенду —
   шаблон компонентного теста: `tests/README.md` (харнесс T1.4: `stand`,
   `a11y`, `shot`).

## Чек-лист ревью компонента (эталон — T4.2, ui-button)

Каждая компонентная задача проходит полный цикл; эталонный пример —
`components/ui-button/` (T4.2). Исполнимая страница: пройдите пункты,
отмечайте галочки в PR-описании. Прежде чем выставлять PR на приёмку:

- [ ] **Тесты first** (TDD): юнит-пин исполняемой формы решения
  (`tests/unit/<name>.test.js`) и e2e-сценарии (`tests/e2e/<name>.spec.js`)
  написаны ДО реализации и падают (красный шаг зафиксирован коммитом).
- [ ] **Папка `components/ui-<name>/`**: `ui-<name>.css` (первая строка
  `/** @define <name> */`, box-sizing на корне — ADR-0002, только токены
  слоя 2, без `!important`/hex, `:hover` только под `@media (hover: hover)`);
  `ui-<name>.html` — канонический паттерн; `README.md` — API, состояния,
  a11y, do/don't, известные границы.
- [ ] **Токены** (§ «Правила токенов»): значения — из слоя 2; новый смысловой
  токен — с потребителем в том же PR и minor-версией (дефолт в `:root`,
  комментарий происхождения, строка в таблице диффов
  `docs/ui-system/architecture/tokens-career-portal-mapping.md`); новый
  ЦВЕТОВОЙ токен получает пару или исключение в
  `tests/contrast/pairs.config.mjs` (иначе `npm run test:contrast` красный).
- [ ] **Подключение**: одна строка в `COMPONENTS` `showcase/build.mjs`.
- [ ] **Стенд**: `showcase/pages/<name>/index.html` — матрица
  варианты × размеры × состояния; `data-ui-check-layout` — только если стенд
  входит в `CHECK_STANDS` гейта масштабирования (пин — scaling.test.js).
- [ ] **e2e**: computed-стили состояний, поведение (клавиатура Tab/Enter/Space
  для интерактивных), axe на всём стенде (исключения — только списком
  `KNOWN_AXE_EXCEPTIONS` в спеке с обоснованием + таблица в
  `tests/README.md` при отключении правил харнесса), контраст сквозной
  с T2.3 (`tests/contrast/lib.mjs`), эталоны 375/768/1280/1440 —
  только из контейнера/CI (`npm run test:docker`, ADR-0003/0004).
- [ ] **Гейты**: `npm run lint` зелёный; новые html-validate/stylelint-правила —
  с негативной фикстурой в `tests/lint-cases/` + строка в `EXPECTATIONS`
  `tools/run-lint-cases.mjs` (`npm run test:lint` зелёный).
- [ ] **a11y-требования задачи** отмечены в AC файла задачи и исполнены
  (клавиатурный прогон, accessible name, контраст, семантика).
- [ ] **Версия и changelog**: триггер версии по § «Semver-триггеры»
  распознан; changelog-строка компонента и версия введения на док-странице
  обновлены.

## Чек-лист «страница = шаблон» (эталон — T10.1, для T10.2 и ревью)

Каждый компонент dist имеет док-страницу `showcase/dist/docs/<имя>.html`,
собираемую генератором [`showcase/docs-template.mjs`](showcase/docs-template.mjs)
из файлов компонента (02-architecture §8). Чтобы добавить страницу компоненту:

1. Опишите в `components/ui-<name>/README.md` полный состав доки (API,
   состояния, клавиатура и a11y, do/don't, Bitrix-заметки, границы) — секции
   страницы рендерятся из его «## заголовков».
2. Положите метаданные `showcase/docs/<name>.mjs`: карта «секция шаблона →
   ## заголовок README» + клавиатурная таблица, ARIA-список, чек-лист
   скринридера (по протоколу T9.2), schema-заметка (`null` = н/п осознанно),
   версия введения и changelog. Эталонные примеры — `ui-button`, `ui-field`,
   `ui-modal` (T10.1).
3. `npm run build` — страница появится в `showcase/dist/docs/` и в индексе.

Чек-лист страницы (по нему идёт ревью и прогон T10.2; пункты 1–4 машина
проверяет сама — selfChecks сборки «диф на билде», юнит-пины
`tests/unit/docs-template.test.js`, e2e `tests/e2e/docs-template.spec.js`):

1. **9 секций шаблона по порядку**: живые примеры → HTML-сниппет → состояния →
   responsive-стенд (375/768/1440) → a11y → API → do/don't → schema →
   версия/changelog.
2. **Сниппет = разметка стенда**: сниппет и живые примеры — одна строка
   канонического `components/<name>/<name>.html`; расхождение уронит сборку
   (дока не отстаёт от кода — риск EPIC-10).
3. **Responsive — реальные iframe-вьюпорты** (не картинки): стенд компонента в
   ширинах 375/768/1440; прокручиваемые фреймы доступны с клавиатуры.
4. **A11y-секция непуста**: клавиатурная таблица + ARIA-атрибуты + чек-лист
   скринридера (протокол T9.2, релизный гейт T12.1).
5. **Тексты секций — из README компонента** (один источник): не дублируйте
   формулировки в метаданных, правьте README.
6. **Do / Don't с примерами**, «плохая» разметка — статический пример
   (подсветка `ui-docs-dont`, код не исполняется).
7. **Schema-заметка**: если компонент несёт микроразметку — описание правил;
   иначе осознанное «н/п» (секция не удаляется).
8. **Версия введения и changelog компонента** (semver: изменения канонического
   HTML/классов — только major, 02-architecture §11).
9. **Индекс и связи**: страница есть в каталоге `showcase/dist/index.html`,
   ведёт на стенд и обратно.

## Контракт JS-модуля (эталонный Vitest-тест — `tests/unit/module-template.test.js`, T1.6)

Каждый модуль компонента обязан соответствовать; шаблон уже соответствует,
сценарии проверены фактически при T1.1 (node-симуляция window/document),
физический Vitest-тест контракта — `tests/unit/module-template.test.js`
(T1.6), гейт — `npm run test:unit`:

1. **readyState-guard в обоих режимах:** при `readyState = 'loading'` init
   откладывается ровно одной подпиской на `DOMContentLoaded`; при `'complete'` /
   `'interactive'` (Bitrix `addJs(..., true)` кладёт скрипт в конец страницы)
   — вызывается синхронно, без подписки.
2. **Регистрация в `window.IraoUI`** под именем модуля — сразу, включая режим
   отложенной инициализации.
3. **Guard отсутствия элементов:** нет корневых элементов — тихий выход, без ошибок.
4. **try/catch вокруг инициализации инстансов:** ошибка одного инстанса уходит в
   `console.warn` и не мешает остальным инстансам и регистрации.
5. **Повторная инициализация запрещена:** повторный `init()` не создаёт дублей.
6. **Флаг инициализации — data-атрибут, не dataset:** `data-ui-<name>-init` через
   `setAttribute/getAttribute/removeAttribute`. Имена модулей пишутся в kebab-case
   (конвенция «Как добавить компонент»), а свойства `dataset` (DOMStringMap) дефисов
   не допускают: запись `dataset['uiSkip-linkInit']` бросает SyntaxError, которая
   ловится catch'ем как «ошибка инстанса», при этом слушатель уже навешан — повторный
   `init()` вешает дубли. Эталонный тест T1.6 обязательно включает кейс дефисного имени.
