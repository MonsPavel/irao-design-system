## Найденное и решения (Implementation requirements п.2: нарушение → фикс или исключение)

1. **Теряют границу в forced-colors кастомные слои ui-select** (триггер с
   `border: 0`; список на `--ui-shadow-lg`, которую режим не рисует; фоны
   Canvas сливаются со страницей). Нативные `button`/`input`/`select` и
   `ui-card` UA дорисовывает сам (зонд computed-стилей: у триггера/списка
   `border: 0/none`, у ghost-кнопки `2px solid`, у input `1px solid`,
   у карточки `1px solid`). **Фикс**: `@media (forced-colors: active)` в
   `components/ui-select/ui-select.css` — граница
   `var(--ui-border-width) solid currentColor` (системный цвет текста в
   любой теме ОС; ширина — токен; `box-sizing: border-box` базы — габариты
   не меняются). Гейт — `tests/e2e/forced-colors.spec.js` (писался до правок).
2. **Белая подпись на hover accent — 2.91:1** (< 3:1 чек-листа T9.2;
   hover ухудшает против базовых 3.12:1). Значение одобренного дизайна
   `#f37131` (career-portal components.css:83, ADR-0010 п.2/п.6) — **не
   меняется** (инвариант «значения одобренного дизайна не менять»); путь
   исправления сайтами — переопределение пары `--ui-color-accent-hover` в
   теме (граница ADR-0010 п.3). Исключение — `tests/contrast/derived.config.mjs`
   (`btn-accent-hover`); на design-decision владельца.
3. **Hover крошек accent на белом — 3.12:1** при тексте 14px (порог 4.5).
   Одобренный макет (.breadcrumbs a:hover, components.css:21) — исключение
   `breadcrumbs-hover`, изменение — design-decision владельца.
4. **Фокус на тёмных секциях не читается** — outline `--ui-focus-color`
   (primary #002856) на `surface-dark` 1.00:1 и на `primary-deep` 1.03:1
   (< 3:1). Ограничение принятой политики ADR-0001; в собственном полигоне
   разрыв не воспроизводится (в тёмном варианте landing-section интерактив
   живёт на светлых карточках), для сайтов — штатный рецепт: переопределение
   focus-тройки в контексте секции (документирован в
   `patterns/landing-section/README.md`, исключения `focus-on-dark` /
   `focus-on-primary-deep` в derived.config).
5. **Сквозной axe-обход не нашёл новых нарушений**: все узлы color-contrast
   за пределами реестра отсутствуют; в реестре `KNOWN_AXE_EXCEPTIONS`
   (`tests/helpers/harness.js`, таблица `tests/README.md`) — три известных
   узла стенда ui-button (accent 3.12:1 — одобренный дизайн; disabled —
   WCAG 1.4.3 исключает неактивные; loading — лейбл скрыт clip-path'ом).
6. **Пост-ревью: аффорданс ui-file исчезал в forced-colors** (замечание
   ревью ветки): коробка `.ui-file` держится на solid-фоне surface-muted
   (режим подменяет Canvas'ом), кнопка-лейбл — `<label>` без рамки, UA
   границу label не дорисовывает — «прикрепить файл» становился текстом,
   тождественным подсказке. Тот же класс дефекта, что п.1, но e2e его не
   видел: файлового поля не было на стенде ui-field, стенд ui-file не был
   включён в спеку. **Фикс**: `@media (forced-colors: active)` в
   `components/ui-file/ui-file.css` — граница `var(--ui-border-width) solid
   currentColor` на коробке поля и кнопке-лейбле; тест стенда ui-file в
   `tests/e2e/forced-colors.spec.js` (написан до правок, RED воспроизведён).
7. **Пост-ревью: гейт границы не ловил прозрачный border-color комма-формы**
   (замечание ревью ветки): `isOpaque('rgba(0, 0, 0, 0)')` возвращала true —
   парсер альфы не разбирал комма-форму rgba (единственную, которую Chromium
   реально выдаёт для computed border-color). Латентно (пробы стендов давали
   честные `rgb(0, 0, 0)`), но защита гейта не работала. **Фикс**: парсер
   вынесен в чистую функцию `isOpaqueColor` (`tests/helpers/forced-colors.js`)
   с поддержкой всех трёх форм сериализации (rgba комма-форма, rgb без
   альфы, слэш-форма) и юнит-пином `tests/unit/forced-colors.test.js`
   (негативный кейс ревью — `rgba(0, 0, 0, 0) → false`).

## Ограничения (честно)

- **Ручной протокол NVDA/VoiceOver не исполнялся**: у исполнителя-агента нет
  NVDA/VoiceOver, а автоматизация скринридеров — Out of scope спринта.
  Выполнено 100% подготовительной части: матрица зафиксирована, ожидания
  сформулированы как сравнимые последовательности объявлений и привязаны к
  пинам e2e (aria-контракт и клавиатурное поведение машинно покрыты).
  Подписание протокола (AC «заполнен на 100% и подписан») — за ручным
  прогоном по п. 2 документа; чек-лист прикладывается к T12.1.
- **AC не подтверждён приёмкой и не может быть закрыт агентом** (пост-приёмка
  T9.2): условие «заполнен и подписан» выполнит только живой исполнитель с
  NVDA (Windows) и VoiceOver (macOS/Safari). Чтобы статус был машинно
  проверяемым, добавлен гейт `node tests/a11y/protocol-gate.mjs`
  (юнит-пин логики — `tests/unit/protocol-gate.test.js`, 5/5): exit 0 —
  протокол заполнен и подписан (условие §6 протокола), exit 1 — ожидает
  ручного прогона (текущее состояние: 35 строк матрицы, 111 незаполненных
  ячеек), exit 2 — структурные ошибки. Релизный чек-лист T12.1 включает
  прогон гейта; закрывать T9.2/T12.1 с exit ≠ 0 нельзя.
- Пилотные страницы (T11.2) в финальный VI-прогон не входили — T11.2 в
  статусе todo (Scope: «если T11.2 готов»); при готовности пилотные страницы
  добавляются в `tests/helpers/stands.js` и входят в оба сквозных прогона
  автоматически.
- Ручная сверка forced-colors на Windows High Contrast (Technical
  considerations T9.2) — за ручным прогоном; e2e-эмуляция chromium зелёная.

## Решение владельца прогона (10.10.2026, пост-приёмка)

AC «Протокол NVDA/VoiceOver заполнен на 100% матрицы и подписан» перенесён
владельцем в **релизный гейт T12.1** (вариант «б»): AC требует живого
исполнителя с NVDA (Windows) и VoiceOver (macOS) — агенту недоступен по спеке
(ручной протокол, автоматизация скринридеров — Out of scope); матрица и
машинный гейт `tests/a11y/protocol-gate.mjs` подготовлены (exit 0 обязателен
до релиза), датированная пометка внесена в файл задачи T9.2 (## Notes).
Статус: **протокол ожидает ручного прогона владельца — это action item
владельца, не блокер мержа ветки**; остальные критерии приёмки закрываются
как обычно (зелёные).
