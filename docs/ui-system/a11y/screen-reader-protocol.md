# Протокол скринридеров NVDA / VoiceOver (T9.2 — повторяемый артефакт)

> Статус: матрица и ожидания зафиксированы на 100% (Implementation requirements
> T9.2 п.1); колонки «Факт» заполняются ручным прогоном — автоматизация
> скринридеров осознанно вне охвата (Out of scope T9.2). Прогон выполняет
> исполнитель с реальными ассистивными технологиями; артефакт прикладывается
> к релизному чек-листу T12.1 (Implementation requirements T9.2 п.3).

## 1. Что это и как читать

Спринт T9.2 закрывает разрыв между «axe = 0» и «реально удобно с ассистивными
технологиями»: axe-гейт (входит в каждый компонентный e2e, `tests/README.md`)
проверяет разметку, но не то, что скринридер реально объявляет пользователю.
Протокол — матрица «стенд × сценарий»: для каждого сценария заранее
зафиксирована **ожидаемая последовательность объявлений** (последовательности
сравнимы между запусками — Technical considerations T9.2), которую сверяют с
фактической озвучкой.

- **Ожидание** сформулировано семантически («имя, роль, состояние») и
  привязано к атрибуту канонической разметки — источник цитируется в графе
  «Пин». Дословные строки озвучки различаются между SR/версиями — исполнитель
  вписывает факт дословно, сверка идёт по семантике.
- **Пин (авто)** — e2e-сценарий, который уже пинит aria-контракт и/или
  клавиатурное поведение (`npm test`). Ручной прогон проверяет именно то, что
  автоматике недоступно: реальную озвучку, её полноту и порядок.
- **Статус** ячейки: `PASS` (объявления совпали семантически), `FAIL`
  (расхождение → п. «Расхождения»), `—` (ожидает прогона).

## 2. Окружение прогона (записывать фактические версии)

| Роль | Требование |
| --- | --- |
| SR №1 | NVDA (последняя стабильная), Windows 10/11, браузеры Chrome и Firefox |
| SR №2 | VoiceOver, macOS (версия записать), Safari |
| Полигон | `npm run build && npm run serve` → `http://127.0.0.1:8080/showcase/dist/stands/<стенд>.html` |
| Настройки NVDA | Синтез по умолчанию; «Схема озвучивания» — обычная; пунктуация — «некоторые» |
| Настройки VO | Утилита VoiceOver → Вербальность по умолчанию; курсор — клавиатурный режим (`VO` при вводе) |
| Фиксация | Экранная запись или журнал speech viewer NVDA; verbatim-строки вносятся в «Факт» |

Порядок: один стенд → все его сценарии → запись вердиктов. Найденное
расхождение не правится «на месте» — вносится в «Расхождения» (п. 5).

## 4. Критерии PASS/FAIL

`PASS` — семантическая последовательность совпала: имя/роль/состояние объявлены
в ожидаемом порядке; дословные формулировки SR («нажато», «кнопка, развернуто»)
могут отличаться. `FAIL` — пропущено существенное объявление (состояние, имя,
группа), объявлено лишнее мешающее (декоративный svg, «…»), порядок ломает
понимание, или фокус ушёл не туда.

## 5. Расхождения (заполняется по ходу прогона)
