# Адаптивный подход (mobile-first)

> Деливерабл задачи [T2.5 — Шкала брейкпоинтов и линтер mobile-first](../epics/EPIC-02-design-tokens/T2.5-breakpoint-scale.md).
> Источники: [02-architecture §3.2](../../02-architecture.md) (утверждённая шкала),
> гейт — [stylelint.config.mjs](../../../../stylelint.config.mjs) (правило 8).
> Дока описывает конвенцию; исполняет её линтер, синхронность —
> tests/unit/breakpoints.test.js.

Зачем: у career-portal семь «плавающих» брейкпоинтов (1439/1365/1279/1023/767/
479/359) — каждый компонент ломался на своей ширине, поведение системы не
согласовано. Media query нельзя выразить CSS-переменной, поэтому шкала — не
токены, а конвенция: константа в конфиге линтера + эта дока.

## Шкала брейкпоинтов

| Имя | min-width | Назначение |
| --- | --- | --- |
| `sm` | 480px | крупные телефоны, узкие карточные раскладки |
| `md` | 768px | планшет: рост типографики, паддинг контейнера 24 (T3.4) |
| `lg` | 1024px | узкий десктоп: паддинг контейнера 32, сетки 2/3 колонок |
| `xl` | 1280px | основной десктоп-макет career-portal |
| `2xl` | 1440px | широкие декоративные секции (наследие макета 1440) |

**Единственный источник значений — константа `BREAKPOINTS` в
[stylelint.config.mjs](../../../../stylelint.config.mjs)** (Implementation
requirements T2.5 п.1: «один источник: константы в конфиге, дока ссылается»).
Новый брейкпоинт — правка константы и этой таблицы одним PR; рассинхрон ловит
tests/unit/breakpoints.test.js.

Гейт (stylelint): viewport-фичи семейства ширины/высоты запрещены, кроме
`min-width`; значения `min-width` — только из шкалы (px). Негативные
фикстуры: tests/lint-cases/css/components/ui-card/media-*.css (2 красных),
позитив — ui-badge/media-scale.css (5 значений шкалы), прогон `npm run test:lint`.

## Mobile-first: база — мобильная

- Базовые стили компонента (без media) = мобильный вид; рост к sm/md/lg/xl/2xl —
  только в `@media (min-width: …)`. Это требование №1 ТЗ и база доступности:
  одноколоночный мобильный вид — естественный порядок чтения для скринридера
  и самый узкий дозволенный экран (320).
- `max-width`-запросы запрещены гейтом (`media-feature-name-disallowed-list`):
  desktop-first career-portal осознанно не переносится (класс C аудита).
  Перенос существующих значений — инверсия той же сетки: 767 → 768−1,
  1023 → 1024−1, 1439 → 1440−1 (брейкпоинт = «включительно от», а не «до»).
- Range-синтаксис (`width >= 768px`, `400px <= width`) гейт отклоняет по имени
  фичи — каноническая форма записи одна: `(min-width: Npx)`.
- px, не em/rem: фиксируем px сознательно (Technical considerations T2.5 —
  команда мала, дизайн-макеты в px; пересчёт zoom'ом браузера не требуется).

## Правило переломов — по контенту

1. Сначала без медиазапроса: `flex-wrap`, `auto-fit` + `minmax()`, токены
   размеров — большинство раскладок не требуют перелома вовсе.
2. Контент действительно ломается (строка не читается, карточка схлопывается) —
   берём ближайший **выше** пункт шкалы, а не «ширину конкретного устройства».
3. Один запрос — одно изменение поведения; значения шкалы — не магические
   числа, а согласованные точки, где синхронно растут сетка, типографика и
   контейнер.

## Критические вьюпорты для проверки

| Вьюпорт | Роль |
| --- | --- |
| 320 | smoke: нет горизонтального скролла (`scrollWidth === clientWidth`) — сценарий T3.4 |
| 375 | критический мобильный (визуальная приёмка, стенды компонентов) |
| 768 | `md`: перелом типографики и контейнера |
| 1440 | `2xl`/xl-граница: основной десктоп-макет career-portal |

Стенды компонентов расширенной приёмки — 375/768/1440 (CONTRIBUTING «Как
добавить компонент»); e2e-проверка overflow на 320/375/768/1024/1440 —
задача T3.4.

## Неширинные media-фичи — вне шкалы

`prefers-reduced-motion`, `prefers-contrast`, `forced-colors`, `hover`,
`pointer`, `print` — не брейкпоинты: значения не из шкалы, гейт их не
регулирует. Их применение — a11y-задачи (EPIC-9) и ревью.

## Исключения

Только через ADR: запись в [docs/adr/](../../adr/) с обоснованием (почему
шкала/`min-width` не покрывают случай) + `overrides` по путям в
stylelint.config.mjs — тот же механизм, что у исключений hex
(tokens/primitives.css) и `!important` (a11y/vi.css). Inline-отключение
гейта (`stylelint-disable`) исключением не считается — оно ловится ревью,
как и остальные обязательства вне линтера (CONTRIBUTING).

Container queries: требований нет; появятся — отдельный ADR (Out of scope
T2.5).
