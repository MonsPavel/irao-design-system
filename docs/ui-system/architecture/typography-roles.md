# Роли типографики: ui-h1…ui-micro

Задача T3.3. Типографическая шкала — API из классов ролей на тройках токенов
`--ui-fs-*` / `--ui-lh-*` / `--ui-fw-*` (T2.2, слой 2). Исполняемая форма —
`base/typography.css`; пин формы — `tests/unit/typography.test.js`; факт в
браузере — `tests/e2e/typography.spec.js`.

## Почему классы, а не теги

В шаблонах Bitrix заголовки выводятся **классами**, потому что теги стилизует
legacy-CSS сайта (`h1 { font-size: 28px }` в старом шаблоне побьёт тег-стиль
системы при любом порядке подключения). Специфичность одного класса (0-1-0)
выше тега (0-0-1) — класс роли гарантирует вид независимо от legacy-правил.

Семантику и иерархию при этом даёт **реальный тег**: класс — только вид.

```html
<!-- Семантика: тег по месту страницы (h1 → h2 → h3 без пропусков).
     Вид: класс роли (может не совпадать с уровнем тега). -->
<h1 class="ui-h1">Заголовок страницы</h1>
<section>
  <h2 class="ui-h2">Заголовок раздела</h2>
  <article>
    <h3 class="ui-h3">Заголовок карточки</h3>
  </article>
</section>

<!-- Легально: тег ниже уровнем, класс возвращает утверждённый вид
     (визуал ≠ семантика) -->
<h3 class="ui-small">Мелкий подзаголовок карточки</h3>
```

Иерархия тегов исполняется тремя гейтами: `irao/one-h1` (один h1),
`irao/heading-order` (без пропусков уровней: h1→h3 — ошибка) и e2e-обход всех
страниц showcase (перенос идеи `test_internship_headings.py` career-portal).

## Классы ролей

Каждый класс задаёт `font-size` / `line-height` / `font-weight` /
`letter-spacing` **целиком** (Implementation requirements T3.3 п.1) — роль не
собирается по частям. Размеры — rem-токены: mobile-first лестница живёт в
`tokens/semantic.css` (база — мобильные значения, рост 768/1024 — переопределением токенов), классы при этом не меняются и media-запросов не содержат.
letter-spacing: заголовочные роли −0.02em (перенос макета career-portal:
`page-title`, `section__title`; в em — масштабируется с ролью), текстовые —
normal.

| Класс | Роль | Когда использовать | Токены |
|---|---|---|---|
| `.ui-h1` | Заголовок страницы | главный заголовок материала (визуал для `h1`) | `--ui-fs/lh/fw-h1`, ls −0.02em |
| `.ui-h2` | Заголовок раздела | секции страницы (визуал для `h2`; в career-portal — `page-title`, `section__title`) | `--ui-fs/lh/fw-h2`, ls −0.02em |
| `.ui-h3` | Подзаголовок раздела | вложенные секции, заголовки карточек списков | `--ui-fs/lh/fw-h3`, ls −0.02em |
| `.ui-h4` | Заголовок карточки | мелкие смысловые блоки | `--ui-fs/lh/fw-h4`, ls −0.02em |
| `.ui-h5` | Заголовок блока | редкий уровень; в career-portal роли нет, размер = ступень lead | `--ui-fs/lh/fw-h5`, ls −0.02em |
| `.ui-h6` | Заголовок группы | редкий уровень; в career-portal роли нет, размер = ступень body | `--ui-fs/lh/fw-h6`, ls −0.02em |
| `.ui-lead` | Лид | вводный абзац под заголовком страницы | `--ui-fs/lh/fw-lead` |
| `.ui-body` | Основной текст | абзацы контентных областей (= дефолт `body`) | `--ui-fs/lh/fw-body` |
| `.ui-small` | Вторичный текст | подписи полей, сноски, строки списков | `--ui-fs/lh/fw-small` |
| `.ui-caption` | Подпись | подписи к иллюстрациям, даты | `--ui-fs/lh/fw-caption` |
| `.ui-micro` | Микротекст | служебные и юридические строки | `--ui-fs/lh/fw-micro` |
| `.ui-text--muted` | Вторичный цвет | модификатор к текстовой роли: цвет `--ui-color-text-muted` (AA-пара T2.3) | — |

## Body-дефолты страницы

`base/typography.css` задаёт `body`: шрифт/размер/веса/цвет/фон — из токенов
(`--ui-font-family`, тройка body, `--ui-color-text`, `--ui-color-surface`;
порт career-portal `css/base.css:60`) плюс `overflow-wrap: break-word` —
длинные RU-слова переносятся и не создают горизонтальный скролл, в том числе
при 32px-базе (требование №19 ТЗ; e2e-сценарий — 32px-тест T3.3).

Правило ADR-0002 остаётся в силе: **компоненты не зависят от element-стилей** —
base задаёт только разумный дефолт страницы; компонент обязан стилизовать текст
своими классами/токенами.

## Списки и адрес

- глобальный reset (T3.1) выключает маркеры у всех `ul`/`ol` — содержательный
  список возвращается классом `.ui-list` (работает на обоих тегах: `ul` —
  `disc`, `ol` — `decimal`); отступ слева `--ui-space-5`, ритм пунктов
  `--ui-space-2`;
- `.ui-address`-минимум: убирает браузерный курсив `address`. Маркетинговые
  «адресные» блоки (например `vacancy__address` career-portal) — тема
  компонентов (EPIC-4+), не base.

## Сознательные ограничения

- `text-wrap: pretty/balance` не используется: нет в матрице браузеров
  (Technical considerations T3.3); кандидат на minor-улучшение после
  расширения матрицы;
- утилит выравнивания/трансформации нет (ADR-0005, анти-utility-framework) —
  потребности «выровнять/перекрасить» закрываются токенами и классами ролей;
- контентная типографика статей (заголовки внутри длинных текстов,
  blockquote…) — EPIC-8, паттерн detail page.

## Как расширять

Новая роль (или изменение значений) — это изменение токенов T2.2 (minor, если
токен новый; major — при переименовании/удалении) + класс в
`base/typography.css` + строка в таблице выше + пины `tests/unit/typography.test.js`
(квадро fs/lh/fw/ls) и `tests/e2e/typography.spec.js` (computed из токена).
Список ролей фиксирован таблицей §3.2 архитектуры — новая роль требует записи
в ней (владелец системы).
