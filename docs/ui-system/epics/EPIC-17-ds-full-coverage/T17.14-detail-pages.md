# TASK T17.14 — Детальные страницы на ddp-канон

## Epic

[EPIC-17 — Полнота ДС: карьерный портал из компонентов](README.md)

## Priority

P2

## Type

TASK (паттерн-слой + adoption пилота)

## Goal

Перевести композиции детальных страниц пилота на ddp-канон паттерна
detail-page (T8.2): контентная колонка (head/tags/photo/секции),
специфичные блоки вакансии (salary 18px-литерал, place, foot, map),
статьи (meta-строка с точкой-типом, галерея 2fr/1fr, related) и
компании (hero 2кол, статы/преимущества на ui-stat T17.4, where,
banner на фото-секции+CTA T17.3/17.8). Снимает ~350 строк pilot.css
(cp-vacancy-page*, cp-detail-*, cp-article-page*, cp-company-*).

## Context

Detail-page паттерн описывает «крошки → page-head → контент +
sticky-aside → related» и уже принят пилотом наполовину (aside вакансии
— ui-form__layout, related-строки — lpp-row с T17.1). Остальное пилот
несёт в cp-классах: карточка-контейнер деталки, шапка-тройка, теги-строка,
фото 420px, контент-секции (pilot.css:1209–1317), article-специфика
(1319–1405), company-специфика (1710–1865). Все значения уже
откалиброваны раундами 2–4 (probe-пары salary/section-h2/aside-* —
MATCH) — перенос механический.

## Scope

- паттерн-слой: ddp-канон — `ddp` (колонка gap 32), `ddp__head`
  (тройка gap 8), `ddp__tags` (лента gap 8), `ddp__photo`
  (высота 420/260 по ступеням), `ddp__section` (gap 8), `ddp__foot`
  (разделитель+space-between);
- article-связки: `ddp__meta` (лента 12, элементы 28px высоты),
  `ddp__type` (точка 8px + uppercase 14/500 ls 0.02em), `ddp__gallery`
  (2fr/1fr), related (заголовки/шаги);
- company-связки: hero-2кол (400px/1fr, ступени), where-пары;
- пилот: cp-vacancy-page*/cp-detail-*/cp-article-*/cp-company-* →
  ddp + готовые компоненты (статы/баннер — после своих задач);
  зарплата — литерал 18px остаётся каноном ddp (`ddp__salary`,
  T16.13-mapping), НЕ ролью;
- карта (vacancy map-заглушка) — слот `ddp__media`, содержимое — сайт.

## Out of scope

- schema.org-разметка (JobPosting/Article) — уже в паттерне/пилоте,
  не меняется;
- контент секций — данные;
- лестницы 1023/767 cp-специфики, не покрытые каноном, — проверяются
  на соответствие ступеням канона (расхождения — решение в задаче:
  канон принимает значение оригинала).

## Existing implementation

## Implementation requirements

1. Канон забирает только композицию; типографика — ролями
   (salary-исключение — оговорка T16.13);
2. Значения «как есть» (420px фото, 56px шаги related, 40px отступы
   company) — с комментариями-источниками, прецедент pilot.css;
3. Пример канона (деталька события):

   ```html
   <div class="ddp">
     <div class="ddp__head">
       <h1 class="ui-page-title">День открытых дверей</h1>
       <div class="ddp__tags">
         <span class="ui-tag ui-tag--blue">Москва</span>
         <span class="ui-tag ui-tag--gray">очно</span>
       </div>
     </div>
     <img class="ddp__photo" src="event.jpg" alt="" loading="lazy">
     <section class="ddp__section">
       <h2 class="ui-h4">Программа</h2>
       <p class="ui-body">…</p>
     </section>
     …
   </div>
   ```
