# TASK T17.10 — Adoption таймлайна

## Epic

[EPIC-17 — Полнота ДС: карьерный портал из компонентов](README.md)

## Priority

P1

## Type

TASK (adoption пилота)

## Goal

Перевести таймлайны этапов пилота (internships/practices «Как попасть»,
education/career-track) с сайт-зонной копии `cp-timeline` на паттерн
`patterns/timeline` (T14.11) — самый дешёвый adoption эпика: канон уже
существует и, с паттерн-слоем, поставляется исполняемым CSS.

## Context

T14.11 доставил паттерн таймлайна (композиция «этапы процесса»: ol
нумерованных точек с заголовками/текстами, ряд от 1024, мобильная
колонка) — но пилот остался на собственной копии `cp-timeline`
(pilot.css:1493–1518: те же точки `--ui-control-size`, gap, ступени),
потому что паттерн — док без CSS. REPORT §4 фиксировал: «в пилоте —
сайт-зона cp-timeline (та же композиция)». С patтерн-слоем копия
становится бессмысленной.

## Scope

- при варианте A (T17.1): `tlp-*`-классы канона в паттерн-слое;
  разметка build.mjs (timeline-хелпер) — на классах канона; правило
  `cp-timeline*` удаляется из pilot.css;
- при варианте B: разметка копией канона 1:1 + машинный гейт пары
  «классы пилота == классы паттерна» в compare;
- сверка вида: точки primary, заголовки ui-h6 (T16.12), тексты
  ui-small muted — уже канон, изменений вида нет.

## Out of scope

- содержание этапов — данные страниц;
- вертикальный таймлайн — нет потребителя (доки-оговорка остаётся).

## Existing implementation

- patterns/timeline/timeline.html — канон (T14.11);
- pilot.css:1493–1518 (cp-timeline/cp-timeline__stage/__dot);
- build.mjs:498–508 (timeline-хелпер).

## Implementation requirements

1. Один класс-префикс на сущность: pilот использует канонические имена
   паттерна без переименований (урок cp-vac-row → lpp-row);
2. Пример канона:

   ```html
   <ol class="tlp">
     <li class="tlp__stage">
       <span class="tlp__dot">1</span>
       <h3 class="ui-h6">Заявка</h3>
       <p class="ui-small ui-text--muted">Заполни анкету…</p>
     </li>
     …
   </ol>
   ```

## Dependencies

- T17.1 (паттерн-слой) — жёстко: без носителя adoption бессмыслен
  (при варианте B — замена на гейт, задача не блокируется, меняется
  форма исполнения).
