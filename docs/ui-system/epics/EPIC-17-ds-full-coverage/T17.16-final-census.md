# TASK T17.16 — Закрывающая: ценз полноты и гейт

## Epic

[EPIC-17 — Полнота ДС: карьерный портал из компонентов](README.md)

## Priority

P1

## Type

TASK (закрывающая эпика: ценз + compare + правило)

## Goal

Зафиксировать итог эпика количественно: ценз сайт-зоны до/после
(строки pilot.css, число cp-блоков, JS пилота), свежий compare
20 страниц с расширенными пробами, правило «новые визуальные блоки —
только через ДС» в контрибьюторских доках, обновление REPORT/PLAN/
mapping.

## Context

Эпик меняет метрику полноты: вместо «оригинал vs клон» (раунды 1–5)
появляется «клон vs ДС» — доля портала, собираемая из поставки системы
без сайт-зонного CSS/JS. Базлайн раунда 5 (25.10): pilot.css 2022
строки / 228 селекторов / ~46 блоков; pilot.js 243 строки; блоки
классифицированы (README эпика, ценз п.1–3). Без гейта полнота
размоется первым же новым блоком — нужен явный стоп-правило.

## Scope

- ценз после: wc/селекторный подсчёт pilot.css/pilot.js; таблица
  «блок → судьба → задача» с фактическим исходом (снято/канон/
  осталось сайт-зоной с обоснованием);
- гейт: скрипт ценза в инструментарии пилота (по образцу probe-vac-
  rows.mjs): счётчик cp-селекторов и строк; порог фиксируется
  (например: новых cp-визуальных блоков нет, деградация строк —
  ошибка прогона); подключение — в запуск compare (до браузеров,
  как гейт ссылок T15.9);
- правило в CONTRIBUTING.md (раздел пилота): новый визуальный блок
  клона = задача ДС (компонент/паттерн-слой/токен) — сайт-зона только
  ритм/тон-строки/контент-композиции из ценза п.3;
- свежий compare: 20 страниц × 2, probe-набор расширяется парами
  «блок на каноне» (lpp-row/ddp__head/hro__search/ftp__link — по
  факту исполнения), viewer.html;
- REPORT: §11 дополнен итогом; PLAN §P2 переписан (лендинг-блоки —
  не «по мере вторых потребителей», а «полнота по career-portal»);
- mapping (tokens-career-portal-mapping.md): строки новых сущностей
  (ui-stat/ui-card--media/--cta/--photo/nvp/ddp/hro и др.).

## Implementation requirements

1. Порог ценза — явный числом в скрипте и REPORT (не «меньше»,
   а конкретное значение по факту итога; деградация — exit 1);
2. probe-пары новых канонов — в том же стиле (первое вхождение,
   короткие поля), null-симы для страниц без сущности;
3. Пример вывода ценза:

   ```text
   ценз сайт-зоны: pilot.css 598 строк (−70%), cp-блоков 17 (−29),
   JS пилота 78 строк (карусель/галерея — в dist)
   гейт: новых cp-визуальных блоков 0 — OK
   ```
