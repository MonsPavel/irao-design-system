# TASK T17.1 — Паттерн-слой ui-patterns.css в dist

## Epic

[EPIC-17 — Полнота ДС: карьерный портал из компонентов](README.md)

## Priority

P0

## Type

TASK (инфраструктура ДС; решение владельца ПРИНЯТО — вариант A, 25.10)

## Goal

Поставлять канонические связки паттернов страниц опциональным CSS-файлом
`dist/ui-patterns.css` (классы `lpp-*` list-page, `ddp-*` detail-page,
`fpp-*` form-page — те же имена, что в док-паттернах), чтобы сайты
группы перестали копировать связки руками, а пилот снял дубликаты
`cp-vac-row`/`cp-vac-side`/`cp-page-head`/`cp-breadcrumbs`/`cp-find-bar`.

## Context

Паттерны ДС — доки без кода в dist (02-architecture §7: «patterns/ —
доки-паттерны без кода»). Канон живёт в HTML-файлах паттернов; пилот
копировал связки под `cp-`-именами — и копипаста дрейфовала: строка
вакансии ушла от канона (паддинг 16px против 24/28, ui-link вместо
plain-ссылки — чинено T16.5), сайдбарная колонка 320px против 280px
оригинала (раунд 5, REPORT §11). Владелец изменил критерий полноты
(цитата — README эпика): блоки должны жить в ДС, а не в скрипте клона.

**Решение принято владельцем 25.10 — вариант A (паттерн-слой в dist).**
Вариант B (копипаста + гейт «связки пилота == канон паттерна») отклонён.

## Scope

- решение владельца A/B, фиксация в 02-architecture §7 (оговорка) и
  patterns/README.md («слой = связки, которых нет в компонентах»);
- `patterns.css` (единый исходник слоя: list/detail/form-связки) в сборке
  showcase/build.mjs → `dist/ui-patterns.css` (минифицированный,
  с баннером версии, как ui-core);
- перенос канонов из док-HTML паттернов в слой — имена/значения 1:1
  с list-page.html/detail-page.html/form-page.html (доки остаются
  источником правды, в их HTML — те же классы);
- пилот подключает `dist/ui-patterns.css` (build.mjs копирует в dist/ds/)
  и переключает строки/сайдбар вакансий на `lpp-*` (разметка build.mjs);
  `cp-vac-row*`, `cp-vac-layout`, `cp-vac-side*`, `cp-page-head*`,
  `cp-breadcrumbs`, `cp-find-bar` — удаляются из pilot.css по мере
  перевода соответствующих страниц (полное снятие — в adoption-задачах);
- калибровка сайдбар-колонки канона: 280px оригинала (17.5rem «как есть»,
  прецедент rem-колонки list-page) против текущих 320px в пилоте —
  значение канона, не пилота.

## Out of scope

- компонентные стили (кнопки/карточки/поля — из ui-core, слой их не
  дублирует; stylelint-гейт: селекторы слоя — только `lpp-*|ddp-*|fpp-*`);
- лендинг-связки (hero, marquee, nav-карточки) — отдельные задачи эпика,
  в слой добавляются ими;
-.Bitrix-снippets подключения слоя — док-строка в quickstart (T10.3),
  если слой принят.

## Existing implementation

- patterns/list-page/list-page.html:105–148 (lpp-layout/lpp-side/lpp-row),
  detail-page.html, form-page.html — каноны;
- pilot.css:939–1206 (cp-breadcrumbs/cp-page-head/cp-vac-layout/
  cp-vac-side/cp-find-bar), 1063–1134 (cp-vac-row) — дубликаты;
- showcase/build.mjs — сборка dist (конкатенация+минификация).

## Implementation requirements

1. Слой подключается опционально: `ui-core.min.css` не меняется;
   порядок в `<head>`: токены → core → patterns → сайт;
2. Селекторы слоя — только канонические префиксы `lpp-|ddp-|fpp-`
   (stylelint-правило/проверка в сборке — защита от превращения слоя
   в свалку);
3. Значения — из док-паттернов 1:1 (включая «как есть»-литералы с
   комментариями-источниками, прецедент pilot.css);
4. Слой не содержит `@media`-ступеней, кроме канонических ступеней
   паттернов (mobile-first ДС; лестницы пилота 1023/767 не переносятся —
   ступени канона уже mobile-first);
5. Пример канона (строка списка, из list-page.html):

   ```html
   <article class="ui-card ui-card--hover lpp-row">
     <div class="lpp-row__main">
       <h2 class="ui-h6 lpp-row__title"><a href="…">Заголовок строки</a></h2>
       <p class="ui-small ui-text--muted lpp-row__short">Описание</p>
     </div>
     <button class="ui-button ui-button--pill" type="button">
       <span class="ui-button__label">откликнуться</span>
     </button>
   </article>
   ```
