# TASK T17.13 — Каркасы шапки и подвала в паттерн-слое

## Epic

[EPIC-17 — Полнота ДС: карьерный портал из компонентов](README.md)

## Priority

P2

## Type

TASK (паттерн-слой + adoption пилота)

## Goal

Перенести каркасные связки шапки (`hsp-*`: сетка 1fr-auto-1fr, меню,
режимы absolute/static) и подвала (`ftp-*`: 4-колоночный каркас,
колонка ссылок, контакты-address, правая колонка) в паттерн-слой —
паттерны header/footer (T7.6) получают исполняемый CSS; пилот снимает
самые объёмные дубликаты сайт-зоны (`.cp-header*` 11 селекторов,
`.cp-footer*` 14). Заодно закрывается бэклог-кандидат «соц-кнопки
подвала по оригиналу» (36px blue-50 r12 hover primary).

## Context

Шапка/футер клона откалиброваны до computed-матча (T16.3/T16.4: пробы
header-link/dropdown-item/footer-link MATCH 14/14) — но вся композиция
живёт в pilot.css. Паттерны header/footer ДС — доки с другой
композицией (on-dark футер, иное меню). Слой даёт каркас: сетки,
режимы, ритмы; бренд-специфика (hover-accent футера, VI-пилюля 15px,
logo-размеры) остаётся сайт-зоной тонкими строками — это и есть
«зона сайта» в чистом виде (02-architecture §7).

Соц-кнопки: остаток §8.3 REPORT («on-dark-стиль на белом не видны —
кандидат бэклога: 36px blue-50, r12, hover primary, footer.css:93-108»)
— решается парой `--round`-кнопки (T17.9) на токенах.

## Scope

- паттерн-слой:
  - `hsp` — шапка: `hsp__inner` (grid 1fr auto 1fr, паддинги 16/8),
    `hsp__menu(--left/--right)` (flex, gap 16, nowrap-пункты),
    режимы `hsp--overlay` (absolute, z-40) / базовый static
    (border-bottom muted), `hsp__logo`;
  - `ftp` — подвал: `ftp__inner` (grid auto 2fr 2fr 1fr, gap 40,
    паддинги 48), `ftp__links` (колонка 14/1.35, шаг 9px), `ftp__contact`
    (label/значение 14/500/1.35, шаг 4), `ftp__socials` (лента круглых
    36px), `ftp__right`, мобильные ступени (2 колонки → перенос);
- соц-кнопки: `.hsp/.ftp__social` на `ui-button--round` + токены
  blue-50/primary-hover (T17.9-модификатор; если T17.9 позже —
  временно локальное правило слоя, снимается её мерджем);
- пилот: cp-header*/cp-footer* → каркас + тонкие бренд-строки
  (hover-accent, VI-пилюля 0.9375rem, логотип-размеры, letter-spacing
  оговорка); соц-кнопки — по оригиналу (снимает остаток §8.3);
- паттерны header/footer (доки) — синхронизировать HTML с классами
  слоя (один источник правды), доку дополнить светлым вариантом футера.

## Out of scope

- VI-панель/панель настроек — компонент ui-vi, не каркас;
- мобильное бургер-меню — нет в оригинале (меню-право скрыто ≤767 —
  канон оригинала, остаётся ступенью каркаса);
- sticky-шапка — нет в оригинале.

  + ступени 767);

## Implementation requirements

1. Каркас НЕ несёт цветов текста/ссылок (кроме surface-пары основы):
   цвет ссылок, hover-accent, :visited-политика — сайт-зона
   (комментарии-источники сохраняются);
2. VI-пилюля — слот `hsp__action`: вид (15px, рамка primary,
   glass-light) — бренд-строка пилота; в доке — общий вид кнопки;
3. Пример канона (шапка):

   ```html
   <header class="hsp hsp--overlay">
     <div class="ui-container hsp__inner">
       <nav class="hsp__menu hsp__menu--left" aria-label="Основное меню">
         <a class="ui-link ui-link--nav" href="vacancies.html">Вакансии</a>
         <div class="ui-dropdown" data-ui-dropdown>…</div>
       </nav>
       <a class="hsp__logo" href="index.html" aria-label="…— на главную">
         <img src="logo.svg" alt="" width="105" height="100">
       </a>
       <nav class="hsp__menu hsp__menu--right" aria-label="Дополнительное меню">
         <button class="hsp__action" type="button" data-ui-vi-toggle>…</button>
       </nav>
     </div>
   </header>
   ```
