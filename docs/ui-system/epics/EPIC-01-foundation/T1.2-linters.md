# TASK T1.2 — Линтеры: stylelint (БЭМ + hex-гейт), eslint, prettier, html-validate

## Epic

[EPIC-1 — Foundation & Tooling](README.md)

## Priority

P0

## Type

TASK

## Goal

Заставить машину исполнять архитектурные правила 02-architecture: нейминг `ui-`, отсутствие hex вне `tokens/primitives.css`, `!important` только в `a11y/vi.css`, валидный/семантичный HTML паттернов, единый стиль кода.

## Context

Дисциплина «цвета только через токены» в career-portal держалась вручную — из-за этого в компонентах остались hex'ы (#D6D6D6, #B9C6DE). В системе на 5+ лет и 1–2 разработчиков ручная дисциплина деградирует; stylelint-гейты — главный механизм против (риск №5 из 05-mvp-risks).

## Scope

- stylelint: селектор-паттерн БЭМ `ui-{block}__{elem}--{mod}`; `declaration-strict-value` для color-свойств (разрешены `var(...)`, `inherit`, `currentColor`, `transparent`); запрет `!important` вне `a11y/vi.css` (по путям); порядок свойств; запрет `outline: none` без замены (warning→error после EPIC-4);
- eslint: env browser + jsdom (тесты), `eqeqeq`, запрет глобалов;
- prettier + editorconfig;
- html-validate: один h1, label для input, alt обязателен у img, запрет `tabindex > 0`.

## Out of scope

- media-query-правило брейкпоинтов (настраивается в T2.5 вместе со шкалой);
- контраст-скрипт (T2.3);
- прогон линтеров в CI (T1.5, здесь — локальные скрипты).

## Existing implementation

career-portal: линтеров нет вообще (Node отсутствует) — создаём с нуля.

## Implementation requirements

1. Каждый файл-нарушитель из AC ниже проверить реальным коммитом (демо-PR).
2. Правила снабдить комментариями «почему» со ссылками на раздел архитектуры/ADR.
3. `npm run lint` ≤ 10 сек на текущем (почти пустом) репо.

## Technical considerations

- `stylelint-selector-bem-pattern` с пресетом под `ui-`; проверка.pattern на элементы/модификаторы;
- hex-гейт: `declaration-strict-value` с `ignoreFiles: tokens/primitives.css`;
- eslint на нативном JS (TS отсутствует сознательно — 06 §7).

- [ ] img без alt и страница с двумя h1 валят html-validate;
