# TASK T1.1 — Скелет репозитория и шаблон JS-модуля

## Epic

[EPIC-1 — Foundation & Tooling](README.md)

## Priority

P0

## Type

TASK

## Goal

Создать структуру каталогов и конвенции репозитория irao-ui, при которых добавление каждого следующего компонента/токена не требует архитектурных решений.

## Context

Первая задача проекта. Структура утверждена архитектурой (02-architecture §7); JS-модули обязаны переживать позднюю загрузку в Bitrix (`addJs(..., true)` кладёт скрипт в конец страницы, DOMContentLoaded может уже произойти) — guard обязателен.

## Scope

- дерево каталогов: `tokens/`, `base/`, `components/`, `a11y/`, `patterns/`, `themes/`, `showcase/`, `bitrix/`, `docs/`, `tests/`;
- README в каждом каталоге (1–5 строк: назначение, что сюда можно/нельзя);
- шаблон JS-модуля + вкладка в CONTRIBUTING «Как добавить компонент» (черновик);
- `.gitignore`, `.editorconfig`, `package.json` (только devDependencies + скрипты-заглушки).

## Out of scope

- Конфиги линтеров (T1.2), сборка (T1.3), CI (T1.5);
- какой-либо production-код (кроме `docs/templates/module-template.js`).

## Existing implementation

career-portal: структура `src/blocks/<block>/{block.html,block.css,block.js}` (одна папка = один блок) и IIFE-модули с guard'ами `if (!root) return` — паттерн переносим. Отличие: у них нет единого неймспейса и readyState-guard.

## Implementation requirements

1. Каталоги строго по 02-architecture §7, имена совпадают буква в букву (на них завязаны сборка и линтеры).
2. `docs/templates/module-template.js`: IIFE + `'use strict'`, регистрация в `window.IraoUI`, init-функция, guard `document.readyState !== 'loading' ? init() : document.addEventListener('DOMContentLoaded', init)`, guard отсутствия элементов, try/catch вокруг инициализации инстансов.
3. `.gitignore`: node_modules, артефакты сборки кроме dist (решить: dist коммитим или собираем в CI — см. Open Questions).
4. `package.json` скрипты: `lint`, `test`, `test:unit`, `build`, `serve` (заглушки до T1.2–T1.4).

## Technical considerations

- Node LTS; версии пиннятся в package.json (важно для воспроизводимости контейнера — ADR-0004);
- никаких runtime-зависимостей — только devDependencies (ADR-0005).

## Dependencies
