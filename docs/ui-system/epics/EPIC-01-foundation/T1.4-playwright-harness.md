# TASK T1.4 — Playwright-харнесс: e2e + axe + скриншоты

## Epic

[EPIC-1 — Foundation & Tooling](README.md)

## Priority

P0

## Type

TASK

## Goal

Создать тестовую базу, на которой все компоненты EPIC-2…8 пишутся по TDD: фикстуры открытия стендов, axe-анализ, скриншот-хелперы, контейнерный прогон.

## Context

Visual-эталоны чувствительны к растеризации шрифтов ОС; решение ADR-0004: единый официальный Playwright-образ локально (`test:docker`) и в CI; CI-джоба `update-snapshots` — fallback; гейт advisory до v1.0. PR-матрица — chromium; firefox/webkit — nightly/release.

## Scope

- конфиг playwright: проект chromium (PR), матрица (nightly/release); baseURL на локальный serve;
- пин версии образа `mcr.microsoft.com/playwright:vX-jammy` в репо (рядом с версией playwright);
- `npm run test:docker` — прогон в контейнере (docker или podman; WSL2 на Windows);
- фикстура `stand(name)`: открыть стенд, networkidle;
- хелпер `a11y()`: `AxeBuilder().analyze()` с задокументированным списком отключённых нерелевантных правил;
- хелпер `shot(viewport)` (375/768/1440) с маскировкой таймеров/дат;
- первый сквозной тест: индекс showcase открывается, axe чист, эталон снят;
- README «Как писать тесты компонента».

## Out of scope

- CI-workflows (T1.5);
- сценарии конкретных компонентов;
- Docker-образ собственный (официальный Playwright).

## Existing implementation

career-portal: автотестов e2e нет (Python unittest по HTML + ручной design-qa с `.shots/`) — переносим идею «проверять фактический вывод», не код.

## Implementation requirements

1. Шаблон теста компонента в README: состояния → e2e-сценарии → axe → скриншоты; правило: эталоны создаются только из контейнера или CI-джобы.
2. Контрольная проверка (AC): эталон, созданный `test:docker` локально, бинарно совпадает с CI-эталоном того же стенда.
3. Список отключаемых axe-правил — обосновать каждое.

## Technical considerations

- ADR-0004, лицензионная оговорка: Docker Desktop в крупной компании платен; бесплатные пути — podman или docker-ce в WSL2; выбор инструмента за исполнителем, контракт один — тот же образ;
- скриншоты — `toHaveScreenshot` со стабильными именами `tests/**/__screenshots__/`.
