# TASK T5.4 — ui-form: раскладка, сводная ошибка, success

## Epic

[EPIC-5 — Forms](README.md)

## Priority

P0

## Type

TASK

## Goal

Форма как целое: адаптивная раскладка полей, required-легенда, сводная ошибка с ролями, success-состояние с фокус-менеджментом.

## Context

Источники: `.form-grid` (2 колонки → 1 на мобиле) и `.form-aside` (информационная колонка) из pages.css career-portal; success-свап из `js/forms.js` (скрытие body + показ success + scrollIntoView). Сводная ошибка — новое (обязана быть role="alert" и списком ссылок на поля).

## Scope

- `components/ui-form/`:
  - `ui-form` — контейнер; `ui-form-grid` (+`--wide` для полных ширинах) — 1 колонка mobile → 2 от md;
  - `ui-form__aside` — боковая колонка (2-колоночный лейаут на десктопе → стек на мобиле);
  - `ui-form__summary` — сводная ошибка: `role="alert"`, заголовок + список ссылок на id полей;
  - `ui-form__success` — блок успеха: заголовок, текст, CTA; фокус переводится на заголовок (tabindex="-1") после показа;
  - легенда обязательных полей (footnote с маркером `__req`);
- правила фокуса: при показе summary — фокус на него; при успехе — на success-заголовок (паттерны для T5.5/T5.6).

## Out of scope

- JS-логика переключения состояний (T5.5/T5.6);
- многошаговые формы/визард (нет требований).

## Existing implementation

career-portal `pages.css` `.form-grid`, `.form-aside*`, success-поведение `forms.js` — переносим раскладки в mobile-first, success — визуально, поведение в модуль.

## Implementation requirements

1. Раскладки из токенов spacing; grid с minmax(0,1fr).
2. Ссылки summary — реальные переходы фокуса на поля (href="#id" + фокус-скрипт в T5.5, поведение зафиксировать в доке).
3. `box-sizing` на корнях.

## Technical considerations

- summary появляется после попытки submit — живой пример role="alert" (немедленное объявление);
- success-паттерн должен работать и без JS (серверный рендер成功-страницы — вариант Bitrix).
