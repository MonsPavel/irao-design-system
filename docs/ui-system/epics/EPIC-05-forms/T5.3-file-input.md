## Goal

Стилизованный файловый инпут, доступный с клавиатуры и скринридера: исправление анти-паттерна career-portal (`display: none` на нативном input).

## Context

Аудит career-portal (§6): `.field__file input { display: none }` — стилизованная кнопка не замещает клавиатурный доступ. Правило системы: нативный контрол никогда не прячется display:none (фиксируется в stylelint-правиле/доке).

## Scope

- `components/ui-file/`: паттерн «кнопка-лейбл + визуально-скрытый input»: `label.ui-file__button` обёрнут вокруг input (или `for`); input — sr-only (клип, не display:none);
- состояние выбора: имя файла (+размер) в `ui-file__value` со статусом «выбран» (role="status" — озвучивание);
- accept-подсказка и ограничения (типы/размер) в `__hint`;
- сброс выбора (кнопка «убрать файл» — доступная);
- правило доки: запрет display:none/visibility:hidden на нативных контролах.

## Out of scope

- Мультизагрузка и drag&drop (нет требований; паттерн расширяется сайтом);
- прогресс загрузки (зона сайта).

## Existing implementation

career-portal `.field__file` — визуал кнопки переносим; способ скрытия input полностью заменяем.

## Implementation requirements

1. После клика по кнопке-лейблу activeElement = input (или фокус остаётся на label-кнопке с видимым индикатором — зафиксировать поведение и покрыть тестом).
2. Повторный выбор файла обновляет value; Escape в диалоге не ломает состояние.
3. Имя выбранного файла озвучивается (role="status" на контейнере значения).

## Technical considerations

- sr-only-паттерн (клип 1px) — стандартный; focus-visible на input рисует обводку вокруг label-кнопки (`:focus-visible + …` или `:has()`);
- `accept`-атрибут из паттерна career-portal (.doc,.docx,.pdf) — как пример в доке.
