# TASK T5.5 — IraoUI.form: клиентская валидация как progressive enhancement

## Epic

[EPIC-5 — Forms](README.md)

## Priority

P0

## Type

TASK

## Goal

Порт `js/forms.js` career-portal в системный модуль: валидация required/email/pattern/файл-размер с фокусом на первую ошибку — только как усиление нативной формы; без модуля форма полностью функциональна.

## Context

Принцип: сервер — источник истины; JS — UX. Ключевой трюк совместимости: атрибут `novalidate` ставит JS при инициализации — разметка остаётся нативно-валидной, без JS браузерная валидация работает. Контракт ошибок единый с сервером (T5.6): класс `ui-field--error` + aria-invalid + aria-describedby + текст в `ui-field__error`.

## Scope

- `components/ui-form/ui-form.js` → `IraoUI.form`:
  - активация: `form[data-ui-form]`; правила из нативных атрибутов (required, type=email, pattern, minlength) + опционально data-ui-validate;
  - логика валидации — чистые функции (unit-тестируемые): required, email (регэксп career-portal `/^[^\s@]+@[^\s@]+\.[^\s@]{2,}$/`), pattern, file-size (data-attr лимит);
  - поведение: ошибка на change/blur, снятие на input; submit: валидация всех видимых полей (скрытые ветки пропускаются — перенос поведения career-portal), блокировка, фокус на первую ошибку, заполнение summary (T5.4) ссылками;
  - события: `irao-ui:form-invalid` / `irao-ui:form-valid` (CustomEvent) для сайтов;
  - success-цикл — делегируется сайту/паттерну (модуль только пропускает submit).

## Out of scope

- Серверная отправка/AJAX (зона сайта);
- кастомные правила бизнес-логики (расширение через события/свой валидатор — точка расширения в доке).

## Existing implementation

career-portal `js/forms.js` — переносим модель целиком (класс B): required/email, снятие ошибок на input, фокус на первую ошибку, пропуск hidden-полей; рефакторинг: неймспейс IraoUI, чистые функции, novalidate-JS, aria-контракт, summary-связка.

## Implementation requirements

1. `novalidate` ставится ТОЛЬКО при инициализации модуля (e2e-проверка: в разметке его нет).
2. Сообщение об ошибке: текст по умолчанию для каждого типа правила (RU) + переопределение через data-атрибут; текст кладётся в существующий `ui-field__error` (создаётся при отсутствии).
3. Повторная отправка заблокирована на время валидного сабмита (кнопка is-loading — интеграция с T4.2 через data-атрибут).

## Technical considerations

- Модуль не знает о сервере: после submit страница перезагружается, сервер рендерит состояния по контракту T5.6;
- module-template из T1.1 (readyState-guard обязателен).
