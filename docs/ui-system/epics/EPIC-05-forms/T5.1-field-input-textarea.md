# TASK T5.1 — ui-field: input, textarea и обвязка label/hint/error

## Epic

[EPIC-5 — Forms](README.md)

## Priority

P0

## Type

TASK

## Goal

Основа всех контролов: обвязка `ui-field` (label/req/hint/error) и стилизованные input/textarea со всеми состояниями, доступными без JS.

## Context

Источник — `.field` из career-portal: flex-колонка, label 14/500, поле 52px с bg surface-muted и прозрачной рамкой, focus → белый фон + рамка primary, `--error` → рамка error + фон error-bg, текст ошибки fs-micro. Система добавляет: hint, связность aria, размеры, требование «масштаб шрифта не режет поле».

## Scope

- `components/ui-field/`:
  - структура: `ui-field > ui-field__label + control + ui-field__hint + ui-field__error`; модификаторы `--error`, `--required` (маркер `__req`), `--wide` (в grid);
  - `ui-field__input` — типы: text, email, tel, password, date, number (нативные атрибуты — в доке-паттерне);
  - `ui-field__textarea` — min-height, `resize: vertical`, авто-рост опционально;
  - состояния: default / focus-visible / error / disabled / readonly;
- правила связности: label `for`↔id; hint `aria-describedby`; error: `aria-invalid="true"` + `aria-describedby` на id ошибки; required-маркер не только цветом (текст «обязательное поле» для скринридера — паттерн в доке);
- placeholder ≠ label — правило доки.

## Out of scope

- select/checkbox/radio (T5.2), file (T5.3);
- JS-валидация (T5.5);
- кастомный список ошибок у нескольких полей (T5.4 — сводная).

## Existing implementation

career-portal `components.css` `.field*` — переносим визуальную систему (поведение focus с bg-сменой сохраняем как фирменный паттерн + глобальный focus-visible), hex → токены.

## Implementation requirements

1. Высота полей: min-height (не height) — переживает 32px-сценарий T3.6; textarea без фикс. высоты.
2. `box-sizing` на корне и контроле (ADR-0002).
3. Ошибка — визуал и aria в одном паттерне (копипаст из доки даёт доступный результат).
4. Иконки валидации (если вводятся) — декоративные, aria-hidden, смысл дублируется текстом ошибки.

## Technical considerations

- Focus-паттерн поля (bg+border) дополняет глобальный outline T3.2 — не заменяет;
- автозаполнение: не отключать (`autocomplete`-атрибуты — рекомендации в доке, WCAG 1.3.5).

## Accessibility requirements

- ошибка объявляется (текст в DOM, связан с полем);
- контраст ошибок ≥ 4.5:1 (сквозной с T2.3).
