# TASK T6.4 — ui-accordion (на `<details>/<summary>`)

## Epic

[EPIC-6 — Navigation & Interactive](README.md)

## Priority

P1

## Type

TASK

## Goal

Аккордеон, полностью работающий без JS (`<details>/<summary>`), с плавной анимацией высоты через grid-rows и вариантом FAQ.

## Context

career-portal: `.faq` — анимация `grid-template-rows: 0fr → 1fr` (техника класса A, без JS-измерений) + `faq.js` (toggle is-open). Семантика была div/button — система переходит на нативный `<details>`, который даёт Enter/Space, состояние и скринридер бесплатно.

## Scope

- `components/ui-accordion/`:
  - разметка: `ui-accordion` + N × (`details.ui-accordion__item > summary.ui-accordion__q + div.ui-accordion__a > .ui-accordion__a-inner`);
  - анимация: grid-rows-переход при `[open]` (с учётом того, что details раскрывается мгновенно — паттерн анимации через класс + `::details-content`/интерсект — реализацию выбрать и зафиксировать в доке);
  - вариант `--faq` (визуал career-portal: bg surface-muted, радиус card, иконка-шеврон с поворотом);
  - режим «один открыт» — опционально через data-атрибут (JS-усиление; без JS все независимы);
- reduced-motion: без анимации.

## Out of scope

- Деревья/вложенные аккордеоны (по потребности);
- динамическая загрузка контента при открытии (зона сайта).

## Existing implementation

career-portal `components.css` `.faq*` + `js/faq.js` — переносим визуал и технику анимации; управление заменяем на нативное.

## Implementation requirements

1. Без JS: open/close работает нативно (e2e).
2. Имя summary — текст вопроса; иконка aria-hidden.
3. Режим single-open — модуль-усиление по `data-ui-accordion="single"`.

## Technical considerations

- `<details>` + анимация: известная проблема мгновенного раскрытия — решение (interpolate-size / details-content animation или класс-обёртка) выбирается по матрице evergreen ×2 и фиксируется в доке; если ни одно не покрывает матрицу — анимация деградирует (раскрытие без плавности), контент не теряется;
- FAQ-вариант — канонический потребитель микроразметки FAQPage? Нет — schema.org FAQPage требует видимости вопросов/ответов; отметить в доке «когда уместно» (ТЗ №7).
