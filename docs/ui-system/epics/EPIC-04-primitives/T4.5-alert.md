# TASK T4.5 — ui-alert

## Epic

[EPIC-4 — Primitive Components](README.md)

## Priority

P0

## Type

TASK

## Goal

Статусные сообщения (инфо/успех/предупреждение/ошибка) с корректными live-ролями и закрываемым вариантом.

## Context

В career-portal статусы есть только как пары токенов (error/success + bg) и текст ошибок полей — отдельного компонента сообщений нет. Формы (T5.x) и списки (T8.1) нуждаются в едином визуальном и семантическом паттерне.

## Scope

- `components/ui-alert/`: варианты `--info / --success / --warning / --error` (bg+иконка+цвет из семантических пар);
- роли по критичности: `role="status"` (info/success — вежливое объявление) vs `role="alert"` (warning/error — немедленное) — правило выбора в доке;
- закрываемый вариант: `ui-alert__close` (кнопка с aria-label), скрытие — удаление или hidden + aria — фиксируется докой;
- стенд: 4 варианта × (статичный/закрываемый).

## Out of scope

- Toasts/стеки уведомлений (P2);
- alert-контейнеры с таймаут-скрытием (JS-модуль не нужен — статичный компонент).

## Existing implementation

career-portal: пары `--color-error/--color-error-bg`, `--color-success/--color-success-bg` — основа; info/warning-пары заводим в семантике (контраст-гейт).

## Implementation requirements

1. Иконка варианта — svg `aria-hidden`; смысл дублируется текстом (не только цветом — WCAG 1.4.1).
2. Закрытие: aria-live-регион не должен «терять» контент неожиданно — правило в доке (закрытие по явному действию пользователя допустимо).
3. Пары цветов проходят контраст-скрипт.

## Technical considerations

- `role` выставляется в HTML-паттерне (копирует интегратор), не JS;
- отступы — spacing-токены; радиус — `--ui-radius-md`.
