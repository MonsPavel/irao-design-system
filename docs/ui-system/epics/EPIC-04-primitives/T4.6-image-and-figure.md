# TASK T4.6 — ui-image / ui-figure: паттерн изображений

## Epic

[EPIC-4 — Primitive Components](README.md)

## Priority

P0

## Type

TASK

## Goal

Систематизировать изображения: правила alt/retina/размеров как enforceable-паттерн, компонент `ui-figure` с подписью, fallback-поведение при незагрузившемся файле, CLS = 0.

## Context

Аудит career-portal: width/height только на лого, lazy на карточных img, retina — только PNG @2x логотипы; системной политики нет. Требования ТЗ №11 (alt/a11y изображений), №12 (Retina), №20 (работа при отсутствующих изображениях). У career-portal `img { display:block; max-width:100% }` — уже в reset (T3.1).

## Scope

- `components/ui-figure/`: `ui-figure` (+`__caption` с корректной семантикой `figure/figcaption`), `ui-image`-модификаторы `--cover/--contain/--ratio` (aspect-ratio из шкалы);
- правила (html-validate + дока-чек-лист): alt обязателен (пустой — для декоративных); `width/height` или aspect-ratio обязательны (нет CLS); `loading="lazy"` для вне-first-screen;
- retina-политика: вектор для иконок; `srcset` 1x/2x для растра (примеры в доке для Bitrix: генерация из инфоблоков);
- complex images: длинное описание через `aria-describedby` (кейс в доке);
- fallback: сломанный src — деградация без разрушения сетки (стили + правило alt-текста).

## Out of scope

- `<picture>`/art-direction и AVIF/WebP-конверсия — инфраструктура контента сайтов, не системы (заметка в доке);
- lazy-loading JS-библиотеки (нативный loading достаточно).

## Existing implementation

career-portal: `loading="lazy"` на карточках, `alt=""` на декоративных фото, лого с width/height и осмысленным alt — хорошие привычки, переносим в правила; PNG-логотипы @2x — кейс для доки srcset.

## Implementation requirements

1. `ui-image--ratio` с `aspect-ratio` + `object-fit` — фиксация места под картинку без знания размеров файла.
2. Стенд: декоративное (alt=""), информативное (alt-текст), complex (aria-describedby) + сломанный src.
3. CLS-проверка стенда (layout-shift = 0 при lazy-загрузке) — e2e.

## Technical considerations

- Правила html-validate настраиваются в T1.2 — здесь используются, при необходимости донастраиваются;
- дока адресует контент-менеджеров Bitrix (как готовить картинки: форматы, вес, @2x).

## Dependencies

- [ ] Чек-лист «как готовить изображения» в доке (вкл. retina и Bitrix-контекст).

## Accessibility requirements

- подпись figure связана семантически;
- fallback не ломает доступ к соседнему контенту.
