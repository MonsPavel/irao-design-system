# TASK T4.8 — Empty state / Error state паттерны

## Epic

[EPIC-4 — Primitive Components](README.md)

## Priority

P0

## Type

TASK

## Goal

Эталонные разметки трёх «неудобных» состояний: пустой список, страница 404, ошибка загрузки — с правилами «что говорить пользователю».

## Context

В career-portal есть только 404.html (контентная страница сайта). Системе нужны переиспользуемые паттерны: списковые страницы (T8.1) требуют empty-state, надёжность (ТЗ №20) — error-состояния. Это паттерны: разметка + минимальный CSS + дока; тяжёлого компонента не делаем (анти-overengineering).

## Scope

- паттерн `ui-empty`: иконка/иллюстрация (декоративная), заголовок-роль, пояснение, CTA (ui-button/link по смыслу);
- паттерн `ui-error`: вариант inline (в секции) и полностраничный (404/500): h1, пояснение, действия (назад/на главную/повторить);
- дока: правила текстов (нет вины пользователя, есть следующее действие), когда retry-кнопка, когда просто ссылка;
- стенды всех трёх состояний.

## Out of scope

- JS-логика retry (контекст сайта);
- иллюстрации (сайты подставляют свои; система — только слот и правила).

## Existing implementation

career-portal `404.html` — как контентный референс тона текстов; кодовой базы для переноса нет.

## Implementation requirements

1. Паттерны собираются из существующих компонентов (типографика, button, link) — новый CSS минимален.
2. Заголовок пустого состояния — h2 (страница уже имеет h1); 404 — h1 (правило в доке + html-validate-сквозная проверка).
3. CTA обязательны: хотя бы одно действие из паттерна.

## Technical considerations

- Empty-state не должен ловить фокус программно (появляется в потоке);
- error-полностраничный включает крошки? Нет — только nav-минимум (дока).
