# TASK T4.2 — ui-button (эталонный компонент)

## Epic

[EPIC-4 — Primitive Components](README.md)

## Priority

P0

## Type

TASK

## Goal

Кнопка со всеми вариантами, размерами и состояниями — и одновременно эталон качества: на ней отрабатывается полный цикл (тесты-first → реализация → дока-шаблон → visual-матрица), который затем копируют все компоненты.

## Context

Источник — `.btn` из `components.css` career-portal: варианты primary/accent/outline/light, высота 52px, радиус pill, transition. Расширения системы: размеры (md/sm), состояния disabled и loading, hover через color-mix (T2.6), focus-visible.

## Scope

- `components/ui-button/`:
  - варианты: `ui-button--primary / --accent / --outline / --light`;
  - размеры: md (высота из `--ui-button-height`), sm;
  - состояния: default / hover / focus-visible / active / disabled / loading (`is-loading` + `aria-busy`, спиннер `aria-hidden`, повторные клики игнорируются);
  - слоты: `ui-button__icon` (svg, currentColor, aria-hidden), `ui-button__label`;
- семантика: `<button type="submit|button">` — тип обязательный (html-validate warning);
- правило do/don't: действие → button, переход → ui-link (в т.ч. `ui-link--button`);
- стенд: матрица варианты × размеры × состояния;
- CONTRIBUTING: чек-лист новой компоненты (заводится здесь, на эталоне).

## Out of scope

- Кнопки-иконки (icon-only) — если понадобятся, отдельным модификатором с обязательным aria-label (в доке);
- группы кнопок/тулбары (нет требований).

## Existing implementation

career-portal `components.css` `.btn*` — переносим визуальную систему (высоты, радиус, шрифтовые тройки), цвета — строго в токены; hover-пару (--color-blue-700 как hover primary) заменяет color-mix.

## Implementation requirements

1. Все значения из токенов; высоты через токен размера; `box-sizing` на корне (ADR-0002).
2. `disabled` — атрибут `disabled` (не фокусируется, не кликается нативно); визуал из токенов disabled.
3. `loading`: JS-независимый базовый класс + модуль-хелпер не требуется (кнопка в форме управляется T5.5); лейбл сохраняет accessible name при замене на спиннер.
4. hover/active — color-mix (T2.6) под `@media (hover: hover)`.

## Technical considerations

- Каскад: `.ui-button` один класс; модификаторы не создают специфичность выше одного класса;
- min-height вместо height на md (совместимость с 32px-сценарием T3.6).

## Acceptance Criteria

- [ ] Стенд-матрица полная; visual-эталоны всех комбинаций (CI/контейнер);
- [ ] e2e: disabled не фокусируется и не кликается; loading — `aria-busy="true"`, спиннер `aria-hidden`, accessible name неизменен, клики игнорируются;
- [ ] axe стенда без нарушений (включая контраст disabled — декоративный, зафиксировать исключение);
- [ ] клавиатурный прогон: Tab/Enter/Space;
- [ ] CONTRIBUTING-чек-лист компоненты создан на этом эталоне.

## Testing requirements

Tests first:
- e2e сценарии состояний (computed-стили + поведение loading/disabled);
- axe на стенде;
- visual-матрица.

## Accessibility requirements

- keyboard accessible (нативный button); visible focus (T3.2);
- disabled state — семантически корректен; correct semantic element (`<button>` с type);
- accessible name (текст лейбла или aria-label); sufficient contrast (все интерактивные варианты ≥ 4.5:1).
