# TASK T11.3 — Пилот B: интеграция (сайт с другой структурой)

## Epic

[EPIC-11 — Bitrix Integration](README.md)

## Priority

P1

## Type

TASK

## Goal

Доказать переиспользование на сайте с другой структурой: тот же dist без форка и правок `/local/ui/`, другой набор паттернов.

## Context

Phase 0: оба пилота в одном бренде — цель пилота B не темизация, а доказательство, что система не является скрытым «сайтом для career-portal». Кандидата определяет менеджер (критерий: другой тип структуры — например, корпоративный сайт с новостями/структурой/документами).

## Scope

- Подключение по quickstart (сниппеты T11.1) — без модификаций;
- перевод 2–3 страниц, непохожих на страницы пилота A (новостная лента, страница структуры, документ/таблица — по факту сайта: таблицы — хороший кейс T7.4);
- чек-листы страниц, журнал конфликтов (отдельный);
- сверка с пилотом A: список расхождений в потребностях → задачи в систему (не форк).

## Out of scope

- Полный перевод сайта;
- тема (один бренд).

## Existing implementation

Нет (новый сайт); паттерны EPIC-8 — строительный материал.

## Implementation requirements

1. Запрет форка: любое «не хватает» → задача в систему или локальный паттерн сайта (вне `/local/ui/`).
2. Различия паттернов фиксируются — это данные для развития системы (P2-очередь).

## Technical considerations

- Если сайт B ещё на старом UI — применить стадийную модель миграции (план 06 §6): достаточно Stage 1–2 для приёмки.

## Dependencies

- [T11.2 — Пилот A](T11.2-pilot-a.md)
- Решение менеджера по пилотам.

- [ ] Список расхождений/потребностей передан в бэклог системы.
