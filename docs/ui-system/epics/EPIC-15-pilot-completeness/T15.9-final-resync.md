# TASK T15.9 — Закрывающая: пересверка 20 страниц и гейт мёртвых ссылок

## Epic

[EPIC-15 — Пилот career-portal: полнота страниц и хвосты раунда 2](README.md)

## Priority

P1

## Type

TASK

## Goal

Финальная сверка эпика по образцу T14.12: compare-прогон на всех 20
страницах клона, машинный гейт «мёртвых внутренних ссылок» как
постоянная проверка пилота, обновление REPORT/PLAN по итогам всех
задач EPIC-15.

## Context

После T15.1–T15.6 в dist клона 20 страниц (12 текущих + event,
article, company, education-catalog, internship, internship-apply,
event-apply, events-search). T15.7/T15.8 меняют ДС — пилот пересобирается
на свежей поставке до сверки. Раунд 2 показал, что отсутствие страниц
не ловилось существующими проверками: compare гоняет фиксированный
список PAGES, ссылки dist никто не валидирует.

## Scope

- pilot/career-portal/compare.mjs: PAGES = все 20 страниц;
- гейт мёртвых ссылок: скрипт (в pilot/career-portal/ или tools/),
  который собирает dist, парсит все внутренние href (*.html) и падает,
  если цель не существует в dist; подключить в тот же запуск, что и
  compare (документировать в README пилота запуск);
- сравнение: свежий compare.json + viewer.html; анализ новых страниц —
  docHeight, probe-пары (уточнить селекторы проб под новые страницы),
  артефакты выборки помечать как в REPORT §2;
- axe-прогон новых страниц (по протоколу пробы vacancies — не CI-гейт);
- REPORT.md: итоговая секция после EPIC-15 — что закрыто (мёртвые
  ссылки 0, compact принят, label/on-photo статус), новые остатки если
  появились; PLAN.md — отметки выполнения;
- STATUS/эпик README: галочки AC/DoD эпика.

## Out of scope

- Новые DS-задачи по находкам — в BACKLOG.md по обычному правилу
  (не в этот эпик);
- Пересъём эталонов ДС (если T15.7/T15.8 уже сняли — не повторять).

## Existing implementation

compare.mjs (12 страниц), viewer.html, протокол пробы axe из T14.12
(46 passes vacancies + KNOWN_AXE_EXCEPTIONS).

## Implementation requirements

1. Гейт ссылок детерминированный: без сети (только файлы dist),
   игнорирует внешние URL/якоря/mailto/tel.
2. compare.json/generatedAt свежий; цифры в REPORT — из compare.json,
   не из памяти.
3. Оценка «расхождение = свойство ДС или сайт-зоны» — по методике
   REPORT §2/§3; новые систематики — кандидаты бэклога с приоритетом.

## Technical considerations

- 20 страниц × 2 версии ≈ 5 мин прогона — время compare вырастет,
  проверить таймауты запуска (документировать в README);
- пробы новых страниц: education-catalog повторит probes vacancies
  (select/pagination), apply-страницы — probes vacancy-apply, event/
  article/internship — probes vacancy (общий шаблон) — переиспользовать
  существующие пары, не множить.
