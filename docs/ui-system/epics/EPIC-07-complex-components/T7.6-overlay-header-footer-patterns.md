# TASK T7.6 — Паттерны: search overlay, header, footer

## Epic

[EPIC-7 — Complex Components](README.md)

## Priority

## Type

TASK

## Goal

Три документационных паттерна на базе готовых компонентов: полноэкранный поиск (на ui-modal), шапка, подвал — копируемая разметка для Bitrix-шаблонов, не dist-код.

## Context

Граница «компонент vs паттерн» (02 §4): шапки/подвалы сайтов слишком различаются, чтобы быть компонентами системы; но референс-разметка резко ускоряет интеграцию. Источники: `search-screen` career-portal (без диалоговой семантики — класс B), `header.html` (лендмарки, nav aria-label, кнопка VI, dropdown), `footer.html` (контакты, соцсети).

## Scope

- паттерн **search overlay**: полноэкранный диалог на базе ui-modal (T7.2): фокус в поле при открытии, Escape, restore, `aria-modal`; форма поиска — нативный GET (без JS работает как переход);
- паттерн **header**: референс-разметка: skip-link (T3.5) + `<header>` + nav-лендмарки + dropdown (T6.1) + логотип (T4.6) + кнопка VI (из T9.1) + поиск;
- паттерн **footer**: `<footer>` + колонки ссылок + контакты (address) + переход кверху;
- доки: правила ленмарк/заголовков, aria-label навигаций, где стилизиBIrix-меню (`bitrix:menu`).

## Out of scope

- CSS паттернов в dist (сайты стилизуют под себя; из системы — только компоненты внутри паттерна);
- конкретный дизайн шапки career-portal (бренд-специфика).

## Existing implementation

career-portal `src/blocks/search-screen/*`, `header.html`, `footer.html` — переносим структурные решения; визуал — зона сайта.

## Implementation requirements

1. Паттерны собираются строго из готовых ui-компонентов — новый CSS в паттернах минимален и живёт в showcase.
2. Search overlay проходит полный диалог-чек (как T7.2) — закрывает пробел аудита career-portal.
3. Каждый паттерн — страница showcase с копируемым HTML и Bitrix-заметками.

## Technical considerations

- Header-паттерн обязан включать место под VI-кнопку (T9.1) — согласование разметки заранее;
- footer: `address`-семантика для контактов.
