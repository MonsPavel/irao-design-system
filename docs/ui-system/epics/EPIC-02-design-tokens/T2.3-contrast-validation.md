# TASK T2.3 — Контраст-валидация AA (CI-скрипт)

## Epic

[EPIC-2 — Design Tokens](README.md)

## Priority

P0

## Type

TASK

## Goal

Инструментальное доказательство WCAG AA для всех смысловых цветовых пар дефолтной палитры; нарушение становится красным PR-гейтом до того, как попадёт в компоненты.

## Context

Требование AA: обычный текст ≥ 4.5:1, крупный (≥24px или ≥19px bold) ≥ 3:1, некстовые ≥ 3:1. Известный кандидат на исправление — muted-серый career-portal `#808080` на белом (≈3.54:1). Phase 0: один бренд → качество дефолтной палитры критично.

## Scope

- node-скрипт `tests/contrast/` : парсит `tokens/semantic.css`, по конфигу пар «использование → фон» (text/surface, text-muted/surface, on-dark/surface-primary, теги fg/bg, link/surface, error/surface, focus/поверхности) вычисляет контраст и сверяет с порогами;
- конфиг порогов с учётом «крупности» ролей;
- markdown-отчёт в артефакты CI; шаг в `ci.yml` (T1.5);
- правки значений, не проходящих порог (muted-серый затемнить до ≥4.5:1; проверить пары тегов из career-portal).

## Out of scope

- Контраст VI-тем (гарантированные пары ГОСТ — модуль vi, проверка в T9.1);
- проверка фактических компонентов (пар достаточно — компоненты читают только семантику, ADR-0009).

## Existing implementation

career-portal: контраст не проверялся (аудит §6 — «серый #808080 на белом ниже AA»).

## Implementation requirements

1. Новый семантический цвет автоматически попадает в проверку (скрипт требует пару для каждого нового токена цвета — иначе красный).
2. Осознанные исключения — только записью в конфиг с комментарием-обоснованием.
3. Правки значений против career-portal — в таблицу диффов эпика.

## Technical considerations

- Формула контраста WCAG; разбор `var()`-цепочек до примитивов.

## Dependencies

- [T2.2 — Семантический слой](T2.2-token-semantic-layer.md)

## Acceptance Criteria

- [ ] Скрипт зелёный на дефолтной палитре; все текстовые пары ≥ 4.5:1 (крупные ≥ 3:1);
- [ ] Нарушение (специально изменённый токен) валит CI-шаг;
- [ ] Отчёт markdown прикладывается к CI-прогонам;
- [ ] Правки против career-portal (muted и др.) задокументированы.

## Testing requirements

Tests first: скрипт — сам тест; негативный кейс (тонкий серый) красный.

## Accessibility requirements

Это и есть a11y-задача: закрытие WCAG 1.4.3 на уровне системы.

## Notes

Гейт обязательный с момента появления (mandatory PR — 06 §7). **Говернанс одобренного дизайна:** правки значений (например, затемнение muted-серых) меняют одобренный визуал career-portal — каждая такая правка оформляется строкой в таблице диффов со статусом `design-decision` и согласуется с владельцем дизайна. Возможные исходы согласования: изменить значение / оставить с осознанным исключением в конфиге (например, muted только для крупного текста) — выбор не за разработчиком.
