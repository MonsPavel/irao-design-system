# TASK T2.4 — Механизм тем + синтетическая тестовая тема

## Epic

[EPIC-2 — Design Tokens](README.md)

## Priority

P0

## Type

TASK

## Goal

Доказать работоспособность механизма тем («переопределили семантические токены — изменился вид, классы и HTML компонентов не тронуты») без строительства мульти-брендовых тем.

## Context

Phase 0: в MVP один бренд Интер РАО; реальные темы будут добавляться minor-версиями (ADR-0009). Механизм обязан быть проверенным сейчас, потому что от него зависит обратная совместимость будущих тем: тема, написанная сегодня, должна работать с core завтра (новый токен = дефолт в `:root`).

## Scope

- `themes/theme-test.css`: `[data-ui-theme="test"] { …переопределение 5–7 семантических токенов (primary, accent, surface-muted, focus и др.)… }` — синтетическая, на сайты не подключается;
- переключатель темы на всех стендах (query-параметр `?theme=`, без перезагрузки или с ней — фиксируется реализацией);
- правило обратной совместимости тем в доке: новые токены вводятся только с дефолтом в `:root`;
- кейс в integration-guide: как сайту переопределить токены локально (`template_styles.css` после core).

## Out of scope

- Реальные брендовые темы компаний (нет по Phase 0);
- компонентные токены (слой 3 — ADR-0009);
- тёмная тема (do-not-build, 07 §5).

## Existing implementation

career-portal: тем нет; `:root`-переопределение по media используется — механика var-каскада та же.

## Implementation requirements

1. Тестовая тема должна переопределять только семантический слой (stylelint-проверка для themes/).
2. Фикстура совместимости: тест-тема без одного из новых токенов + core с ним — визуал валиден (дефолт работает).

## Technical considerations

- `data-ui-theme` вешается на `<html>` или `<body>` (фиксируется здесь, используется везде, включая каркас showcase T1.3 и сниппет T11.1).
