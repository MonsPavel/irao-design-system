# TASK T14.11 — Паттерн «таймлайн этапов»

## Epic

[EPIC-14 — Калибровка по пилоту career-portal](README.md)

## Priority

P1

## Type

TASK

## Goal

Добавить эталон повторяющейся композиции «этапы процесса» (`.timeline`
оригинала: «Как попасть на практику», горизонтальный ряд нумерованных точек
с заголовками и текстами) — паттерном сайт-зоны по образцу landing-section.
Пилот собирал связку самодельно (REPORT §4, PLAN P1-5).

## Context

Таймлайн — чистая CSS-композиция (ol + нумерованные точки + соединительная
линия), компонентовая база не нужна: кандидат в patterns/ как «правила сборки
+ mini-эталон» (прецедент landing-section T8.3). Компонент в dist не
создаём — второго потребителя нет; при появлении — решение о компоненте
отдельно.

## Scope

- patterns/timeline/timeline.html: правила сборки + mini-эталон (3–4 этапа
  на ol: нумерованная точка, заголовок h3, текст; соединительная линия на
  ::before/::after связок; мобильная деградация в колонку);
- patterns/timeline/README.md: композиция, a11y-правила (ol-семантика,
  нумерация видимым текстом, aria-hidden для декоративной линии, иерархия
  h2-секция → h3-этап), Bitrix-заметки (этапы из инфоблока);
- showcase/build.mjs: стенд паттерна (генерация по образцу landing-section:
  existsSync-условие, nav/каталог, STAND_DESCRIPTIONS, каркас с служебным h1 —
  фрагмент, не страница);
- связки (tl-*) — <style> паттерна на токенах (зона сайта, не dist);
- lint:html/axe стенда зелёные; эталон стенда в контейнере (ADR-0004).

## Out of scope

- Компонент dist/ui-timeline (нет второго потребителя — решение после эпика);
- Анимации шагов (за пределами матрицы, reduced-motion-осознанно — без них);
- Вертикальный таймлайн (в оригинале только горизонтальный; колонка —
  мобильная деградация той же композиции).

## Existing implementation

Прецедент паттерна-композиции: patterns/landing-section (T8.3); источник —
steps_html + .timeline career-portal build.py/pages.css (переносится
композиция, не стили).

## Implementation requirements

1. Новый CSS в системе запрещён (patterns/README): только связки в <style>
   паттерна на токенах.
2. Эталоны переснимаются ТОЛЬКО в контейнере (ADR-0004).
3. axe page-has-heading-one: каркас стенда несёт служебный h1 (фрагмент).

## Technical considerations

- Номер этапа — видимый текст (не content: counter — скринридер читает
  текст точки; нумерация ol дублирует — list-style: none + role="list" по
  конвенции .htmlvalidate.js с директивой);
- линия — декоративная aria-hidden связка, не несёт смысла;
- перенос длинных RU-слов в текстах этапов (overflow-wrap — base уже даёт).

## Dependencies

Отсутствуют.

## Acceptance Criteria

- [ ] Стенд patterns/timeline генерируется, доступен из каталога и сайдбара;
- [ ] ol-семантика + видимые номера + aria-hidden линия (axe зелёный);
- [ ] Мобильная деградация в колонку без горизонтального скролла (эталон 375);
- [ ] README: композиция, a11y-правила, Bitrix-заметки;
- [ ] Новый CSS отсутствует в dist; npm run lint, lint:html зелёные.

## Testing requirements

Поверхность — axe/lint стенда + эталоны 4 вьюпортов (как landing-section);
отдельных e2e не требуется (композиция без JS).

## Accessibility requirements

ol-семантика этапов, видимые номера (WCAG 1.3.1), иерархия h1(каркас)→h2(если
в эталоне секция)→h3(этапы), контраст текстов — гейты стенда.
