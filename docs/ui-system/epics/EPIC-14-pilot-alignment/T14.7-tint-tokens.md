# TASK T14.7 — Тинт-токены производных primary

## Epic

[EPIC-14 — Калибровка по пилоту career-portal](README.md)

## Priority

P2

## Type

TASK

## Goal

Дать сайт-зонам штатные полупрозрачные производные primary (плашки hero-тегов,
стеклянные карточки): в пилоте каждый потребитель городил `color-mix()` от
базовых токенов вручную (REPORT §4, PLAN P3). Система предоставляет тинты на
слое 2 — потребители не изобретают оттенки.

## Context

career-portal использует rgba-производные: теги hero (primary 20%, accent 26%,
спец-оттенки), стеклянные карточки holding/why-us (белые 0.1–0.2), оверлеи
(primary 55/94%). Белые/акцентные тинты — вторичны; эпик закрывает только
семейство primary (самое частое), остальные — по потребности.

## Scope

- tokens/semantic.css: тинты `--ui-color-primary-a10/-a20/-a26/-a55/-a94`
  через color-mix(in srgb, var(--ui-color-primary) N%, transparent) —
  производные следуют за primary в темах автоматически; провенанс-комментарии
  (career-portal hero__tag/holding/why-us, PLAN P3);
- проверка совместимости с матрицей браузеров (color-mix — baseline 2023;
  зафиксировать в комментарии токена; сборка не транспилирует CSS — ADR-0005);
- docs/ui-system/architecture/tokens-usage.md: раздел «тинты» (когда
  использовать, границы — декоративные поверхности, не текст);
- стенд tokens (tokens-stand.mjs): рендер новой секции, если генератор
  фильтрует по имени — расширить;
- юнит-пин парсера токенов (новые имена не ломают tokens-stand);
- эталон стенда tokens в контейнере при визуальных изменениях (ADR-0004).

## Out of scope

- Тинты белого/акцента/спец-оттенков hero (по потребности, не в эпике);
- Применение тинтов в компонентах dist (потребители — сайт-зоны и будущие
  лендинг-паттерны P2);
- Замена color-mix() в pilot.css — произойдёт в закрывающей T14.12 попутно,
  не в этой задаче.

## Existing implementation

tokens/semantic.css: --ui-color-primary, --ui-color-glass-* (существующие
стеклянные константы career-portal: 0.8/0.1/0.5); pilot.css (сайт-зона) —
ручные color-mix.

## Implementation requirements

1. Юнит: парсер tokens-stand находит новые имена (секция рендерится).
2. Эталоны: только стенд tokens (ADR-0004, если визуально изменился).

## Technical considerations

- Имена по паттерну BEM-токенов системы (--ui-color-primary-aNN — суффикс
  прозрачности в процентах);
- transparent в mix даёт нулевую альфу без сдвига оттенка (в отличие от
  rgba-хака с белым фоном);
- fallback для браузеров без color-mix не делается (матрица уже поддерживает).
