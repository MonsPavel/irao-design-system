# TASK T3.2 — Политика фокуса (реализация ADR-0001)

## Epic

[EPIC-3 — Base & Typography](README.md)

## Priority

P0

## Type

TASK

## Goal

Видимый фокус на каждом интерактивном элементе, переживающий legacy-CSS вида `a { outline: none }`, подключённый после системы.

## Context

ADR-0001 принят: политика фокуса пишется списком селекторов «элемент+псевдокласс» (специфичность 0-1-1 побеждает tag-правила legacy независимо от порядка каскада). В career-portal фокус-стили точечные (2 места) — система вводит глобальную гарантию.

## Scope

- `base/focus.css`: `a:focus-visible, button:focus-visible, input:focus-visible, select:focus-visible, textarea:focus-visible, summary:focus-visible, [tabindex]:focus-visible` с `outline: var(--ui-focus-width) solid var(--ui-focus-color); outline-offset: var(--ui-focus-offset)`;
- правило stylelint: запрет `outline: none` без замены (warning при старте, error после EPIC-4);
- дока/ADR-заметка «Focus visible: почему так» (ссылка на ADR-0001);
- e2e-сценарий «legacy-атака» (инжект `a { outline: none }` после ui-core).

## Out of scope

- Фокус-стили конкретных компонентов (классы компонентов в их задачах);
- focus trap/restore (T7.2, модальные контексты).

## Existing implementation

career-portal: `.vac-card__title a:focus-visible::after` и header-dropdown focus-стили — единичные случаи; паттерн `::after`-outline для растянутых ссылок перенесётся в T4.4.

## Implementation requirements

1. Список селекторов — точный по ADR-0001 (включая `[tabindex]` и `summary`).
2. Токены `--ui-focus-*` из T2.2; смена темы меняет фокус (сквозной e2e с T2.4).
3. Расширение списка новым тегом — ответственность этой задачи (записать в доках).

## Technical considerations

- `:focus-visible` — стандартное поведение «фокус с клавиатуры»; мышь не подсвечивается — осознанно;
- `outline-offset` гарантирует видимость на заполненных фонах.
