# TASK T3.6 — Сценарии масштабирования шрифта и zoom (релизный гейт)

## Epic

[EPIC-3 — Base & Typography](README.md)

## Priority

P0

## Type

TASK

## Goal

Превратить требование №19 ТЗ («корректная работа при увеличении шрифта») из надежды в автоматический тест: 200% browser zoom и 32px база не ломают вёрстку.

## Context

Требование менеджера из исходного ТЗ; связано с rem-типографикой (T2.2/T3.3), отказом от фиксированных высот и minmax(0,1fr)-сетками (T3.4). Сценарии гоняются на ключевых стендах (base, типографика, grid, форма) в nightly и релизе, не в PR (скорость).

## Scope

- e2e-сценарий A: browser zoom 200% (CDP-эмуляция) — нет горизонтального скролла, нет перекрытий ключевых узлов (проверка boundingBox);
- e2e-сценарий B: `html { font-size: 32px }` (инжект стиля) — те же проверки;
- подключение сценариев в nightly + release workflow (шаг T1.5/T12.1);
- чек-лист «что считать поломкой» (пороги перекрытия/обрезки).

## Out of scope

- 400%+ zoom (WCAG 1.4.10 рефлоу — цель 320px-ширины уже покрыта T3.4);
- VI-режим (у него свой масштаб, T9.1).

## Existing implementation

career-portal: ручные проверки оверфлоу в design-qa (`scrollWidth === clientWidth` на 390/320) — автоматизируем и расширяем.

## Implementation requirements

1. Список «ключевых узлов» стенда — фиксированный селектор-контракт (data-атрибут `data-ui-check-layout`), чтобы сценарий не ломался при рефакторинге стендов.
2. Порог: перекрытие > 2px или обрезка текста (scrollHeight > clientHeight у текстовых блоков) — падение.

## Technical considerations

- Zoom-эмуляция через Playwright CDP (`Emulation.setPageScaleFactor`/viewport CDP) или viewport-ширина/2 — реализацию зафиксировать в README тестов;
- инжект 32px — через `page.addStyleTag`.
