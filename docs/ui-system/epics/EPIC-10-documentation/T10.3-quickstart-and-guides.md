## Type

## Goal

Три ключевых документа внедрения: quickstart (подключение за минуты), integration-guide (living doc по 02-architecture §6), гайд интегратора «30 минут»; сниппеты bitrix/ синхронны гайдам.

## Context

Дока внедрения — главный рычаг adoption (риск №8 из 05-mvp-risks: «проще сверстать свою кнопку»). Целевая аудитория — Bitrix-разработчик без глубокого frontend-бэкграунда; всё должно работать копипастом.

## Scope

- **Quickstart** (README/showcase): скачать dist релиза → скопировать в `/local/ui/{version}/` → 4 строки в header.php → скопировать кнопку из доки → работает;
- **Integration guide** (living doc): подключение CSS/JS/шрифтов, порядок каскада, тема/токены-переопределения, компоненты в PHP, JSON-данные, формы-контракт (T5.6), крошки/пагинация-сниппеты, legacy-констрейнты (раздел 6 плана 06), миграция по стадиям, обновление версии;
- **«Bitrix-разработчику за 30 минут»**: сквозной туториал — от подключения до страницы со списком и формой;
- сверка: каждый сниппет в гайдах = файл в `bitrix/snippets/` (один источник).

## Out of scope

- Серверные рецепты Битрикса (инфоблоки, AJAX-контроллеры) — только стыковка с фронтендом;
- FAQ (накопится — заведём по факту).

## Existing implementation

Раздел «Интеграция в Битрикс» README career-portal (6 шагов) — зерно integration-guide; сниппеты — из T5.6/T6.3/T4.7/T11.1.

## Implementation requirements

1. Каждый шаг гайдов проверяем: инкогнито-тест (T11.1/эпик-AC) должен пройти только по докам.
2. Версионирование сниппетов: если сниппет меняется между minor — пометка «с версии X».
3. Русский язык, скриншоты не обязательны (текст+код читаются в CLI/редакторе).

## Technical considerations

- Quickstart обязан работать без Node на стороне сайта (только копирование файлов);
- инкогнито-тест — формализованный сценарий (чек-лист в доке эпика 11).
