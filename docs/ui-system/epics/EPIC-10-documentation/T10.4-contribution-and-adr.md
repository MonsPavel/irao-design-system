# TASK T10.4 — Contribution guide и ADR-процесс

## Epic

[EPIC-10 — Documentation](README.md)

## Priority

P1

## Type

TASK

## Goal

Финализировать CONTRIBUTING: полный процесс добавления компонента, правила токенов, semver-триггеры; закрепить ADR-журнал как процесс (формат, supersede-паттерн, номера).

## Context

Черновики созданы в T1.1/T4.2. К моменту задачи система прошла цикл до hardening — известны реальные места трения. ADR-журнал уже живой (0001–0009 + решение SPIKE T7.1): остаётся описать процесс, чтобы решения принимались командой единообразно.

## Scope

- CONTRIBUTING финал:
  - процесс «новый компонент»: задача → шаблон → тесты-first → реализация → дока → чек-лист ревью (заведён в T4.2);
  - правила токенов (слои, гейт «новый семантический — с потребителем», компонентный слой 3 — по ADR-0009);
  - semver-триггеры (что minor/patch/major — ADR-0007) + «изменение канонического HTML = major»;
  - правило «site-специфика не попадает в системные модули» (урок T7.3);
- ADR-процесс: формат (контекст/решение/альтернативы/последствия/проверка), нумерация, supersede, когда ADR обязателен (SPIKE, смена подхода, исключение из правила);
- индексация ADR в docs/ui-system/architecture/README.md — актуальность.

## Out of scope

- CODEOWNERS/командные роли (команда 1–2 — не нужно);
- автоматическая генерация changelog из коммитов (ручный Keep a Changelog — T12.2).

## Existing implementation

ADR-журнал docs/adr/ (0001–0009) — живой прецедент; CONTRIBUTING-черновики из T1.1/T4.2.

## Implementation requirements

1. ADR-формат описан по факту существующих файлов (не выдуманный).
2. Чек-лист ревью компонента — исполнимая страница (галочки).
3. Semver-триггеры — таблицей с примерами.

## Technical considerations

- CONTRIBUTING ссылается на файлы реального репо (шаблон module-template, чек-листы), не абстрактен.
