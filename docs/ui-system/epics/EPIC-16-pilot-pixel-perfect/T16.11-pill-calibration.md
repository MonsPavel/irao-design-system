# TASK T16.11 — ДС: калибровка ui-button--pill по канону (рамка/кружок primary, метка, hover)

## Epic

[EPIC-16 — Пилот career-portal: пиксель-перфект зоны shell (раунд 3)](README.md)

## Priority

## Goal

`ui-button--pill` (T14.4) — самый частый CTA оригинала («откликнуться»,
«подробнее») — отходит от канона в трёх точках: рамка серая вместо
primary, кружок-иконка всегда accent вместо primary (оранжевый — только
hover), метка без uppercase/letter-spacing. Откалибровать вариант по
байт-канону оригинала: правка убирает расхождение со ВСЕХ страниц
владельца (деталка вакансии, строки, internship/event) одним местом.

## Context

Канон оригинала — `.pill-btn` (career-portal pages.css:215–254):

- пилюля h44, фон surface, **рамка 1px primary**;
- паддинг `0 6px 0 20px`, gap 12;
- метка **fs 13** (0.8125rem), fw-small, **text-transform: uppercase**,
  **letter-spacing: 0.04em**, цвет primary;
  - кружок `.pill-btn__icon`: 32px (30px в `--sm`), фон primary,
  текст on-dark;
- hover: фон пилюли `--color-surface-blue-50`, **кружок → accent**.

Текущий DS-вариант (components/ui-button/ui-button.css, T14.4):
рамка `--ui-border-color` (серая), кружок **статично accent**
(рвение accent/white), метка fs-small 14 без uppercase и
без letter-spacing, паддинг 16/4. Замер раунда 3 (REPORT §8.2 №6,
строка вакансии): «border primary + кружок primary fs 13 → без рамки,
кружок accent fs 14».

Предыстория: mapping §3 (строка pill-btn) в раунде 1/2 закрывал диффы
fs 13→14 и паддинг 20/6→16/4 как «принято ДС» (ступень шкалы), рамку —
«пара outline, серая». Пиксель-перфект (директива владельца 22.10)
переоткрывает пункты до уровня байт-канона: задача сверит probe'ом
обе версии и решит по каждой точке либо «как есть»-перенос
(прецедент height-pill 44px: вне шкалы — токен), либо подтверждение
прежнего «принято» с фиксацией в mapping.

Внимание: кружок в оригинале меняется НА HOVER (primary → accent),
не статичен. Решение T14.4 «иконка красится акцентом» — неверно
прочитанный канон (PLAN P0-4): фактически accent — hover-состояние.

## Scope

- components/ui-button/ui-button.css `--pill`:
  - рамка → primary (`--ui-color-primary`), паддинг/гэп — по решению
    probe (оригинал 20/6/12; токены `--ui-button-pill-pad-*` при
    переносе «как есть»);
  - кружок `__icon`: фон → `--ui-color-primary`; hover — accent
    (в `@media (hover: hover)` по конвенции) + фон пилюли
    `--ui-color-surface-muted`;
  - метка: `text-transform: uppercase`, `letter-spacing: 0.04em`,
    fs 13 — токен `--ui-button-pill-label-fs: 0.8125rem` вне шкалы
    «как есть» ЛИБО подтверждение fs-small «принято ДС» (решить по
    probe-замеру; uppercase/ls обязательны в обоих исходах);
  - `--sm`: пересадить 30px-кружок и уплотнённые значения, не теряя
    комбинированный AC T14.4;
- README ui-button: правило варианта (кружок primary, hover accent;
  uppercase — происхождение из варфрейма; когда применять);
- стенд ui-button: pill-вариант показателен с иконкой (замер кружка);
- mapping §3: обновить строку pill-btn (рамка primary — пара primary;
  кружок base/hover — алиасы tag-blue/tag-orange; метка uppercase/ls;
  паддинги);
- unit-пины (button.test.js): классы, минвысоты, цвета кружка
  base/hover, uppercase/ls метки;
- эталоны стенда в контейнере (ADR-0004), CHANGELOG;
- контраст: пары уже в гейте (primary/white, accent/white) — убедиться,
  что обе роли попали в покрытие (алиасы при необходимости).

## Out of scope

- Adoption в пилоте не нужен: `pillButton()` (build.mjs:164) уже
  использует `ui-button--pill` — калибровка компонента применяется
  на всех страницах автоматически (текст разметки остаётся строчным —
  uppercase даёт CSS, aria читает исходный регистр);
- Изменение высоты 44 (`--ui-button-height-pill` уже канонична);
- Другие варианты кнопок (primary/accent/outline/light) — вне.

## Existing implementation

`ui-button--pill` + `--sm` (T14.4): высота/фон/радиус каноничны,
расходятся рамка, цвет кружка и типографика метки (см. Context).

## Implementation requirements

1. Эталоны только в контейнере (ADR-0004, sha-паритет).
2. Углы кружка — круг (border-radius 50% текущий), стрелка 16px.
3. Hover только под `@media (hover: hover)`; active — color-mix
   по конвенции (как у остальных вариантов кнопки).
4. VI-перекраска кружка: currentColor-стрелка сохраняется; фон
   варианта должен переворачиваться токен-парами (ui-vi стенд).

## Technical considerations

- Токены цветоносителей НЕ менять: primary/accent роли уже есть;
  вариант только ссылается на них — ниже fallout на другие темы;
- uppercase через CSS (не контент): локализация и скринридер читают
  исходный регистр (a11y-безопасно, как .tag-надписи);
- «принято ДС» vs «как есть»: обе точки fs и паддингов — по решению
  probe-сверки; фиксация решения обязательна в mapping (правило
  REPORT §2: каждое расходование закрывается строкой).

## Accessibility requirements

Пары primary/white и accent/white — AA 14.60:1 и 3.55:1 (крупная
графика/иконка — ≥3:1 достаточно); uppercase не мешает скринридеру
(текст в DOM остаётся строчным); кнопка — нативный button/a с
фокус-кольцом от базового класса.

> **Errata 25.10 (владелец, триаж-дайджест):** исходный текст этой секции
> писал «12.58:1» для primary/white — это пара primary на blue-100
> (surface-hover), а не primary/white. Первичная цифра — на практике
> (контраст-гейт lib): primary #002856 на white = 14.60:1. Тот же класс
> ошибки уже чинился в README ui-badge (T13.8) и спеке T16.10 (errata).
