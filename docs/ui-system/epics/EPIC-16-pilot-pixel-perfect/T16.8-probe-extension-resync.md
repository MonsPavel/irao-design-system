# TASK T16.8 — Пробы и закрывающая пересверка раунда 3

## Epic

[EPIC-16 — Пилот career-portal: пиксель-перфект зоны shell](README.md)

## Priority

P1 (гейт эпика)

## Type

TASK (инструменты сравнения + ресинк)

## Goal

Расширить probe-набор compare.mjs зонами, которые не покрывались
(шапка, футер, строки, сайдбар, фон страницы), прогнать свежий
compare на 12 страницах и актуализировать REPORT/PLAN — закрывающий
гейт EPIC-16: каждый фикс подтверждён числами, а не глазами.

## Context

Раунды 1—2 сравнивали компонентные зоны (кнопки, карточки, поля,
чипы, крошки, пагинация, табы, модалки), поэтому shell-зоны
(шапка/футер/строки/сайдбар/фон) оставались «слепым пятном»: расхождения
(§8.2 №1—№8) жили вне проб и всплыли только по ручным показаниям.
Урок — систематические зоны должны быть в probe-наборе на постоянной
основе.

## Scope

1. **Новые probes (пары original/pilot на каждой странице):**
   - `body-bg` — фон `<body>` (rgb; ловит возврат blue-50);
   - `header-link` — первый пункт меню шапки: fs, fw, tdl, color,
     rect (высота строки);
   - `dropdown-item` — пункт «Рабочие направления» dropdown:
     fs, lh, padding, tdl;
   - `footer-link` — первая ссылка футера: fs, fw, tdl, color;
     `footer` — bg и высота футера;
   - `row-title` — заголовок первой строки (vacancies-подобные
     страницы): тег, fs, fw, tdl, color;
   - `row-item` — сам ряд: паддинг, bg, радиус;
   - `pill-icon` — кружок стрелки CTA строки: bg (ловит accent vs
     primary);
   - `reset-control` — «Сбросить»: тег, fs, fw, tdl, color, высота.
2. **compare.mjs** — подключение проб по тем же конвенциям
   (selector-пары, styles/rect/text), обновление viewer при
   необходимости;
3. **свежий compare** на 12 страницах (после T16.1—T16.7);
4. **REPORT**: §8.2 актуализация статусов (№1—№8 «закрыто T16.x»),
   срез новых чисел; вывод — остатки в BACKLOG (если есть);
5. **PLAN**: отметить выполненные пункты раунда 3, итоговое
   состояние.

## Out of scope

- Скриншоты новых зон типа «обрезанных баннеров» — compare уже
  снимает полные пары страниц (PNG), этого достаточно для
  side-by-side;
- автогейтинг ночного конвейера по новым пробам (конвейер читает
  compare.json как есть; алерты — отдельная тема, не эпик);
- экстрапробы на index (hero/карусель) — вне скоупа эпика (P3
  бэклог).

## Existing implementation

- `pilot/career-portal/compare.mjs` — текущий набор 20 проб,
  12 страниц; новые пробы добавляются в то же место конвейера
  (структура compare.json совместима);
- отчётная дисциплина — REPORT §2 (методика live-замеров) не
  меняется.

## Implementation requirements

1. Каждый probe обязан возвращать пару коротких полей (не весь
   computed-стиль), с одинаковыми семантиками на двух сторонах
   (селекторы оригинала ≠ селектора клона — у probe есть матчер
   пары);
2. absence-of-element: если сущности нет на какой-то из 12 страниц
   (например, row-title не на media.html) — проба возвращает null
   на обеих сторонах (а не падает);
3. json продолжает быть машиночитаемым (владелец nightly-гейта
   читает diff-счётчики).

## Technical considerations

- Пробы не зависят от состояний: header/footer/rows — static DOM,
  hover не требуется; pill-icon проверяется через computed bg
  кружка (не псевдоэлемент);
- JS-проба body-bg — логика «computed root bg» переиспользуется из
  существующего замера doc-height.

## Dependencies

Выполняется последней в эпике — после T16.1…T16.7 (все фиксы должны
быть в dist). Не конфликтует файлами ни с чем.

## Acceptance Criteria

- [ ] compare.json содержит 8 новых проб на страницах, где сущность
  существует (null-сима на обеих сторонах — иначе);
- [ ] по итогам прогона §8.2 №1—№8 каждая помечена фиксирующим
  «закрыто T16.x» с числами после фикса;
- [ ] новые расхождения (если исходные пробы поглотили) перечислены
  отдельным списком с приоритетами — «принято ДС» против кандидатов;
- [ ] REPORT/PLAN актуализированы; ссылка на свежий compare.json
  (дата/время) в REPORT §8;
- [ ] новые пробы видны в viewer.html вместе с прежними;

## Testing requirements

compare.mjs — инструмент пилота (вне unit-гейтов ДС). Проверка:
локальный прогон заполняет json без ошибок, diff-счётчик согласован
с REPORT.

## Accessibility requirements

Не относится (инструменты сравнения); однако пробы tdl/color
косвенно помогают следить за контрастными политиками на сквозных
зонах — сохраняются.

## Definition of Done

- [ ] Implementation completed (probes + compare + docs)
- [ ] Свежий compare.json приложен (gitignored артефакт, фиксация
  даты в REPORT)
- [ ] Documentation updated (REPORT §8, PLAN)
- [ ] Коммит по конвенции (`chore(pilot): T16.8 …`)
