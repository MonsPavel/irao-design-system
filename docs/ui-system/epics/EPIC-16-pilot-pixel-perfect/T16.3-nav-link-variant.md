# TASK T16.3 — ДС: навигационные ссылки и шапка

## Epic

[EPIC-16 — Пилот career-portal: пиксель-перфект зоны shell](README.md)

## Priority

P0

## Type

TASK (компонент/паттерн ДС + adoption пилота)

## Goal

Дать ДС корректный nav-вариант ссылки и интегрировать его в пилотную
шапку: пункты меню — fs-small (14px), без подчёркивания, hover —
opacity как в оригинале; пункты dropdown — 16px. Сейчас навигация
клона (и паттерна header ДС) рисуется 20px с подчёркиванием.

## Context

Замера отчёта §8.2 №4 (vacancies, 22.10):

| Сущность | Оригинал | irao-ui сегодня |
|---|---|---|
| `.header__link` | fs 14 (`--fs-small`), fw 500, lh 1.1, tdl none, color primary, hover opacity .7 (src/blocks/header/header.css:30-43) | `.cp-header .ui-link`: fs 20 (наследование), tdl underline (политика ui-link) |
| `.header__link--toggle` | fs 14 + chevron | наследует 20px — исправляется вместе с меню |
| `.header__dropdown-link` | fs 16, lh 20, pad 8/12/15, tdl none | `.ui-dropdown__item`: fs 20 (наследование), tdl underline; padding 8/12/15 совпал |
| `.header__link--vi` / `--search` | fs 14 | VI-пилюля: пилотная сайт-зона оставила fs наследуемым (20px) |

Причина: политика ДС «ui-link подчёркнут всегда» (a11y-решение T4.1)
верна для inline-ссылок контента. Nav — не inline-ссылки: пункты
навигации в `<nav>` — WCAG 1.4.1 допускает не-подчёркнутые ссылки
в структурном (навигационном) контексте; паттерн header ДС
(patterns/header) сам использует `ui-link` в nav и не задаёт размер —
обе формы выходят как 20px/underline.

Показания owner («хедер не такой по размерам шрифтов», «все ссылки
underline») — сюда. Решение владельца 22.10: nav-ссылки без
подчёркивания при структурной маркировке; inline-ссылки контента
остаются подчёркнутыми.

## Scope

1. **ДС — компонент ui-link:**
   - модификатор `.ui-link--nav`: fs-small/fw-small (14/500), tdl
     none, hover: opacity 0.7 (@media hover:hover), focus-ring не
     меняется (ADR-0001); допускает наследование размера узким
     `.cp-header`-случаем — не требует;
   - `:visited` — nav-ссылки переходят между страницами одного сайта:
     цвет меняется, как у default (`--ui-color-text-muted`); правило
     остаётся, не отключается;
   - README ui-link: правила для nav (do: пункты меню/шапки/футера
     навигации; don't: inline-текст контента);
   - unit-пины: tdl none, fs 14, fw 500, hover opacity; e2e-стенд
     ui-link — добавить карточный вариант nav (не мешает, обновляется
     отображение стенда).
2. **ДС — компонент ui-dropdown:**
   - `__item` размер — fs 16 / lh 20 (fixed, прецедент «как есть»:
     16px вне шкалы, как T14.3 паддинг 28px; добавляется токен
     `--ui-dropdown-item-fs: 1rem`); tdl none — якорь внутри item
     подчёркивания не наследует (hover не добавляет подчёркивания);
   - unit-пин fs 16/padding.
3. **ДС — паттерн header (patterns/header):**
   - nav-ссылки → `ui-link ui-link--nav` (header.html, README);
   - эталон паттерна пересъём при добавлении.
4. **Пилот (adoption):**
   - build.mjs: шапка — пункты меню и «Поиск» → `ui-link--nav`;
     снятие сайт-зонных правил шрифта `.cp-header__menu .ui-link`
     (размер и вес теперь несёт модификатор);
   - `.cp-header__vi` — приведение к fs-small (сегодня наследует
     20px от страницы).

## Out of scope

- Футер — T16.4 (там же разговор про тёмные ссылки);
- содержимое VI-режима (on/off, кнопки — остаются);
- underline inline-ссылок контента (статьи, form-success) — политика
  ДС остаётся;
- hover-цветов (только opacity — цветной hover ui-link не добавляется
  к nav-варианту).

## Existing implementation

- ui-link.css уже имеет прецеденты `--on-dark`/`--button` — новый
  модификатор в том же стиле;
- паттерн header T7.6 (родственная структура навигации);
- `.cp-header__menu .ui-link` (pilot.css:67) — единственная текущая
  site-zone связка.

## Implementation requirements

1. Модификатор должен вести себя одинаково на шапке клона и standalone
   (unit-пины std-стенда).
2. Прецедент снятия подчёркивания — задокументировать: WCAG 1.4.1
   «Use of Color» не требует подчёркивания при выраженной навигационной
   структуре; пункт в README do/don't.
3. Контраст-гейт: пара primary/white — без изменений.

## Technical considerations

- `opacity`-hover (оригинал) против цветного hover (ui-link default) —
  для групп навигации opacity даёт более точную картину и не требует
  новых цветовых токенов; фиксируется в css-комментарии.
- aria-связка триггера dropdown (`aria-controls`, раскрытие) — не
  трогается.

## Dependencies

- DS-часть (модификатор, dropdown item) до правки паттерна и adoption
  пилота;
- T16.2 желательно рядом (общая картина «кнопки и ссылки навигации»);
- файлы пересечения: только ui-link/ui-dropdown CSS + паттерн header —
  их не трогает ни одна другая задача эпика.

## Acceptance Criteria

- [ ] `.ui-link--nav`: computed fs 14px, fw 500, tdl none, hover
  opacity .7 (unit/e2e-пин);
- [ ] `.ui-dropdown__item` в шапке: fs 16px, lh 20px, tdl none,
  padding 8/12/15 (unit-пин);
- [ ] паттерн header: nav-ссылки на ui-link--nav, эталон переснят
  (контейнер, ADR-0004);
- [ ] шапка клона: все пункты совпадают с оригиналом по
  computed-стилям (probes T16.8);
- [ ] гейт репозитория зелёный.

## Testing requirements

Unit-пины (ui-link--nav, ui-dropdown__item) + стенда-снапшоты;
e2e-стенд ui-link расширяется вариантом; снапшоты стенда и паттерна
header пересняты (контейнер).

## Accessibility requirements

- Nav-структура `<nav[aria-label]>` — маркировка навигации, WCAG 1.4.1
  исключение документируется в README ui-link;
- focus-ring — как у default ui-link (ADR-0001);
- hover opacity 0.7 — производное состояние (ADR-0010, не гейтится
  парами токенов, e2e-гейт hover не падает).
