## Goal

Заголовки карточек списков рендерятся в клоне крупными ролями (`ui-h4` 28px,
`ui-h5` 24px) против канона оригинала **20/500 `#1F1F1F`** (`--fs-body` ×
`--fw-body-bold`) и **14/500** для мини-карточек статей. Раунд 4 дал ~96+
текстовых находок этой систематики на events, education (org/adv/offer),
internships/practices (intern/timeline/intern-person), media/career-track
(article-card). Мини-тайтлы статей также 14/500. Класс расхождения один —
переносится одним пакетом замен в build.mjs после фиксации DS-роли.

Текущий клон: `eventCard/orgCard/offerCard/advCard/internCard` — `h3.ui-h4`
(28), `timeline`/`internPerson` — `ui-h5` (24, замер показал navy — заголовок
не тянет цвет по умолчанию в контексте карточки), заголовки статей
`h3.ui-h4` (28). Подписи собраны `ui-small` БЕЗ цвета (наследуют
`#1F1F1F` fw 500) там, где оригинал рисует 14/400 muted.

Роль DS для 20/500 уже есть: **`ui-h6`** (tokens/semantic.css: «новый:
роль §3.2, в career-portal её нет; размер = ступень body» 1.25rem, fw 500,
lh 1.25) — задумана ровно под карточные заголовки. DS-часть задачи —
подтвердить роль для этого применения (цветное поведение заголовка DS
проверить: если ui-heading фиксирует цвет, решение по adv/offer primary —
модификатор или наследование), остальное — adoption build.mjs.

## Scope

- **ДС**: README/ui-заголовков — зафиксировать `ui-h6` как канонический
  «заголовок карточки списков»; проверка цвета ui-heading (наследование vs
  фиксированный `--ui-color-text`); для adv/offer primary — выбор
  (модификатор `ui-h6--primary` по прецеденту цветных вариантов ui-tag
  ИЛИ сайт-зонная перекраска — решить по probe и отметить в mapping);
  mapping §3: строки org/adv/offer/article-card;
- **адопция build.mjs**:
  - `eventCard`, `orgCard`, `offerCard`, `advCard`, `internCard`:
    `h3.ui-h4` → `h3.ui-h6` (adv/offer + цвет primary по решению ДС-части);
  - `timeline`: `ui-h5` → `ui-h6`; `internPerson`: `p.ui-h5` → `ui-h6`;
  - заголовки статей (`articleCard`, `mediaHomeCard` с desc): `h3.ui-h4` →
    мини-карточный тайтл 14/500 (решение по review: модификатор
    `ui-h6--sm` / утилита `ui-small` на семантике заголовка — одним
    выбором на оба места);
  - подписи/шорты/даты: `ui-small` → `ui-small ui-text--muted` там, где
    оригинал muted (org/adv?, timeline, intern, person, article/media
    дата — по таблице Context; offer-card short/adv-card text остаются
    color-text — без muted);
- **pilot.css**: clamp 3 для `--short` карточек (как `.org-card__short`);
- сравнение REPORT §8.2/§9: строка mapping «заголовки карточек».

## Out of scope

- Строки списка вакансий (vac-row) — T16.5, иные кнопки — T16.11;
- карточки компаний (14/500 отдельный случай) — T16.16;
- лендинг-блоки index (why-us/students/directions) — P2, вне эпика;
- fw 400→500 подписей — канон small-роли ДС, «принято ДС» (mapping
  T14.8/T14.9), не переоткрывается.

## Implementation requirements

1. Adoption не меняет семантику (h3 остаётся h3; заменить только
   классы ролей).
2. Замены делаются одним батчем в одной задаче — чтобы не оставить
   страницы в промежуточном (смешанном) состоянии.
3. Замер до/после — по probe-паре «event-card / article-card» на
   сравнительном сервере.

## Technical considerations

- `ui-h6` lh 1.25 vs оригинал lh 1.3 (25 vs 26px на строке) — в пороге
  ≤4px эпика, «принято ДС» (фиксация в mapping не требуется).
- Mini-тайтл 14/500 — fs-small/fw-small DS точно совпадает с `.article-card__title`
  (fw-small = 500 в обеих системах).
