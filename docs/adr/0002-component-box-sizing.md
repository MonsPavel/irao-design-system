# ADR-0002: box-sizing объявляется на корне каждого компонента

- **Дата:** 2026-10-05
- **Статус:** принято
- **Влияет на:** [02-architecture.md](../02-architecture.md) §1, §2; задачи T1.1 (шаблон компоненты), T11.1

## Контекст

Глобальный сброс системы (`*, *::before, *::after { box-sizing: border-box }`) и legacy-сброс сайта (`* { box-sizing: content-box }` и подобные) имеют одинаковую специфичность универсальных селекторов — победит тот, кто подключён позже, то есть legacy. Следствие: геометрия ui-компонентов (кнопки и поля с padding + width) разваливается на «токсичных» страницах. Это самый вероятный источник жалоб «у вас кнопка кривая» при интеграции.

## Решение

Каждый компонент объявляет `box-sizing: border-box` на своём корневом селекторе и на внутренних элементах с размерами:

```css
.ui-button { box-sizing: border-box; … }
.ui-button__icon { box-sizing: border-box; … }
```

Строка включена в шаблон новой компоненты и в ревью-чек-лист «Как добавить компонент» (T1.1, закрепляется в CONTRIBUTING — T10.4). Глобальный сброс в base сохраняется: он нужен для зон без legacy-конфликтов, но компоненты не полагаются только на него.

Принцип, следствием которого является этот ADR: **класс компонента полностью определяет свой вид** — компонент не зависит от element-стилей base (шрифт body и т.п.) и от глобальных сбросов для своей корректности.

## Последствия

**Плюсы:** компоненты автономны от среды подключения; цена — одна строка на компонент.

**Цена/минусы:** дисциплина («нельзя забыть строку») держится чек-листом и ревью, а не линтером (stylelint не умеет требовать наличие свойства у селектора); при написании CSS нельзя полагаться только на глобальный сброс.

## Проверка

E2E-стенд «legacy-атака» в T11.1: инжект `* { box-sizing: content-box }` после ui-core — геометрия ключевых компонентов (button, field, card) не меняется.
