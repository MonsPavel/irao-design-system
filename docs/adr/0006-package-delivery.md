# ADR-0006: Дистрибуция — копия версионированной папки на сайт

- **Дата:** 2026-10-05
- **Статус:** принято (фиксирует решение из 02-architecture §6 и Phase 0)
- **Влияет на:** T11.1–T11.4, T12.1

## Context

Сайты группы на Bitrix должны потреблять dist UI-системы. Варианты: копия ассетов на каждый сайт, общий статик-домен, npm/composer-пакет, git-submodule. Решение Phase 0 (2026-10-05): мульти-бренда нет, репозиторий GitHub; инфраструктура общего домена и политика ИБ не подтверждены.

## Decision

Релиз = git-тег + zip-артефакт `dist/`. Сайт получает систему **копией в `/local/ui/{semver}/`** (ui-core.min.css, ui-vi.min.css, ui.min.js, fonts/, themes/). Подключение — 3–4 строки в `header.php` через `Asset::getInstance()` с константой `UI_VERSION`; обновление = смена константы; откат = возврат константы. Правки в `/local/ui/` на сайте запрещены (копия read-only).

## Alternatives considered

- **Общий статик-домен** — центральное обновление затрагивает все сайты разом (противоречит поэтапной миграции и политике N−1), нужны HTTPS/CORS/SLO и решение ИБ. Остался отложенной опцией для 5+ сайтов.
- **npm/composer-пакет** — Bitrix-команды группы не имеют гарантированного Node/Composer-конвейера у потребителя; добавляет сборочный шаг там, где достаточно копии.
- **Git submodule** — пинятся коммитами, болезненны для интеграторов, ломаются при переносе репо.

## Why

Копия даёт автономность сайта (нет CORS и внешних зависимостей), осознанное обновление, тривиальный откат и мажорное сосуществование (`/local/ui/1.x/` и `/local/ui/2.x/` рядом). Файлы dist при переходе на домен не меняются — решение обратимо.

## Consequences

**Плюсы:** простота, автономность, безопасность ИБ, мгновенный откат.
**Минусы/цена:** обновления разносятся по сайтам вручную (по upgrade-гайду, ≤0.5 дня — отработано T11.4); при большом числе сайтов решение пересматривается.
