# ADR-0010: Производные цвета состояний — color-mix как стандарт, hover-пары одобренного дизайна — явные токены

- **Дата:** 2026-10-06
- **Статус:** принято (задача T2.6)
- **Влияет на:** T4.2 (button — эталонный потребитель), компоненты с hover (EPIC-4/5), T2.4 (темы), T9.2 (ревизия контраста производных)

## Context

Hover-цвета career-portal захардкожены рядом с базовыми: `--color-blue-700` лежит в `variables.css` рядом с `--color-primary`, а правила выглядят как `.btn--primary:hover { background: var(--color-blue-700) }` (components.css:80, accent — components.css:83). При темизации такие дубли забывают переопределять — тема меняет базу, hover остаётся старым брендом. T2.2 сознательно оставил hover-значения вне слоя 2 (Out of scope → T2.6). Матрица браузеров Phase 0 «evergreen ×2» разрешает `color-mix()`: Chromium 111+, Firefox 113+, Safari 16.2+ (baseline 2023).

## Decision

1. **Стандарт производных состояний — `color-mix` над токеном слоя 2.** Для состояний, которые одобренный дизайн НЕ задавал (active; hover-производные outline/light-вариантов; будущие состояния без макета): `color-mix(in srgb, var(--ui-color-…) 88%, black)`. Конвенция смешения — **88% базовый + black** (02-architecture §3.2, строка «Состояния»). Hover-правила оборачиваются в `@media (hover: hover)` — на тач-устройствах sticky-hover не «залипает» (требование T4.2 п.4).
2. **Исключение — значения, заданные одобренным дизайном.** Hover primary = blue-700 `#164b89` (career-portal components.css:80) и hover accent = accent-light `#f37131` (components.css:83) переносятся семантическими токенами-парами `--ui-color-primary-hover` / `--ui-color-accent-hover` (minor с дефолтом в `:root`, ADR-0007/0009). `color-mix` от базового одобренное значение не воспроизводит (`mix(blue-800 88%, black)` ≈ `#00234c`, не `#164b89`) — пересчёт менял бы утверждённый визуал.
3. **Пары — явная часть API слоя 2; за `--ui-color-primary` автоматически не следуют.** Производная на color-mix вычисляется браузером из токена в момент рендера — тема меняет её сама; пара — константа макета, тема переопределяет её явно вместе с базовым токеном (или осознанно оставляет). Явность и решает анти-паттерн «забыли переопределить дубль»: дубль больше не прячется рядом с базой — он виден в семантическом API и покрыт контраст-гейтом T2.3 (пара или осознанное исключение).
4. **Новый явный hover-токен (сверх двух перенесённых) — только через ревью-гейт:** обоснование «дизайн задал значение, color-mix его не воспроизводит» в PR + запись в таблице диффов (tokens-career-portal-mapping.md).
5. **Fallback — прозрачная деградация, без полифилов и фолбэк-строк.** Браузер без поддержки `color-mix()` отбрасывает невалидное объявление целиком — состояние остаётся с базовым цветом: теряется только оттенок hover/active, функциональной поломки нет. Дублирующая строка с приближённым «ручным» цветом вернула бы те самые дубли, от которых ADR избавляется; матрица evergreen ×2 поддержку гарантирует.
6. **Контраст производных состояний — сфера T9.2** (ревизия производных; чек-лист T9.2: крупные элементы ≥ 3:1 в hover). Факт на момент ADR: белая подпись на primary-hover `#164b89` — 8.74:1 (AA), на accent-hover `#f37131` — 2.91:1 (< 3:1 крупного); значения одобренного дизайна до design-decision владельца не меняются — оба токена пока осознанные исключения контраст-гейта (`tests/contrast/pairs.config.mjs`).

Исполнение: e2e computed-style hover до/после смены темы — `tests/e2e/derived-states.spec.js` (демо-секция «Производные состояния» стенда «Токены», генерация — `showcase/tokens-stand.mjs`); эталонный потребитель — ui-button (T4.2): hover из токенов-пар, active — color-mix. Кнопочная часть AC2 до появления ui-button записана в `tests/e2e/README.md` (секция «Сценарий T2.6, кнопочная часть», пин записи — `tests/unit/derived-states-handoff.test.js`), закрывается при приёмке T4.2: visual-эталоны снимаются только в контейнере/CI (ADR-0003/0004).

## Alternatives considered

- **Все hover через color-mix** (включая одобренные) — пересчитывает утверждённый визуал (см. п.2), нарушение инварианта «значения одобренного дизайна не меняются».
- **Полная матрица явных hover-токенов для всех состояний и вариантов** — взрыв сущностей слоя 2 и возврат ручных дублей в масштабе системы; color-mix покрывает незаданные состояния без новых сущностей.
- **Препроцессорные darken()/lighten() (Sass/Less)** — build-шаг без выгоды (нативный CSS, ADR-0005): при смене темы пересчитывать в рантайме всё равно нечем, кроме custom properties + color-mix.

## Why

Смена темы автоматически перекрашивает все color-mix-производные (браузер пересчитывает mix из themed-токена — проверено e2e на стенде с темой T2.4); одобренный визуал остаётся пиксель-в-пиксель (пары — константы макета); новое состояние не требует нового токена и не плодит дублей.

## Consequences

**Плюсы:** ноль ручных hover-дублей для незаданных дизайном состояний; дешёвые темы (производные едут за токенами сами); единая конвенция 88% + black; прозрачная деградация без полифилов.
**Минусы/цена:** реальная тема обязана переопределять пары осознанно — гейт тем (T2.4) непереопределённую пару пропустит, контроль на ревью темы; контраст производных до T9.2 автоматически не гейтится (исключения в pairs.config.mjs с числами); минимальные версии браузеров подняты до уровня color-mix (Chromium 111+, Firefox 113+, Safari 16.2+) — более старые получают базовый цвет состояния без производной.
