# ADR-0012: ui-select на touch-устройствах остаётся нативным (pointer: coarse)

- **Дата:** 2026-10-09
- **Статус:** принято (задача T7.3, Implementation requirements п. 3: «мобильную стратегию зафиксировать в доке и ADR-заметке»)
- **Влияет на:** components/ui-select/ (T7.3), потребители фильтров (T8.1)

## Context

Кастомный select (T7.3) строит listbox поверх нативного `<select>`. На
touch-устройствах кастомный список проигрывает системному пикеру ОС по всем
осевым параметрам мобильного UX: колесо/шторка нативного пикера — устоявшийся
жест, цели касания крупные, нет проблемы скролл-коллизий списка со страницей,
нет вопроса позиционирования у края вьюпорта. При этом сам паттерн PE
(career-portal `dropdowns.js`) рассчитан на pointer-устройства: hover-гвард
компонентов системы (конвенция EPIC-4) и touch-цели пагинации (T6.3) — уже
учтённые прецеденты «на таче поведение другое».

Спека T7.3 оставляет решение за реализацией: «на touch можно оставить нативный
select (media (pointer: coarse) — модуль не активируется)».

## Decision

Модуль `IraoUI.select` при инициализации каждого инстанса спрашивает
`matchMedia('(pointer: coarse)')`; при совпадении **не активируется** — select
остаётся ровно в том виде, в каком его отрисовал сайт (нативные стили
ui-field__select, T5.2), без кастомного триггера и списка.

- Запрос — живой, на момент инициализации инстанса (Bitrix AJAX: новый select
  после вставки оценивается заново). Ре-инициализация при смене режима без
  перезагрузки (отстёгнутая клавиатура/мышь у планшета) не отслеживается —
  смена primary-указателя на лету не является сценарием системы; страница
  перезагружается (док-заметка в README компонента).
- API-переключателя («форсировать кастом на таче») нет — по потребности,
  отдельным решением.

## Consequences

**Плюсы:** мобильные пользователи получают системный пикер ОС (знакомый UX,
крупные цели, нативная прокрутка); ноль кастомной геометрии на мобиле —
исчезает класс проблем позиционирования/скролла; согласуется с принципом
«никаких opacity-подмен до T7.3» из T5.2: подмена появляется только там, где
она реально лучше нативного опыта.

**Минусы/цена:** визуал контрола на touch отличается от desktop (нативные
стили против брендированного триггера) — осознанно, значение одобренного
дизайна касается pointer-сценария; e2e-пин — эмуляция `hasTouch` в chromium
(та же техника, что hover-гвард ui-card, AC T4.4); два поведения компонента
документированы в README (строка «Мобильная стратегия»).

**Проверка:** tests/unit/select.test.js (пин «pointer:coarse — модуль НЕ
активируется», jsdom-заглушка matchMedia) и tests/e2e/ui-select.spec.js
(контекст `hasTouch`, AC «на pointer:coarse — нативный»).
