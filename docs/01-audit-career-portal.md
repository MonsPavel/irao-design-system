# Аудит career-portal (референс)

Репозиторий: `D:/repositories/career-portal` — статическая многостраничная вёрстка карьерного портала «Интер РАО» (мок-данные, без бэкенда), готовая к переносу в Битрикс. Аудит проведён по фактическому содержимому репозитория; всё, что не проверено, явно отмечено.

---

## 1. Технический стек

| Область | Факт |
|---|---|
| HTML | Статические страницы, собираемые из фрагментов; semantic HTML5 (`header`, `nav`, `main`, `footer`, `article`, `time`) |
| CSS | Собственный нативный CSS, без препроцессоров, без фреймворков; БЭМ-нейминг |
| JS | Vanilla JS, IIFE-модули, без единой внешней зависимости, без jQuery |
| Сборка | `build.py` на Python 3 (стандартная библиотека); **Node/npm в проекте отсутствуют полностью** — нет `package.json`, нет ластинг-конфигов |
| Пакетный менеджер | Не требуется (нет зависимостей) |
| Шрифты | Golos Text 400/500/600, локальные woff2, разбивка cyr/lat через `unicode-range`, `font-display: swap`, preload весов 400/500 |
| Тестирование | 4 Python unittest-файла, парсящих собранный HTML |
| CI/CD | GitHub Actions → GitHub Pages (только деплой, без PR-гейтов) |
| Документация | README.md (структура, карта блоков, заметки по интеграции в Битрикс) + `design-qa.md` (лог дизайн-QA с пиксельными сверками по Figma) |

Ключевой вывод: проект доказывает жизнеспособность подхода «чистый HTML + CSS + vanilla JS без сборки» — в продакшене Bitrix это ровно тот режим, который нужен.

## 2. Структура репозитория

```
career-portal/
├── build.py                  # сборка демо-страниц из фрагментов (Python)
├── serve.py                  # локальный сервер
├── css/
│   ├── variables.css         # дизайн-токены (72 строки)
│   ├── base.css              # @font-face, reset, .container (113 строк)
│   ├── components.css        # UI-примитивы: btn, tag, card, field, pagination, faq, dd (420 строк)
│   ├── pages.css             # стили внутренних страниц (748 строк)
│   └── vi.css                # версия для слабовидящих по ГОСТ Р 52872 (211 строк)
├── js/
│   ├── dropdowns.js          # кастомный select поверх нативного (PE)
│   ├── forms.js              # мок-валидация форм
│   ├── faq.js                # аккордеон
│   ├── tracks.js             # табы карьерных треков
│   └── vi.js                 # логика VI-режима (localStorage)
├── src/
│   ├── blocks/<block>/       # компоненты: <block>.html + .css + .js в одной папке
│   └── pages/*.html          # фрагменты тел внутренних страниц
├── data/*.json               # мок-данные списков
├── assets/{fonts,icons,images,logos}/
├── tests/                    # Python unittest по собранному HTML
└── .github/workflows/deploy.yml
```

Сборка (`build.py`): склейка блоков в страницы, инъекция мок-данных через HTML-комментарии-плейсхолдеры, cache-busting через `?v={timestamp}`, автогенерация preload'ов шрифтов. Порядок каскада задан списком `CSS_ORDER` (variables → base → components → блоки → pages → vi).

## 3. CSS-архитектура и методология

- **Методология: БЭМ** (`vac-card__title`, `tag--blue`, `production--v2`), один блок — одна папка с файлами html/css/js. Последовательно выдержана.
- **Специфичность**: почти вся — один класс. `!important` вне `vi.css` встречается 1–2 раза на файл. Дисциплина хорошая.
- **Токены** (`variables.css`): ~35 цветов, типографическая шкала тройками `--fs-* / --lh-* / --fw-*` (h1…micro), 4 радиуса, контейнер, `--transition`. 
  - **Чего нет:** шкалы отступов (spacing), брейкпоинтов, z-index, теней, focus-токенов, состояний (hover/active цвета частично захардкожены hex'ами прямо в `components.css`: `#D6D6D6`, `#B9C6DE`).
- **Адаптив:** **desktop-first** (`max-width`), набор брейкпоинтов плавающий: 1439 / 1365 / 1279 / 1023 / 767 / 479 / 359 — не токенизирован. Адаптив сделан «по усмотрению» от десктоп-макета 1440 (так заявлено в README).
- **Хорошие базовые решения в `base.css`**: `[hidden] { display: none !important }`, `scrollbar-gutter: stable`, `img { max-width: 100% }`, глобальный kill-switch анимаций по `prefers-reduced-motion`, ресет отступов.
- **Техника аккордеона** (`.faq__a`): анимация через `grid-template-rows: 0fr → 1fr` — современная, без JS-измерений высоты; дублирующий `prefers-reduced-motion`.

## 4. Существующие переиспользуемые компоненты

Из `components.css` (фактически готовый задел UI-кита):

| Компонент | Варианты/состояния | Оценка зрелости |
|---|---|---|
| `btn` | primary / accent / outline / light + hover | хорошо, но нет focus-visible, disabled, size-шкалы |
| `tag` | blue / orange / green / gray / navy | готов |
| `card` | base / `--hover` / `--filled` | готов как основа |
| `field` | input / select / textarea + `--error` + текст ошибки | хорошо; focus меняет border, но нет focus-visible-политики |
| `checkbox`, `radio` | нативные инпуты + `accent-color` | готов, нативно-доступный подход |
| `pagination` | страницы + стрелки + disabled | готов как основа |
| `breadcrumbs` | со скроллом на мобиле | готов |
| `faq` (аккордеон) | open/close без JS-анимаций | готов |
| `dd` (кастомный select) | listbox-семантика, стрелки клавиатуры | зрелый, но см. замечание ниже |
| `section`, `container`, `cards-grid` (2/3/4), `form-grid`, `page-head`, `field__file`, `form-aside` | layout-примитивы | переносятся с адаптацией |

Блоки-секции (`hero`, `production`, `directions`, `media`…) — это контентные компоненты конкретного сайта, не UI-система; из них переносимы **паттерны**, а не код (карусель-табы, модалка, полноэкранный поиск).

## 5. JavaScript

- Все модули — IIFE, ES5-совместимый синтаксис, инициализация по `DOMContentLoaded`, API через `data-*`-атрибуты, «молчаливые» guard'ы (`if (!root) return`).
- **`dropdowns.js` — образцовый progressive enhancement**: нативный `<select>` остаётся в DOM и работает; кастомный listbox строится поверх, выбор синхронизируется, диспатчится `change`. Стрелки вверх/вниз, Escape, `aria-expanded/haspopup`, `role=listbox/option`.
  - ⚠️ Недостаток: внутри общего модуля захардкожена привязка к классу конкретного проекта `vacancy-search__select-wrap` — для системы нужно вынести в модификатор/опцию.
- `header.js`: дропдаун с закрытием по внешнему клику, Escape **с возвратом фокуса** на триггер, простановка `aria-current` по URL.
- `directions.js` (модалка): сохранение/восстановление фокуса, `aria-hidden`, Escape, стрелки листания, закрытие по `transitionend`.
  - ⚠️ Нет `role="dialog"`/`aria-modal` и focus trap — Tab уводит фокус за пределы модалки.
- `search-screen.js`: фокус в поле при открытии, Escape. Та же проблема — нет семантики диалога и ловушки фокуса.
- `vi.js`: состояние в `localStorage`, применение классов на `body`, синхронизация `aria-pressed` всех кнопок-переключателей, `padding-top` под реальную высоту панели.
- `forms.js` (мок): валидация required/email, класс `field--error`, фокус на первую ошибку, скрытие условных веток из валидации, success-состояние.

## 6. Accessibility

**Что уже сделано (и подтверждено работой):**
- Семантические лендмарки, `aria-label` на навигациях, `aria-current="page"`, `aria-expanded/controls/haspopup` на дропдаунах, `aria-pressed` на тумблерах VI, `aria-selected` на табах;
- декоративные inline-SVG с `aria-hidden`, осмысленные alt на логотипе, `alt=""` на декоративных фото, `width/height` на логотипе, `loading="lazy"` на карточных изображениях;
- `prefers-reduced-motion` глобально и локально;
- **версия для слабовидящих по ГОСТ Р 52872** — полноценная: панель настроек (размер шрифта sm/md/lg через `zoom`, 5 цветовых тем ч/б·б/ч·с/б·бежевая·зелёная, картинки вкл/ч-б/выкл, межбуквенный интервал), сохранение в localStorage, отключение анимаций, агрессивная перекраска `!important` кроме панели и графики. Это редкий по полноте рабочий ассет.

**Пробелы (важно для новой системы):**
- нет skip-link («перейти к содержимому»);
- нет глобальной политики `:focus-visible` — стили фокуса встречаются точечно в 2 местах;
- модалки/поиск без `role="dialog"`, `aria-modal`, focus trap;
- `field__file` прячет нативный input через `display: none` — стилизованный контрол не заменяет клавиатурный доступ полностью;
- schema.org микроразметка не используется;
- контраст палитры не проверялся инструментально (в дизайне часть серых `#808080` на белом даёт ~3.5:1 — ниже AA для обычного текста).

## 7. Тестирование, linting, CI

- **Тесты**: Python unittest парсит собранный HTML (`html.parser`) — проверяют preload шрифтов, иерархию заголовков, полноту и `aria-current` субнавигации, трёхуровневые крошки. Идея («тесты по фактическому HTML») — правильная, переносима.
- **Design QA** (`design-qa.md`): задокументированные сверки с Figma вплоть до пикселей, регресс модалки, проверка горизонтального оверфлоу на 390/320px, консоль без ошибок. Процесс ручной/полуавтоматический (`.shots/`).
- **Linting/formatting: отсутствуют** (нет eslint/stylelint/prettier — Node в проекте нет).
- **CI**: только деплой на GitHub Pages. PR-гейтов (линт, тесты, a11y) нет.

## 8. Известные ограничения, признанные в самом проекте

- Адаптив сделан от десктопа, макет только 1440 (README: «адаптив … на усмотрение»);
- мок-данные и «вариант 2» главной собираются строковыми заменами в `build.py` — только для демо;
- README прямо описывает план интеграции в Битрикс (шрифты/токены в `template_styles.css`, header/footer в `header.php/footer.php`, блоки — во включаемые области, JSON в разметке → `json_encode` из инфоблоков, GET-формы). То есть **проект с самого начала проектировался как источник для Bitrix-вёрстки** — это подтверждает пригодность референса.

# Классификация решений: A / B / C / D

## A — Reuse directly (переносим практически без изменений)

1. **Подход «нативный CSS + vanilla JS без runtime-зависимостей»** — стратегический фундамент, доказан в продакшн-режиме.
2. **БЭМ-нейминг и структура «блок = папка с html/css/js»**.
3. **VI-модуль целиком**: `vi.css` + `vi.js` + `vi-panel.html` (панель, темы, zoom-масштаб, localStorage) — с заменой префикса токенов.
4. **Паттерн `@font-face` Golos Text**: cyr/lat subset'ы, `unicode-range`, `font-display: swap`, preload.
5. **Базовые правила `base.css`**: `[hidden] !important`, `scrollbar-gutter: stable`, ресет, глобальный `prefers-reduced-motion`.
6. **Техника аккордеона** `grid-template-rows: 0fr/1fr`.
7. **Архитектура кастомного select** (нативный select остаётся рабочим, listbox поверх, синхронизация + `change`).
8. **Паттерн JS-модулей**: IIFE, `data-*` API, guard'ы, ES5-совместимость.
9. **Нативные checkbox/radio с `accent-color`** вместо кастомных — доступность бесплатно.
10. **Идея HTML-тестов по собранному выводу** и дисциплина design-qa с доказательствами.

## B — Adapt (хорошая основа, нужна доработка до системы)

1. **`variables.css`** → префикс `--ui-*`, два слоя (примитивы/семантика), добавить spacing/z-index/shadow/focus/breakpoints/state-токены, убрать захардкоженные hex'ы из компонентов в токены.
2. **UI-примитивы `components.css`** (`btn/tag/card/field/pagination/breadcrumbs`) → namespace `ui-`, системные focus-visible, size-шкалы, disabled/loading-состояния, цвета строго из токенов.
3. **`dd` (select)** → убрать привязку к `vacancy-search__select-wrap` (модификатор вместо знания о чужом классе), добавить `aria-activedescendant`/home/end по желанию.
4. **Модалка из `directions.js`** → общий `ui-modal` на базе этой логики + семантика `<dialog>`/`role="dialog"`, focus trap.
5. **Поисковый оверлей** → общий паттерн `ui-search-overlay` с семантикой диалога.
6. **`forms.js`** → системный модуль валидации (клиентская валидация — усиление, серверная — источник истины), связка с токенами ошибок.
7. **Layout-примитивы** (`container`, `section`, `cards-grid`, `form-grid`) → пересборка в mobile-first.
8. **`field__file`** → доступный стилизованный файловый инпут (без `display:none` на нативном).
9. **Тесты** → перенос подхода на тулchain нового репо (Playwright/html-validate).
10. **README-заметки по интеграции в Битрикс** → формализованный integration guide + PHP-сниппеты.

## C — Do not reuse (специфично для career-portal)

1. **`build.py` как целое**: склейка демо-страниц, строковые замены «варианта 2», рендереры карточек из мок-JSON — сайт-специфично.
2. **Desktop-first `max-width` стратегия** — новая система требует mobile-first.
3. **`pages.css` и CSS контентных блоков** (`hero`, `production`, `why-us`…) — визуал конкретного сайта; переносимы паттерны, не стили.
4. **Деплой на GitHub Pages как «релиз»** — новой системе нужен релизный процесс артефактов (dist) с версионированием.
5. **Набор из 7 разных брейкпоинтов** — заменяется токенизированной шкалой.

## D — Improve first (фундамент есть, но доработать до/при переносе)

1. **Политика фокуса**: глобальный `:focus-visible` с токеном `--ui-focus-*` — в career-portal его нет, для системы это P0.
2. **Skip-link** — отсутствует, нужен как компонент системы.
3. **Семантика диалогов + focus trap** — паттерны есть, доступность неполная.
4. **Контраст-палитра** — прогнать цвета через инструментальную проверку WCAG AA до закрепления в токенах.
5. **Типографика при масштабировании**: px-размеры пересчитаются только по брейкпоинтам; для требования «корректная работа при увеличении шрифта» перевести шкалу на rem (базовый размер на `html`).
6. **Retina**: есть только PNG @2x логотипы; нужна системная политика (srcset/2x, векторные иконки, `image-set` для фонов).
