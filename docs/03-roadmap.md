# Roadmap irao-ui

Фазы соответствуют бэклогу ([04-backlog.md](04-backlog.md)); оценки — в идеальных неделях для 1 senior frontend-разработчика (без дизайна и приёмки, они идут параллельно). Фазы 1–4 формируют MVP.

```text
Phase 0  Discovery ............ 1 нед.   │ Phase 6  Layout & Patterns ...... 2 нед.
Phase 1  Foundation ........... 1 нед.   │ Phase 7  Accessibility hardening  2 нед.
Phase 2  Design Tokens ........ 2 нед.   │ Phase 8  Documentation .......... 2 нед.
Phase 3  Base & Core (P0) ..... 3 нед.   │ Phase 9  Bitrix Integration ..... 3 нед.
Phase 4  Forms (P0) ........... 2 нед.   │ Phase 10 Release 1.0 ............ 2 нед.
Phase 5  Complex (P1) ......... 3 нед.   │
```

Ключевой веха-демо: после Phase 4 система уже подключается к пилотному сайту (внутренний стенд) — раннее доказательство жизнеспособности вместо «большого взрыва» в конце.

---

## Phase 0 — Discovery

- **Цель:** зафиксировать границы системы и решения по открытым вопросам до написания кода.
- **Результат:** утверждённые docs/01–05; список сайтов-потребителей v1; решение о branding-scope тем; визуальный бренд-аудит (какие палитры должны поддерживаться темами).
- **Зависимости:** нет.
- **Статус:** ключевые решения приняты 2026-10-05 (см. [05-mvp-risks.md](05-mvp-risks.md)): один бренд, копия ассетов, GitHub, evergreen ×2. Остался выбор пилотов — за менеджером, желательно к концу Phase 4.
- **Задачи:** ревью аудита с командой; опрос владельцев сайтов (какие компоненты нужны в первую очередь); согласование матрицы браузеров; решение о месте репозитория (GitHub/GitLab) и правах.
- **Acceptance:** менеджер утверждает архитектуру и MoSCoW; выбраны 2 пилотных сайта.

## Phase 1 — Foundation

- **Цель:** репозиторий и конвейер, в котором любой следующий шаг дешёвый.
- **Результат:** скелет репо (структура из architecture §7), tooling (stylelint/eslint/prettier/html-validate), CI c mandatory-гейтами, showcase-каркас с первой страницей-заглушкой, сборка dist (esbuild), Playwright-прогон в CI.
- **Зависимости:** Phase 0.
- **Acceptance:** PR с пустым компонентом проходит полный конвейер; showcase деплоится на Pages; `npm run build` производит dist-структуру.

## Phase 2 — Design Tokens

- **Цель:** единый источник визуальной правды, пригодный для тем.
- **Результат:** `tokens/primitives.css` + `tokens/semantic.css` (полный состав из architecture §3.2); страница-стенд токенов (все значения видны); механизм тем с одной синтетической тестовой темой (мульти-бренда в MVP нет — решение Phase 0); проверка контраста AA дефолтной палитры инструментально; задокументированная шкала брейкпоинтов.
- **Зависимости:** Phase 1.
- **Acceptance:** ни одного hex вне tokens (stylelint-гейт зелёный); все семантические пары текст/фон ≥ 4.5:1 (или осознанное исключение в протоколе); смена темы на стенде меняет вид без правок компонентов.

## Phase 3 — Base & Core Components (P0)

- **Цель:** компоненты, из которых можно собрать типовую страницу.
- **Результат:** base (reset/fonts/focus/typography/container/grid/skip-link); компоненты: link, button, tag/badge, card, breadcrumbs (+schema.org), image, alert, empty/error-state-паттерны; портированный VI-модуль; каждый с доком-страницей и тестами.
- **Зависимости:** Phase 2.
- **Acceptance:** e2e+axe зелёные на всех стендах; visual-эталоны зафиксированы; VI-режим включается на стенде и перекрашивает все компоненты; всё в rem — 200% zoom тест проходит.

## Phase 4 — Forms (P0)

- **Цель:** формы — самый рискованный контур Битрикса — закрыты полностью.
- **Результат:** input/textarea/select/checkbox/radio/file, form-grid, состояния error/hint/required, JS-валидация как progressive enhancement (сервер — источник истины), паттерн серверной ошибки из Bitrix-формы; интеграционная страница «форма целиком».
- **Зависимости:** Phase 3.
- **Acceptance:** форма отправляется и валидируется без JS; ошибка связана aria-describedby; фокус на первую ошибку; кейс «Bitrix вывел ошибку после submit» выглядит идентично клиентской; **MVP-даун: подключение к стенду пилотного сайта**.

## Phase 5 — Complex Components (P1)

- **Результат:** accordion (`<details>`-база), dropdown, tabs, modal (native `<dialog>` + fallback по итогам SPIKE), custom select (порт dd из career-portal), pagination, table-паттерны, loader, search-overlay-паттерн, header/footer/page-паттерны как документация.
- **Зависимости:** Phase 3; SPIKE dialog — до старта modal.
- **Acceptance:** каждый интерактивный компонент проходит клавиатурный чек-лист APG; focus trap/restor протестирован e2e; без JS каждый либо работает, либо деградирует до доступной нативной альтернативы.

## Phase 6 — Layout & Patterns

- **Результат:** сеты типовых страниц-паттернов (list page, detail page, form page, landing section) на showcase — «собери страницу из кубиков» с копируемой разметкой; адаптивные правила сеток; правила вёрстки контентных секций (граница системы/сайта).
- **Зависимости:** Phases 3–5.
- **Acceptance:** типовая страница списка собирается копипастой из паттернов без написания нового CSS.

## Phase 7 — Accessibility hardening

- **Результат:** прогон полного чек-листа по всем стендам (клавиатура, скринридер NVDA/VoiceOver вручную по протоколу), forced-colors, контраст-ревизия тем, VI-режим на всех страницах, исправления; отчёт a11y-аудита с evidence.
- **Зависимости:** Phases 3–6.
- **Acceptance:** axe без нарушений на всех состояниях; ручной протокол скринридера подписан; ГОСТ-панель работает на всём showcase.

## Phase 8 — Documentation

- **Результат:** showcase полностью укомплектован (все компоненты по шаблону доки из architecture §8), integration-guide, quickstart, «UI System для Bitrix-разработчика за 30 минут».
- **Зависимости:** Phases 3–6 (доки пишутся с каждым компонентом; здесь — доведение и связность).
- **Acceptance:** разработчик вне команды подключает систему к чистому стенду только по докам (инкогнито-тест).

## Phase 9 — Bitrix Integration

- **Результат:** интеграция на 2 пилотных сайтах: подключение core+theme+vi, перенос 2–3 реальных страниц на ui-компоненты (forms обязательны), сниппеты и integration-guide выверены реальностью; процесс обновления сайта отработан на minor-релизе.
- **Зависимости:** Phase 8 (дока) и готовность сайтов.
- **Acceptance:** страницы пилотов в проде/предпроде; чек-лист обновления пройден вручную; конфликты с legacy-CSS зафиксированы и закрыты (или задокументированы как известные ограничения).

## Phase 10 — Testing / Release 1.0

- **Результат:** полный матричный прогон браузеров, релизный процесс (тег → артефакт → changelog), политика N−1 задокументирована, v1.0.0 опубликована.
- **Зависимости:** все фазы.
- **Acceptance:** релиз-артефакты скачиваемы и подключаемы по quickstart; Nightly-матрица зелёная 7 дней подряд; подписан changelog.
