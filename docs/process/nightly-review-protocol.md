# Протокол ночного цикла irao-ui (night-cycle)

Ночной автономный конвейер реализации задач. Воспроизводит паттерн `health-log/.zcode/workflows/night-cycle.dwf.ts`; **фаза ревью усилена** по поручению владельца (05.10.2025): независимый ревьюер по модели агента ecc (everything-claude-code) `code-reviewer`, замечания **critical и high правятся всегда**, до 3 раундов правок.

## Где живёт

- **Воркфлоу:** [.zcode/workflows/night-cycle.dwf.ts](../../.zcode/workflows/night-cycle.dwf.ts) — запуск вечером: «Запусти workflow night-cycle до 04:00»; днём — только с `force=true`.
- **Леджер статусов:** [docs/ui-system/STATUS.md](../ui-system/STATUS.md) (`todo / in-progress / done / blocked`) — ведёт конвейер.
- **CI-контур (детерминированная часть, независимо):** [.github/workflows/nightly.yml](../../.github/workflows/nightly.yml) + [tools/validate-backlog.sh](../../tools/validate-backlog.sh).

## Цикл на каждую задачу

```text
выбор из STATUS.md (todo + все deps done)
  → ветка task/<ID> от main
  → реализация по TDD (агент-реализатор; Scope/Out of scope из файла задачи)
  → УСИЛЕННОЕ РЕВЬЮ (агент-ревьюер, severity-модель ecc)
       critical/high → блокируют мердж; правки ВСЕГДА; до 3 раундов
       medium/low    → не блокируют; собираются в бэклог ночи
  → независимая приёмка (агент-приёмщик: Acceptance Criteria / DoD с доказательствами)
  → gate: bash tools/validate-backlog.sh + npm run lint / test:unit (когда настроены)
  → мердж --no-ff в main + push + строка в STATUS.md (агент-интегратор)
```

Сбой/блокировка одной задачи не останавливает ночь. Технический сбой — аварийный агент: wip-коммит на ветке, строка blocked, ветка пушится для сохранения наработок.

## Окно времени (как в health-log)

- Ночное окно **18:00–04:00** (`cutoffHour=4`, решение 05.10 — ужато с 05:30): последняя задача не берётся позже 04:00, начатая доделывается.
- Утренний предел **08:00–12:00**: новые задачи не начинаются.
- `force=true` — без лимитов времени.
- Лимит 40 задач на прогон; для запуска нужно чистое рабочее дерево (незакоммиченные `.zcode/` игнорируются).

## Рубрика ревью (ecc code-reviewer, усиленная)

Каждая находка обязана иметь: severity · файл:строка · доказательство-цитата · конкретный фикс. Расплывчатые пункты и вкусовщина — не находки; false positives недопустимы (проверь перед репортом).

1. **CRITICAL** — секреты; инъекции; небезопасные `eval`/`innerHTML` с данными; скрытый breaking-change API компонентов (классы/токены/HTML-паттерны) без major (ADR-0007); поломка обязательных гейтов.
2. **HIGH** — логические баги, null/race, сломанные контракты модулей, необработанные внешние вызовы; проектные инварианты: ADR-0001 (фокус), ADR-0002 (box-sizing), hex вне `tokens/primitives.css`, `!important` вне `a11y/vi.css`, потеря no-JS деградации, регрессия Accessibility Requirements задачи, рассинхрон доки и кода.
3. **MEDIUM** — недостающие тесты новой логики; перф-ловушки; мелкие a11y-пробелы вне AC.
4. **LOW** — нейминг, nits, опциональные рефакторинги.

**Политика фиксов (ключевое усиление):** `verdict=fix` ⇔ есть critical или high. CRITICAL/HIGH исправляются **всегда** — реализатор правит все, ревьюер перепроверяет, лимит 3 раунда (в health-log было 2 и без severity); не закрылись за 3 раунда → задача blocked с причиной. MEDIUM/LOW не правятся ночью: попадают в `docs/process/nightly/BACKLOG.md` (агент-писарь, один коммит `chore(nightly): backlog +N`).

## Ограничения реализатора (вшиты в системный промпт)

- Не выходит за `## Scope`, не трогает STATUS.md и файлы задач, не мерджит/не пушит (мердж — только интегратор).
- Инварианты проекта обязательны (см. рубрику HIGH); значения одобренного дизайна career-portal не меняются (design-decision — только владелец дизайна); career-portal — read-only референс.
- Инфраструктуру (npm/линтеры) не создаёт вне Scope задачи; до T1.1–T1.6 проверки — validate-backlog + сценарии задачи.
- Честный `blocked` вместо имитации успеха.

## Отчётность

- Итог ночи: markdown-артефакт «Итоги ночного цикла» (таблица задач × раунды × примечания, последние коммиты main, как проверялось) + board прогресса.
- BACKLOG medium/low — `docs/process/nightly/BACKLOG.md`.
- CI-ночь (`nightly.yml`) работает параллельно и независимо: красный прогон = investigate, PR не блокирует (сегрегация контуров — паттерн health-log).
