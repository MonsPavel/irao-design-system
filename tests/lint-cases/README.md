# tests/lint-cases/ — негативные и позитивные фикстуры линтеров (T1.2)

Это **тест конфигов**: каждый файл — заведомое нарушение одного правила
(или эталонно чистый позитивный контроль). Прогон линтеров по ним должен быть
красным ровно там, где ожидается, — это и проверяет
`npm run test:lint` (`tools/run-lint-cases.mjs`).

Важные свойства каталога:

- **Не источник правды и не примеры для копирования.** Всё содержимое —
  намеренно некорректный код; по этим файлам нельзя учиться писать компоненты
  (см. `docs/templates/` и `CONTRIBUTING.md`).
- **Из основного `npm run lint` исключены**: stylelint — negated-glob в скрипте
  `lint:css`; eslint — negated `files` в `eslint.config.mjs`; prettier —
  `.prettierignore`; html-validate — globs в `tools/lint-html.mjs`. Фикстуры
  линтяются только раннером, который сам решает, где какой линтер ожидаемо
  красный.
- **Пути внутри `css/` повторяют структуру репозитория**
  (`css/components/...`, `css/tokens/primitives.css`, `css/a11y/vi.css`),
  потому что hex-гейт и запрет `!important` — path-based (`overrides` в
  `stylelint.config.mjs`): позитивные контролы проверяют, что исключения
  работают на тех же путях, что и в реальном репозитории.
