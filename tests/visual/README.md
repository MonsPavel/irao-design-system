# tests/visual/

Скриншот-эталоны: `__screenshots__/<spec>/<name>--<viewport>.png`
(375/768/1280/1440 — шкала `VIEWPORTS` харнесса, T3.4 добавил xl). Коммитятся.

Создаются **только** в окружении создания (ADR-0004): `npm run test:docker`
(официальный образ `mcr.microsoft.com/playwright:vX-jammy`, пин — рядом с
версией Playwright в package.json) или CI-джоба `update-snapshots` (T1.5,
fallback). Локальные host-прогоны эталоны не пишут и не сравниваются:
`shot()` вне контейнера — no-op (гейт `IRAO_SNAPSHOTS=1`). Порог сравнения
нулевой — контейнер-паритет даёт бинарное совпадение, любой дифф значим.

## Сверка с CI-эталоном (AC T1.4, «Проверка» ADR-0004)

Контракт: эталон, созданный `test:docker` локально, бинарно совпадает с
CI-эталоном того же стенда. Статус по половинам критерия:

- **Локальная (воспроизводимость) — подтверждено.** sha256 трёх эталонов
  индекса showcase идентичны в независимых контейнерных прогонах, включая
  перегенерацию `npm run test:docker -- --update-snapshots` (прогоны
  2026-10-05/06; закоммиченные файлы — вывод контейнера байт-в-байт).
- **CI (совпадение с эталоном из CI) — подтверждено 06.10.** Джоба
  `update-snapshots` (dispatch, run 37452427560): sha256 артефакта `snapshots`
  идентичны локальному контейнерному прогону на том же коммите
  (desktop `2f96a5cc…`, mobile `11b3078e…`, tablet `a922a38b…`). Bot-PR не
  создавался by design: диффа нет — эталоны в main уже контейнерные;
  бот-коммит сработает при первом реальном диффе. Протокол сверки: на одном
  коммите —
  1. локально `npm run test:docker -- --update-snapshots`, затем
     `sha256sum tests/visual/__screenshots__/**/*.png`;
  2. джоба `update-snapshots` на том же коммите → sha256 из Job Summary
     (или артефакт `snapshots`);
  3. sha256 CI обязаны совпасть с локальными (гарантия — один пин
     образа `iraoUi.playwrightImage`, самопроверка версии в
     tools/test-docker.mjs). Расхождение = дефект паритета, investigate.
