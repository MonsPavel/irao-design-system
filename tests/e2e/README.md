# tests/e2e/

Playwright-сценарии поведения компонентов по стендам `showcase/dist/stands/`
(источники стендов — `showcase/pages/<name>/`, канонические паттерны
`components/<name>/`). Харнесс — `tests/helpers/harness.js`: фикстура
`stand(name)`, хелперы `a11y()`, `shot()`. Шаблон компонентного теста —
[../README.md](../README.md).

Сценарии, чья поверхность ещё не появилась (компоненты EPIC-4/5),
фиксируются здесь текстом (конвенция tests/README.md);
при появлении инфраструктуры каждый сценарий переезжает в код без изменения
сути. Запуск ручных проверок: `npm run build && npm run serve` →
`http://127.0.0.1:8080/showcase/dist/…`.

## Сценарий T2.4 (AC1, суб-часть «вид кнопок/карточек/полей»): тема меняет вид ui-компонентов без их правки

Статус: **ожидает поверхности** — стенды `ui-button`/`ui-card`/`ui-field`
появятся с EPIC-4/5, авто-гейт — с харнессом T1.4. До тех пор механизм
подтверждается на стенде «Токены» (`/showcase/dist/stands/tokens.html`),
все демо-элементы которого читают слой 2 через `var()` (пин:
`tests/unit/themes.test.js` — «промежуточная поверхность доказательства
реальна»); факт-прогон chromium 2026-10-06 — в доке «Как пользоваться
токенами» → «Темы».

Шаги (после появления стендов):

1. Открыть стенд компонента **без темы**:
   `/showcase/dist/stands/ui-button.html` (затем `ui-card.html`, `ui-field.html`).
2. Открыть тот же стенд с `?theme=test` — переключатель каркаса выставляет
   `data-ui-theme="test"` на `<html>` и подключает `dist/themes/theme-test.css`.
3. Assert computed-значения на `<html>`: `--ui-color-primary` `#002856 →
   #511d59`, `--ui-color-accent` `#f26722 → #ffab72`, `--ui-color-surface-muted`
   `#f1f5fe → #ffd3b7`, `--ui-focus-color` `#002856 → #f37131`,
   `--ui-radius-md` `1rem → 0.25rem`, `--ui-shadow-card` — геометрия md → lg.
4. Assert вид элементов компонента на странице: цвет/рамка кнопки (primary- и
   accent-модификаторы), фон и радиус карточки, рамка/фон поля — изменились
   согласно п.3; производные (`--ui-color-surface-dark`, `--ui-focus-color`
   при отсутствии явного override) следуют за цепочками слоя 2.
5. Assert неизменности: не переопределённые темой токены (`--ui-color-info`,
   `--ui-color-text` и т.д.) и слой 1 (палитра на стенде «Токены») — без
   изменений; HTML и классы компонентов на стенде побайтово те же (смена темы
   не правит разметку).
6. Фикстура совместимости: подключить `tests/lint-cases/css/themes/theme-old-compat.css`
   с `data-ui-theme="old-compat"` — переопределённые ею токены принимают её
   значения, «новые» токены core (`--ui-color-info` и др.) работают дефолтами
   `:root` (AC «старая тема + новый токен»).
7. Скриншот тестовой темы — эталон только из контейнера (ADR-0003/0004),
   локальные прогоны эталонов не пишут.

Границы сценария: значения тестовой темы синтетические (декоративные серии
палитры) и контраст-гейт AA не проходят сознательно (исключение в шапке

утверждённый визуал (тот — дефолтная тема career-portal).

### Контракт `data-ui-check-layout`

Ключевые узлы стенда помечаются пустым атрибутом `data-ui-check-layout` в
источнике стенда (`showcase/pages/<имя>/index.html` или канонический паттерн
`components/<имя>/<имя>.html`); сценарий не привязан к классам/структуре —
рефакторинг стенда не ломает гейт. Список стендов гейта — `CHECK_STANDS`
в `tests/e2e/scaling.spec.js`; сейчас это `base`, `typography`, `layout`
(стенд формы добавится с EPIC-5). Синхронизация «размеченные стенды ↔
CHECK_STANDS» в обе стороны — пин `tests/unit/scaling.test.js`: новый стенд
с маркерами без записи в `CHECK_STANDS` (и наоборот) роняет юнит-прогон.

Правила разметки: помечайте узлы, чья взаимная раскладка важна при росте
шрифта (секции, ячейки сеток, текстовые роли, демо-блоки); вложенные друг в
друга маркеры допустимы (предок/потомок из перекрытий исключается).

### Что считать поломкой (пороги чекера)

| Вид | Условие падения | Обоснование порога |
|---|---|---|
| `hscroll` | `scrollWidth > clientWidth` у `html` или `body` (хоть на 1px) | горизонтальный скролл страницы при 200%/32px недопустим (проверка design-qa career-portal) |
| `overlap` | пересечение **видимых** ректов двух ключевых узлов-«не предок/не потомок» **глубже 2px по обеим осям** | 2px гасят субпиксельное округление браузера; ректы обрезаются по clip-предкам (`visualBox`) — контент скролл-контейнера рисуется обрезанным и не «наезжает» на внешние узлы (rev T3.6) |
| `clip` | computed `overflow` узла `hidden`/`clip` и `scrollWidth`/`scrollHeight` > `clientWidth`/`clientHeight` | контент недостижим; `auto`/`scroll` — достижимость прокруткой, поломкой не считается |
| `contract` | на стенде нет ни одного `[data-ui-check-layout]` | пустой гейт = отсутствие поверхности, а не зелёный результат |

Скрытые узлы (нулевой `boundingBox`, `display: none`) в проверках не участвуют.
`auto`/`scroll` никогда не считаются обрезкой (достижимость прокруткой), и их
скролл-контент исключён из overlap — класс «скролл ≠ поломка» закреплён
e2e-тестом чувствительности (широкий инжект `height: 40px + overflow: auto`
на все маркерные узлы обязан оставаться зелёным) и юнит-пином.

### Механика сценариев (зафиксирована по Technical considerations T3.6)

- **A, zoom 200%** — CDP-эмуляция `Emulation.setDeviceMetricsOverride`:
  CSS-вьюпорт = база/2 (640 и 384 при базах 1280/768), `deviceScaleFactor` ×2 —
  точная модель системного зума: rem-типографика остаётся в CSS-px,
  медиазапросы пересчитываются. Только chromium (`test.skip` на остальных —
  CDP вне chromium недоступен). Раскладка-эквивалент для не-chromium браузеров,
  если когда-нибудь понадобится: `page.setViewportSize({ width: база/2 })`.
  Применение эмуляции ожидается `waitForFunction` (не одиночным чтением
  `innerWidth` — гонка при параллельной нагрузке).
- **B, 32px-база** — `page.addStyleTag({ content: 'html { font-size: 32px
  !important; }' })`: инжект переживает любые будущие правила `html` в
  каскаде; базы 1280/768/375.
- **Чувствительность** — постоянные тесты инжектят на стенд `layout`
  поломки и проверяют чекер в обе стороны: фикс. высота + `overflow: hidden`
  (обрезка) и сдвиг соседа (наложение) обязаны ловиться; `overflow: auto` с
  прокручиваемым контентом (достижим) обязан НЕ флагаться (rev T3.6 high —
  предикат «overflow ≠ visible» флагал скроллируемое). Красное доказательство
  TDD-шага — коммиты e11d2aa (красный на специально сломанном стенде с фикс.
  высотой) и bfeefe8 (зелёный после удаления стенда).

Прогон локально: `npx playwright test scaling.spec.js` (chromium;
32px-половина — и на firefox/webkit через `--project=`).
