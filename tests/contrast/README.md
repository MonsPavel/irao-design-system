# Контраст-гейт AA (T2.3)

Инструментальное доказательство WCAG 2.1 AA для всех смысловых цветовых пар
дефолтной палитры (критерий 1.4.3, некстовые — 1.4.11). Нарушение — красный
CI-шаг до того, как цвет попадёт в компоненты: компоненты читают только слой 2
(ADR-0009), поэтому пар «смысл → фон» достаточно.

## Запуск

```bash
npm run test:contrast            # то же, что node tests/contrast/check.mjs
node tests/contrast/check.mjs --report dist/contrast-report.md
```

Код выхода: `0` — все пары ≥ порогов, покрытие полное; `1` — AA-нарушения,
пробелы покрытия или ошибки конфига. Markdown-отчёт пишется всегда (и при
красном прогоне) — `dist/contrast-report.md`, грузится артефактом CI.

## Как устроено

- `check.mjs` — CLI: читает `tokens/primitives.css` + `tokens/semantic.css`
  (парсер стенда — единый контракт формата), конфиг пар, пишет отчёт, задаёт
  exit-код. Аргументы: `--tokens <dir>`, `--config <file>`, `--report <file>`
  (относительные пути — от корня репозитория, абсолютные — как есть).
- `lib.mjs` — чистые функции: WCAG-математика (relative luminance,
  коэффициент), resolve `var()`-цепочек слоя 2 до hex примитивов (циклы и
  неизвестные имена — ошибка), `evaluateContrast` (пары, пороги, покрытие).
- `pairs.config.mjs` — конфиг: пары «использование → фон» с уровнями порогов
  и осознанные исключения с комментариями-обоснованиями.
- `tests/unit/contrast.test.js` — юнит-тесты: математика WCAG, негативный
  кейс «тонкий серый» (#808080 на белом — красный), зелёность дефолтной
  палитры, полнота покрытия, CLI exit-коды (AC 1/2 задачи T2.3).

Пороги AA (`THRESHOLDS` в `lib.mjs`): обычный текст ≥ 4.5:1 (`text`),
крупный (≥ 24px / ≥ 19px bold) ≥ 3:1 (`large`), некстовые ≥ 3:1 (`non-text`).

## Правила ведения конфига (Implementation requirements T2.3)

1. **Новый цветовой токен слоя 2 обязан попасть в проверку**: имя токена
   содержит `color` → он должен быть в паре или в `EXCEPTIONS`, иначе прогон
   красный (`coverageGaps`). Это и есть автоматическое включение нового
   семантического цвета.
2. **Исключение — только записью в `EXCEPTIONS` с обоснованием** (альфа-
   поверхности без подложки, декоративные рамки/разделители — WCAG 1.4.11
   их не требует). Исключение для неизвестного или нецветового токена —
   ошибка конфига.
3. **Пара не проходит порог → правится значение СЛОЯ 2** (примитивы — эталон
   одобренного дизайна career-portal и не меняются): слой 2 указывает на
   более тёмную ступень, изменение фиксируется строкой в таблице диффов
   ([AA-замены](../../docs/ui-system/architecture/tokens-career-portal-mapping.md))
   со статусом `design-decision` — согласование с владельцем дизайна.
   Было сделано в T2.3: muted `#808080` → `gray-700`, tag-orange `#B34A10` →
   `orange-800`, error `#D8402C` → `red-700`.

## CI

Шаг «Contrast check (AA)» в `.github/workflows/nightly.yml` (запуск
`npm run test:contrast`, отчёт — артефакт `contrast-report`). Когда по
[T1.5](../../docs/ui-system/epics/EPIC-01-foundation/T1.5-ci-pipeline.md)
появится `ci.yml` (PR-конвейер), шаг переезжает туда как mandatory PR-гейт
(06 §7: «contrast-скрипт токенов — mandatory»).

## Осознанные границы гейта

- производные hover/active (например, breadcrumbs a:hover — accent как текст
  3.12:1 на белом) — зона [T2.6](../../docs/ui-system/epics/EPIC-02-design-tokens/T2.6-derived-color-states.md)
  (color-mix) с ревизией [T9.2](../../docs/ui-system/epics/EPIC-09-accessibility/T9.2-accessibility-hardening.md);
- белые подписи кнопок на accent (3.12:1 < 4.5) — не гейтится здесь:
  ui-button — [T4.2](../../docs/ui-system/epics/EPIC-04-primitives/T4.2-button.md),
  изменение — design-decision владельца;
- фокус цветом primary на тёмных секциях не читается — замена производных
  состояний на тёмном зафиксирована за T9.2;
- контраст VI-тем — гарантированные пары ГОСТ, проверка в
  [T9.1](../../docs/ui-system/epics/EPIC-09-accessibility/T9.1-vi-module.md)
  (Out of scope T2.3);
- фактические компоненты не проверяются (пар достаточно — ADR-0009).
