Интеграционный стенд T5.6 «форма целиком»: полный цикл из четырёх веток — без JS (нативная валидация) → с JS (блокировка сабмита, сводная ошибка, фокус — модуль IraoUI.form, T5.5) → «серверный ответ» (pre-rendered ошибки: PHP рендерит те же классы и aria, что клиентская валидация) → success. Правило цикла: серверная валидация всегда включена — JS только улучшает UX. Каждая ветка — отдельный якорь-состояние (#ffc-nojs / #ffc-client / #ffc-server / #ffc-success) для e2e и visual. Ветка 3 — статическая эмуляция вывода сниппета bitrix/snippets/form-error-render.php; контракт и таблица «состояние → классы → aria → фокус» — components/ui-form/README.md. Сценарии — tests/e2e/form-full-cycle.spec.js. На реальном сайте ветки — разные загрузки страницы (перезагрузка после сабмита); здесь они стоят рядом, чтобы состояния можно было сверить.

Форма полного цикла: ветки 1 и 2

Ветка 1 — без JS: нативная валидация

В разметке формы нет novalidate: без JS браузерная валидация работает как есть (ТЗ №14) — пустое обязательное поле блокирует отправку, заполненная форма уходит на сервер (GET). novalidate ставит только модуль IraoUI.form при инициализации. e2e открывает эту форму в контексте без JavaScript. E-mail предзаполнен битым значением — так сервер возвращает ввод пользователя вместе с ошибками.

    Ветка 2 — с JS: блокировка сабмита, сводная ошибка, фокус

    Та же форма выше: сабмит с ошибками модуль блокирует (preventDefault — данные не уйдут на сервер, ведь серверная валидация всё равно включена), заполняет сводную ошибку ссылками на поля («В форме N ошибк(и/ок)») и переводит фокус на #ffc-summary; ошибки полей — по контракту T5.6. Валидный сабмит модуль пропускает: страницу перезагружает сервер и рендерит следующую ветку.

    Ветка 3 — «серверный ответ»: PHP-рендер после перезагрузки (статика)

    Эмуляция вывода сниппета bitrix/snippets/form-error-render.php: сервер вернул форму с вводом пользователя и ошибками валидации. Разметка ошибки та же, что у клиентской валидации: ui-field--error + aria-invalid="true" + aria-describedby + <p class="ui-field__error"> (суффикс id -error — единый с модулем T5.5), сводная — ui-form__summary[role=alert]. Идентичность computed-состояний полей веток 2 и 3 — ключевой e2e-сценарий T5.6 (tests/e2e/form-full-cycle.spec.js). Фокус на summary после перезагрузки ставит inline-сниппет под формой — точная копия вывода irao_ui_form_focus_script() из сниппета.

    Ветка 4 — success: серверная success-страница

    Валидные данные сервер принял: success-блок рендерится сразу видимым, без JS (вариант Bitrix). Заголовок с tabindex="-1" — цель фокуса: success-вариант inline-сниппета (irao_ui_form_focus_script('…-success-title')) переводит фокус после загрузки. На стенде ветки соседствуют на одной странице (в реальности это отдельные загрузки), поэтому success-скрипт здесь не исполняется — поведение заголовка проверяет e2e программным фокусом, живой свап показывает стенд ui-form (T5.4).
